# 系统设置域(SYS)

> 面向管理后台(仅超级管理员可读写,见 01-overview.md §角色权限矩阵 `SYSTEM_CONFIG_*`)的平台级参数配置:系统参数中心、订单与履约参数、库存预警阈值、账号与安全策略、通知与订阅消息配置、数据维护。与运营配置域(12-operations-config.md)区分:运营配置为日常运营内容与基础经营规则(管理员可维护),系统设置为平台级基础参数与安全策略(仅超级管理员)。本域范围:F-SYS-001~006(预留 007+);规则:R-SYS-01~03(交叉引用见 §4)。

## 1. 域概述

### 1.1 域范围与功能清单

| F-ID | 名称 | 状态 | 端 |
| --- | --- | --- | --- |
| F-SYS-001 | 系统参数管理 | [规划中] | 管理后台 |
| F-SYS-002 | 订单与履约参数配置 | [规划中] | 管理后台 |
| F-SYS-003 | 库存预警阈值配置 | [规划中] | 管理后台 |
| F-SYS-004 | 账号与安全策略配置 | [规划中] | 管理后台 |
| F-SYS-005 | 通知与订阅消息配置 | [规划中] | 管理后台 |
| F-SYS-006 | 数据维护 | [规划中] | 管理后台 |

> **预留**:支付参数(随 G01 支付链路)、推送通道、时区/单位等系统级参数按序扩展为 F-SYS-007+,不散落到各业务域。

### 1.2 域内角色与入口

- **超级管理员**:管理后台「系统设置」菜单(系统参数/订单与履约参数/库存预警阈值/账号与安全/通知与订阅消息/数据维护)。权限码 `SYSTEM_CONFIG_READ/WRITE` 已在 01-overview.md §角色权限矩阵(仅超级管理员),现状无对应接口,随本域实现接线(G64);强制链路见 R-AUTH-04。
- **管理员**:系统设置菜单不可见,接口访问返回 FORBIDDEN(R-SYS-03);日常运营内容走运营配置域(12-operations-config.md)。
- **消费者侧(用户/送水工端)**:不直接进入本域,消费参数配置结果——配送时段(F-ORD-001)、库存预警展示(F-PRO-006/F-STA-006)、订阅消息模板(F-ADR-011)等。

### 1.3 域级验收清单

- 系统参数可配置:非敏感业务参数在线可配、按声明即时生效(热生效优先)、修改全程审计留痕(R-SYS-01);
- 敏感配置受保护:密钥类参数不可经在线配置修改,仅配置文件/环境变量注入(R-SYS-02);
- 参数变更不追溯已生成业务数据(订单成交价/运费/时段按下单时快照)。

## 2. 域内业务规则

### 2.1 系统参数生效与审计规则

**R-SYS-01 系统参数生效与审计规则**: 系统参数为平台级「键 + 值 + 类型 + 分组」配置,变更按参数声明即时生效或重启生效(热生效优先);所有修改留审计日志(操作人/时间/旧值/新值);参数变更不追溯已生成业务数据。
| 适用功能:F-SYS-001~006
| 校验与数值:参数键唯一(字母数字下划线);值按声明类型校验(数值区间/布尔/枚举/长度);金额类参数以分存储与计算(R-MON-01);保留天数/阈值等数值型为整数且限区间
| 并发与边界:并发修改以最后一次保存为准并留痕;删除参数须二次确认且无业务引用(引用检测为开放问题);配置中心故障时业务按默认值/本地配置降级运行
| 现状与目标:现状仅 `system_settings` 表/实体/仓库脚手架(`setting_key` 唯一,唯一种子键 `bucket_deposit_amount` 为押金功能删除后的孤儿数据,见 13-misc.md §G06),无配置服务/接口/后台页面;目标形态为「参数中心 + 业务消费 + 审计闭环」
| 缺口关联:G64

### 2.2 敏感配置保护规则

**R-SYS-02 敏感配置保护规则**: 微信密钥、支付证书、数据库口令等敏感接入参数一律不进入系统配置在线修改通道,仅通过配置文件/环境变量注入(见 docs/DEPLOYMENT.md);系统配置界面仅暴露非敏感业务参数;日志与审计对敏感字段脱敏。
| 适用功能:F-SYS-001、F-SYS-005
| 校验与数值:配置项按白名单分类(非敏感才可在线修改);密钥类字段后端不回显明文,前端展示掩码
| 并发与边界:密钥变更走部署流程(重启生效)而非在线修改;泄露应急为运维流程(开放问题)
| 现状与目标:现状微信/存储等接入参数均经 application.yml/环境变量注入,无在线配置通道;目标维持现状——密钥类不提供在线配置,仅对非敏感业务参数开放
| 缺口关联: —

### 2.3 配置访问权限规则

**R-SYS-03 配置访问权限规则**: 系统设置仅超级管理员可读写(`SYSTEM_CONFIG_READ/WRITE`,见 01-overview.md §角色权限矩阵);运营配置(`OPS_CONFIG_*/FEEDBACK_*`)为管理员级,见 12-operations-config.md §R-OPS-01。
| 适用功能:F-SYS-001~006
| 校验与数值:方法级 `@PreAuthorize("hasAuthority('PERMISSION_SYSTEM_CONFIG_READ/WRITE')")`(R-AUTH-04);前端菜单按权限码渲染
| 并发与边界:越权返回 FORBIDDEN、匿名返回 UNAUTHENTICATED;角色变更后重新登录生效
| 现状与目标:现状权限强制未生效(G49),SYSTEM_CONFIG_* 无对应接口(G64);目标形态为强制生效 + 接口接线
| 缺口关联:G49、G64

## 3. 功能需求详述

### 3.1 管理后台:系统参数与平台策略

#### F-SYS-001 系统参数管理 [规划中]
**需求描述**: 通用系统参数配置中心:按参数组(订单与履约/库存/安全/通知/数据维护)浏览、搜索、修改、恢复默认;参数带类型(数值/布尔/文本/枚举)、说明、当前值与默认值。现状:仅 `system_settings` 表/实体/仓库脚手架(`modules/aqua-foundation/.../common/domain/model/SystemSettingsModel.kt`),无服务/接口/页面,唯一种子键 `bucket_deposit_amount` 为押金功能删除后的孤儿数据(G06);`SYSTEM_CONFIG_*` 权限码已在矩阵但无对应接口(G64);目标形态:参数中心在线可配、按声明热生效、审计留痕。
**页面与入口**: 系统参数配置页(system-config/parameters)| 管理后台 | 入口:系统设置 → 系统参数(仅超级管理员可见)。
**UI与交互**:
- **页面布局**:
  1. 参数分组导航(Tabs):订单与履约/库存/安全/通知/数据维护;
  2. 参数列表:参数名/键/类型(Tag)/当前值(按类型渲染控件)/说明/修改人/修改时间;操作:「编辑」「恢复默认」;
  3. 编辑弹窗:值输入(数值 InputNumber、布尔 Switch、文本 Input、枚举 Select)+ 类型/说明展示;
  4. 「修改记录」页签:审计日志(时间/操作人/旧值/新值)。
- **组件清单**: Tabs、Table、Form、Input、InputNumber、Switch、Select、Modal、Popconfirm、Tag(均目标形态)。
- **关键交互流程**:
  1. 进入页面 → 按组加载参数列表;
  2. 编辑 → 按声明类型校验 → 保存 → 按声明热生效;
  3. 恢复默认 → 二次确认 → 回默认值;
  4. 修改记录页签可查审计日志。
- **状态呈现**:
  - 空态:组内无参数空态;
  - 加载态:列表/保存 loading;
  - 错误态:保存失败 toast;
  - 禁用态:无 `SYSTEM_CONFIG_WRITE` 权限时只读(仅超管可写)。
- **校验与文案**: 按参数声明类型校验,「参数值格式不正确」「参数值超出范围」;恢复默认确认「确定恢复默认值吗?」。
**验收测试用例**:

| AC编号 | 前置条件 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| AC-SYS-001-01 | 超级管理员已登录 | 进入系统设置-系统参数 | 参数按组展示,类型控件正确(数值/开关/文本/枚举) |
| AC-SYS-001-02 | 参数已配置 | 修改数值型参数并保存 | 保存成功,修改记录追加(操作人/时间/旧值/新值) |
| AC-SYS-001-03 | 参数有取值范围 | 输入越界值保存 | 拦截「参数值超出范围」 |
| AC-SYS-001-04 | 参数有默认值 | 点击恢复默认并确认 | 参数回默认值 |
| AC-SYS-001-05 | 管理员账号登录 | 访问系统设置 | 菜单不可见,直接调接口返回 FORBIDDEN(R-SYS-03) |
| AC-SYS-001-06 | 参数声明热生效 | 修改后业务侧验证 | 按声明即时生效(如配送时段) |

**规则引用**: R-SYS-01、R-SYS-03、R-MON-01(金额类参数,01-overview.md §全局约束)。
**业务规则扩充**:
- `system_settings` 脚手架复用:表(`setting_key` 唯一)/实体/仓库可直接作为参数中心持久化层,补齐配置服务、GraphQL/REST 接口与后台页面(G64)。
- 热生效机制:声明「热生效」的参数业务侧按需读取(缓存 + 失效);「重启生效」参数(如安全策略部分)修改后提示生效时机。
- 开放问题——参数分组与业务消费方映射、批量修改、参数导入导出;孤儿种子键 `bucket_deposit_amount` 清理(G06)。
**缺口关联**: G64;G06(孤儿种子键清理)。

#### F-SYS-002 订单与履约参数配置 [规划中]
**需求描述**: 配置订单与履约平台参数:支付超时(自动取消并恢复库存,R-ORD-04)、配送时段(立即配送时限/上午/下午/晚上各时段)、派单超时提醒、自动确认收货天数;订单域按配置消费。现状:支付超时自动取消为规划中(04-order.md §R-ORD-04),配送时段前端硬编码(立即配送 30 分钟内/上午 9:00-12:00/下午 14:00-18:00/晚上 18:00-21:00,F-ORD-001);目标形态:参数后台可配、前端与服务端统一消费。
**页面与入口**: 订单与履约参数页(system-config/order)| 管理后台 | 入口:系统设置 → 订单与履约参数(仅超级管理员可见)。
**UI与交互**:
- **页面布局**:
  1. 支付参数:支付超时(分钟,默认 30,超时自动取消并恢复库存 R-ORD-04);
  2. 配送时段:各时段起止时间(立即配送时限分钟、上午/下午/晚上时间窗,可启停);
  3. 派单与确认:派单超时提醒(分钟)、自动确认收货(天,开放问题);
  4. 保存按钮(二次确认)+ 修改记录。
- **组件清单**: Form、InputNumber、TimePicker、Switch、Button、Modal.confirm(均目标形态)。
- **关键交互流程**:
  1. 进入页面 → 回显当前参数;
  2. 修改 → 确认保存 → 按声明热生效;
  3. 用户端确认订单页配送时段选项按新配置渲染(F-ORD-001);
  4. 支付超时任务按新参数执行(R-ORD-04 接通后)。
- **状态呈现**:
  - 空态:未配置时按默认值展示;
  - 加载态:回显/保存 loading;
  - 错误态:保存失败 toast;
  - 禁用态:无权限只读。
- **校验与文案**: 时间窗合法(开始 < 结束)、超时/时限 > 0,「参数无效」「时间窗不合法」;确认文案「确定保存吗?将影响新订单的履约流程,已生成订单不受影响」。
**验收测试用例**:

| AC编号 | 前置条件 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| AC-SYS-002-01 | 默认参数 | 修改配送时段并保存 | 用户端确认订单页时段选项按新配置渲染 |
| AC-SYS-002-02 | 支付超时默认 30 分钟 | 改为 15 分钟并保存(支付链路接通后) | 待支付订单 15 分钟未支付自动取消并恢复库存(R-ORD-04) |
| AC-SYS-002-03 | 时段已启用 | 停用某时段 | 用户端该时段不再可选 |
| AC-SYS-002-04 | 时段配置中 | 输入开始 ≥ 结束的时间窗 | 拦截「时间窗不合法」 |
| AC-SYS-002-05 | 参数已修改 | 查看已生成订单 | 不受影响(履约参数按下单时快照) |

**规则引用**: R-SYS-01、R-ORD-04(支付超时,04-order.md §2.1)、R-MON-02(配送费,运费规则配置见 12-operations-config.md §F-OPS-005)。
**业务规则扩充**:
- 支付超时规则归属订单域 R-ORD-04,本功能提供参数化配置;配送时段现状前端硬编码,目标为参数中心统一配置、前端按接口读取。
- 开放问题——时段是否区分工作日/周末、每时段是否限量派单;自动确认收货是否启用。
**缺口关联**: G64。

#### F-SYS-003 库存预警阈值配置 [规划中]
**需求描述**: 配置库存预警阈值(03-product.md §R-PRO-02):低库存阈值(默认 10 件)与预警色阶档位(默认 <10 红 / <50 橙 / ≥50 绿),商品列表与商品统计预警按配置生效。现状:阈值与色阶硬编码于后台商品列表展示逻辑,阈值可配置无后台入口(G39);目标形态:阈值后台可配,商品域/统计域消费。

**UI与交互**:
- **页面布局**:

- **组件清单**: Form、InputNumber、Button、Modal.confirm(均目标形态)。

  2. 修改 → 确认保存 → 商品列表库存着色与低库存预警明细按新阈值刷新。
- **状态呈现**:
  - 空态:未配置时按默认阈值展示;
  - 加载态:回显/保存 loading;
  - 错误态:保存失败 toast;
  - 禁用态:无权限只读。
- **校验与文案**: 阈值为 0-99999 整数、色阶档位递增,「阈值无效」「档位需递增」。

**规则引用**: R-SYS-01、R-PRO-02(03-product.md §2.1)。
**业务规则扩充**:

**缺口关联**: G64;G39(阈值配置入口缺失,涉及功能含 F-SYS-003)。

#### F-SYS-004 账号与安全策略配置 [规划中]
**需求描述**: 配置后台账号安全策略:密码强度(最小长度/复杂度)、登录失败锁定(次数/锁定时长)、Token 有效期;随权限强制生效(R-AUTH-04,G49)一并落地。现状:后台登录无密码强度/锁定策略,Token 有效期配置于 application.yml;目标形态:超级管理员在线可配。
**页面与入口**: 账号与安全策略页(system-config/security)| 管理后台 | 入口:系统设置 → 账号与安全(仅超级管理员可见)。
**UI与交互**:
- **页面布局**:
  1. 密码策略:最小长度(默认 8)、是否要求字母数字混合;
  2. 登录安全:失败锁定次数(默认 5)、锁定时长(分钟);

- **组件清单**: Form、InputNumber、Switch、Button、Modal.confirm(均目标形态)。

- **状态呈现**: 加载态/错误态 toast/禁用态(无权限只读)。
- **校验与文案**: 最小长度 6-32、锁定次数 1-99、锁定时长 > 0,「参数无效」。
**验收测试用例**:

**缺口关联**: G64;G49。

#### F-SYS-005 通知与订阅消息配置 [规划中]
**需求描述**: 配置微信订阅消息模板(下单通知/配送完成/催单/支付结果等场景的模板 ID 与启用状态),为订阅消息通知(05-address-delivery.md §F-ADR-011,G08)提供配置支撑;仅配置非敏感模板参数,密钥类(小程序 appsecret 等)受 R-SYS-02 保护。现状:仅 `WeChatProperties`/`message_history`/`user_notification_settings` 脚手架(用户创建时默认订阅设置已落库),无发送服务、无 access-token 服务(G08),无后台配置页;目标形态:模板配置化 + 发送链路接通(F-ADR-011 联动)。
**页面与入口**: 通知配置页(system-config/notifications)| 管理后台 | 入口:系统设置 → 通知与订阅消息(仅超级管理员可见)。
**UI与交互**:
- **页面布局**:
  1. 模板列表:业务场景(下单通知/配送完成/催单/支付结果)/模板 ID/状态(启用/停用)/说明;操作:「编辑」;
  2. 编辑弹窗:模板 ID(粘贴自微信公众平台)、参数映射说明、启用开关;
  3. 用户通知设置预览:用户端订阅设置说明(F-ADR-011 目标形态,现状 `user_notification_settings` 默认值随用户创建落库)。
- **组件清单**: Table、Modal、Form、Input、Switch(均目标形态)。
- **关键交互流程**:
  1. 进入页面 → 回显模板配置;
  2. 编辑模板 ID/启用 → 保存;
  3. 发送链路接通后(F-ADR-011/G08)按模板发送订阅消息。
- **状态呈现**: 空态/加载态/错误态 toast/禁用态(无权限只读)。
- **校验与文案**: 模板 ID 非空且格式合法(微信模板 ID 规则),「模板 ID 不能为空」「模板 ID 格式不正确」。
**验收测试用例**:

| AC编号 | 前置条件 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| AC-SYS-005-01 | 默认未配置 | 编辑场景模板 ID 并启用保存 | 配置保存成功,列表状态更新 |
| AC-SYS-005-02 | 编辑弹窗 | 模板 ID 为空保存 | 拦截「模板 ID 不能为空」 |
| AC-SYS-005-03 | 模板已启用 | 停用模板 | 该场景不再发送(链路接通后) |
| AC-SYS-005-04 | 用户已创建 | 查看用户通知设置 | 默认订阅设置已落库(现状已有) |

**规则引用**: R-SYS-01、R-SYS-02、R-AUTH-04。
**业务规则扩充**:
- 发送链路(G08)为前置:本功能提供模板配置,实际发送依赖 F-ADR-011 落地。
- 密钥保护:小程序 appid/secret 等不提供在线配置(R-SYS-02),仅模板 ID 等非敏感参数在线可配。
- 开放问题——模板变量映射(参数名)是否在线配置,现状按业务场景内置映射。
**缺口关联**: G64;G08。

#### F-SYS-006 数据维护 [规划中]
**需求描述**: 配置数据维护策略:日志保留天数(API/用户操作/业务日志)、清理开关,提供手动清理执行与清理记录;数据备份为运维职责(scripts/backup.sh),不在本功能范围。现状:无保留策略配置,日志持续累积;目标形态:保留策略可配,超期日志按策略自动/手动清理。
**页面与入口**: 数据维护页(system-config/data)| 管理后台 | 入口:系统设置 → 数据维护(仅超级管理员可见)。
**UI与交互**:
- **页面布局**:
  1. 日志保留策略:API 日志/用户操作日志/业务日志保留天数(默认 90),清理开关;
  2. 存储概览:各类日志数据量概览(目标形态);
  3. 「立即清理」按钮(二次确认)+ 清理记录。
- **组件清单**: Form、InputNumber、Switch、Button、Table、Modal.confirm(均目标形态)。
- **关键交互流程**: 配置保留天数 → 定时任务按策略清理 → 清理记录可查;也可手动「立即清理」。
- **状态呈现**: 加载态/错误态 toast/禁用态(无权限只读)。
- **校验与文案**: 保留天数 1-3650 整数,「保留天数无效」;清理确认「确定立即清理超期数据吗?」。
**验收测试用例**:

| AC编号 | 前置条件 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| AC-SYS-006-01 | 默认策略 | 修改保留天数并保存 | 策略生效,清理任务按新策略执行 |
| AC-SYS-006-02 | 存在超期日志 | 点击立即清理并确认 | 按策略清理超期数据,清理记录可查 |
| AC-SYS-006-03 | 输入 0 或负数 | 保存 | 拦截「保留天数无效」 |
| AC-SYS-006-04 | 清理已执行 | 查看日志管理 | 超期数据不再查询到 |

**规则引用**: R-SYS-01。
**业务规则扩充**:
- 备份为运维职责(scripts/backup.sh),本功能聚焦日志保留与清理;是否提供在线备份触发/下载为开放问题(建议保持运维侧)。
**缺口关联**: G64。
