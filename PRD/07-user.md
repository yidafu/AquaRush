## 2. 域内业务规则

### 2.1 认证与权限(AUTH)

**R-AUTH-01 三端认证**: 用户端微信静默登录(免授权弹窗,code 换 token);送水工端微信登录 + 手机号绑定(未绑定不可用任务功能);后台账号密码登录
| 适用功能:F-USR-001、F-USR-010、F-USR-020
| 校验与数值:用户端 Taro.login 取 code → REST /api/auth/wechat/login;送水工端 → /api/auth/delivery/login 与 /api/auth/delivery/bind-phone;后台 username+password 登录
| 并发与边界:静默登录须单飞防并发;送水工未绑定仅持有 pending token,不得获得完整权限
| 现状与目标:三端登录链路现状均通;送水工「一键绑定」现状走降级硬编码(G14),目标恢复微信 getPhoneNumber 授权
| 缺口关联:G14

**R-AUTH-02 权限隔离**: 送水工仅可见分配给自己的订单与本人数据;用户仅可见本人订单与地址;管理员可见全部数据
| 适用功能:F-USR-001、F-USR-002、F-USR-010、F-USR-011、F-USR-020~022
| 校验与数值:数据查询须以当前登录主体 id 为服务端过滤条件;前端隐藏不作为隔离手段;后台数据访问按 01-overview.md §角色权限矩阵 方法级强制(R-AUTH-04)
| 并发与边界:越权访问返回无权限;用户/送水工数据域互斥;管理员账号管理仅超级管理员
| 现状与目标:现状用户端订单为 mock,未走服务端隔离(G02/G17);目标为订单真实化后按本规则强制过滤;后台权限强制现状未生效(G49)
| 缺口关联:G02、G17、G49

**R-AUTH-03 登录态**: 访问令牌过期自动刷新;登出清除本地凭证
| 适用功能:F-USR-001、F-USR-010、F-USR-011、F-USR-020
| 校验与数值:用户端 401 由 network 拦截器触发 silentLogin 自动刷新并重试;登出清除本地 token/user_info
| 并发与边界:401 重试须幂等,防刷新风暴
| 现状与目标:现状用户端刷新为简化实现(me 校验失败即清态);送水工端 logout 清本地;后台登出仅清 localStorage(G15)
| 缺口关联:G15

**R-AUTH-04 权限矩阵与强制生效**: 后台权限模型为代码级静态"角色→权限矩阵"(单一来源 `AdminPermission` 32 码 + `RolePermissionMapping`,矩阵见 01-overview.md §角色权限矩阵),所有后台 resolver/controller 方法级强制校验,缺省拒绝匿名/越权
| 适用功能:F-USR-020~022、F-PRO-006~008、F-ORD-020~022、F-COL-010/011、F-STA-002~006、F-LOG-001~003
| 校验与数值:权限码见 01-overview.md §权限码目录;方法注解 `@PreAuthorize("hasAuthority('PERMISSION_<码>')")`;方法级安全(`@EnableMethodSecurity`)全局开启
| 并发与边界:越权返回 FORBIDDEN、匿名返回 UNAUTHENTICATED;角色来源仅 `admins.role`(后台账号)与 `users.role`(小程序用户),禁止按手机号前缀等不可信信息推断角色;角色变更后重新登录生效
| 现状与目标:现状方法安全未启用、admin `/graphql` permitAll、client 按手机号前缀猜角色(G49)→ 强制生效
| 缺口关联:G49

## 3. 功能需求详述

### 3.1 用户端:账户与个人中心

#### F-USR-001 微信登录与自动登录 [已实现]
**需求描述**: 启动小程序时静默微信登录(免授权弹窗,code 换 token),登录态过期自动刷新;首次进入自动创建用户;登录失败降级为游客浏览(可浏览商品,下单时引导登录)。
现状:app 启动经 `app.tsx` 调用 silentLogin,Taro.login 取 code → REST `/api/auth/wechat/login` → 存 token+userInfo;网络拦截器 401 自动刷新并重试;游客态可在我的页点击头像触发登录。
**页面与入口**: 全局(app 启动)+ 我的页(my)| 用户端小程序 | 入口:app.tsx 启动初始化(initSilentLogin)、应用 onShow(checkLoginStatus)、network 拦截器 401 自动刷新;我的页未登录点击用户区触发登录。
**UI与交互**:
- **页面布局**: 无独立登录页,登录态在全局与我的页呈现;我的页用户区(UserSection)展示头像/昵称/手机号,未登录显示「点击头像登录」。
- **组件清单**: UserSection、AtAvatar、AtToast(均 my/ 下,taro-ui)。
- **关键交互流程**:
  1. app 启动 silentLogin:已有 token 先 checkAndRefreshToken 校验,无效则 Taro.login 取 code → 调登录接口 → 存 token+userInfo;无 token 直接走 code 换 token。
  2. 请求返回 401 → network 拦截器调 silentLogin 后自动重试原请求。
  3. 我的页未登录点击头像 → handleWeChatLogin 显示「正在登录...」→ 成功 toast「登录成功」。
  4. 首次进入后端自动创建用户并回填 userInfo。
- **状态呈现**:
  - 空态:游客态我的页昵称显示「游客」+「点击头像登录」;
  - 加载态:登录中 toast「正在登录...」;
  - 错误态:登录失败 toast「登录失败」/「网络连接失败,请检查网络设置」;
  - 禁用态:登录请求单飞(silentLoginPromise),防并发重复请求。
- **校验与文案**: 登录失败 → toast「登录失败」;网络异常 → 「网络连接失败,请检查网络设置」;游客可浏览商品,需登录操作(如下单)时引导登录后回跳原页面。
**验收测试用例**:

| --- | --- | --- | --- |
| AC-USR-001-01 | 本地无 token,微信环境正常 | 冷启动小程序 | 自动 Taro.login 换 token,无授权弹窗,登录成功后进入正常页面 |
| AC-USR-001-02 | 本地已有 token 与 userInfo | 冷启动小程序 | 先校验 token 有效性,有效直接进入;无效自动 silentLogin 刷新 |
| AC-USR-001-03 | 请求返回 401 | 发起任意需登录接口请求 | network 拦截器触发 silentLogin,成功后自动重试原请求 |

**规则引用**: R-AUTH-01、R-AUTH-02、R-AUTH-03。
**业务规则扩充**:
- R-AUTH-01 扩充:用户端静默登录为「免弹窗」——直接 Taro.login 取 code,不调用 wx.getUserProfile;首次进入自动创建用户。
- R-AUTH-03 扩充:现状 token 刷新为简化实现(checkAndRefreshToken 以 me 查询校验,失败即清态),目标形态为 refreshToken 刷新;401 重试须幂等防刷新风暴。
- 开放问题:用户端登录走 REST `/api/auth/wechat/login`,与下单 GraphQL 链路(client 8080)分离,登录接口现状可用,无 G 关联。
**缺口关联**: —。
