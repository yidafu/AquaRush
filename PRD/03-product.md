# 商品域(PRO)

> 商品是桶装水订购与配送体系的起点,覆盖用户端浏览与收藏、送水工端代客下单选品、管理后台商品管理。按客户分组配置商品专属价(熟客价)为营销价格策略,归营销域(10-marketing.md §F-MKT-002、§R-MKT-01),本域商品价格为目录价,仅消费其展示。本域范围:F-PRO-001~F-PRO-008;规则:R-PRO-01~R-PRO-03、R-MON-03(交叉引用见 §4)。

### 1.2 域内角色与入口

- **普通用户**:用户端小程序 home / product-detail / favorites。浏览商品、查看详情、收藏/取消收藏,并在详情页发起下单(立即购买)与加购(目标形态);对应 01-overview.md §角色权限矩阵「商品浏览/下单/支付/收藏」。
- **送水工**:送水工端小程序 create-order。代客下单时为用户搜索并选择商品、数量与库存核对(见 02-business-flows.md §代客下单流程)。
- **管理员**:管理后台 产品管理(products/list + detail)。商品的创建、编辑、上下架、删除,维护库存、状态、价格、押金与配送设置。

### 1.3 域级验收清单

用户端浏览/详情/收藏可用;后台增删改查/上下架生效,库存联动正确(迁移自原 PRD §11.1「商品」域验收行)。

## 2. 域内业务规则

### 2.1 商品与库存

**R-PRO-01 库存规则**: 下单必须校验库存充足,扣减库存为原子操作,防超卖;支付超时、订单取消自动恢复库存;售罄商品用户端不可下单
| 适用功能:F-PRO-002、F-PRO-005、F-PRO-007、F-PRO-008
| 校验与数值:库存为非负整数;下单数量 ≤ 当前库存;售罄(库存≤0)商品详情页「立即购买」禁用(R-PRO-03)
| 并发与边界:扣减为原子操作,同一商品并发下单库存只能扣至 0(见 13-misc.md §库存与并发);恢复库存由订单域取消/支付超时触发(见 R-ORD-02,定义于 04-order.md §2)
| 现状与目标:现状下单即扣库存、取消/超时恢复由订单域实现;「是否支付成功才扣减」为开放问题(见 02-business-flows.md §现状与目标差异)
| 缺口关联: —

**R-PRO-02 库存预警**: 库存低于阈值(默认 10 件)视为低库存,后台预警展示,阈值可配置
| 适用功能:F-PRO-006
| 校验与数值:默认阈值 10 件;后台商品列表库存 <10 红色、<50 橙色、≥50 绿色
| 并发与边界: —
| 现状与目标:现状后台列表库存标签已按阈值着色预警;阈值可配置暂无后台配置入口,目标形态提供配置项
| 缺口关联: —

### 2.2 商品状态

**R-PRO-03 商品状态**: 商品状态仅在售/下架/售罄三者间流转;下架与售罄商品不进入用户端列表
| 适用功能:F-PRO-001、F-PRO-006、F-PRO-008
| 校验与数值:状态枚举 ONLINE(在售)/OFFLINE(下架)/OUT_OF_STOCK(售罄);用户端列表仅通过 `activeProducts` 查询在售且库存>0 的商品;后台另存 ACTIVE(活跃)值,仅内部兼容使用
| 并发与边界:下架/售罄不影响已生成订单
| 现状与目标:现状前后端状态枚举基本对齐,后台表单下拉仅提供在售/下架/缺货三选;目标形态统一枚举定义(见 13-misc.md §核心实体 商品)
| 缺口关联: —

### 2.3 押金

**R-MON-03 押金**: 商品可配置桶押金金额(可空);押金的收取与退还流程为三期规划 [规划中]
| 适用功能:F-PRO-002、F-PRO-007
| 校验与数值:押金以分存储,可空;范围 0~99999 元,精度 2 位(与 R-MON-01 金额精度一致,见 01-overview.md §全局约束)
| 并发与边界: —
| 现状与目标:现状仅 `ProductModel.depositPrice` 字段与后台表单录入,押金收取/退还流程整体删除,需从零重建
| 缺口关联: 见 13-misc.md §G06

## 3. 功能需求详述

### 3.1 用户端:商品浏览

#### F-PRO-001 首页商品列表 [已实现]
**需求描述**: 首页顶部轮播位展示运营推广图;下方商品列表展示商品封面、名称、描述(副标题/规格)、价格、库存,支持下拉刷新与触底分页加载下一页;点击商品卡进入详情页。
现状:轮播为 3 张硬编码运营图,商品数据走真实 GraphQL(`activeProducts` 仅返回在售且有库存商品);搜索/分类筛选为 TODO 占位(见 facts.md §3);目标形态为搜索与分类筛选可用、轮播图可由后台运营配置。
**页面与入口**: 首页(home)| 用户端小程序 | 入口:小程序启动默认页;下拉刷新/触底加载为页内交互。
**UI与交互**:
- **页面布局**:
  1. 顶部轮播位:Swiper 自动轮播 3 张硬编码运营图(「新鲜好水 / 品质保证 / 优惠活动」,各含标题、副标题、CTA 按钮,第一张「快速下单」跳转下单流程,其余为静态展示)。
  2. 「推荐产品」分隔线(AtDivider)。
  3. 商品网格:商品封面、名称、两行描述、价格(displayCents 分→元,有营销优惠时展示优惠价并划线目录价)、「库存N」。
  4. 加载更多:AtLoadMore(加载中/点击加载更多),末尾显示「没有更多产品了」。

- **组件清单**: CustomNavBar、Swiper/SwiperItem、AtDivider、AtLoadMore、AtFab、AtButton、ProductService。
- **关键交互流程**:
  1. 首屏 useDidShow/useEffect 加载第 0 页(每页 20 条,按 createdAt 倒序);下拉刷新重置到第 0 页并停止下拉动画。

  4. 点击「+」悬浮按钮 → 跳转地址列表选择模式(select=true),为下单准备地址。

- **状态呈现**:
  - 空态:无商品时显示「暂无产品」;

  - 错误态:首屏错误文案 + 「重试」按钮;分页失败 toast「加载失败」;
  - 禁用态:hasMore=false 时不触发加载更多,显示「没有更多产品了」。
- **校验与文案**:
  - 加载失败 → toast「加载失败」/「刷新失败」;
  - 无更多 → 「没有更多产品了」;
  - 空列表 → 「暂无产品」。

  - 数量 > 库存 → toast「库存不足」,不进入下单;

  - 操作失败 → toast「操作失败，请重试」。

#### F-PRO-008 商品上下架与删除 [已实现]
**需求描述**: 商品状态管理(在售/下架,通过编辑表单状态下拉切换);删除商品仅限无关联订单的商品(删除有 Popconfirm 二次确认);下架/售罄商品用户端不再展示(R-PRO-03),已有订单不受影响。
**页面与入口**: 后台产品管理(products/list + detail)| 管理后台 | 入口:列表行「删除」按钮;详情页编辑态「状态」字段切换上下架。
**UI与交互**:
- **页面布局**:
  1. 列表行操作列:详情/编辑/删除(删除带 Popconfirm)。
  2. 状态列:Tag 在售绿 / 下架红 / 缺货橙 / 活跃蓝;编辑态表单下拉「商品状态」三选(在线销售/下架/缺货)。
- **组件清单**: ProductTable(操作列+状态列)、ProductForm/ProductEditor(状态下拉)、Popconfirm、Tag。
- **关键交互流程**:
  1. 下架:进入详情/编辑 → 状态改为「下架」→ 保存 → 列表状态列更新,用户端 `activeProducts` 查询即不再返回该商品。
  2. 删除:点击「删除」→ Popconfirm → 确认后 deleteProduct → message「删除成功」→ 列表刷新。
  3. 被关联订单的商品删除失败 → message「删除失败」提示。
- **状态呈现**:
  - 空态:删除后列表相应减少;
  - 加载态:删除/保存中 loading;
  - 错误态:删除失败 message「删除失败」;
  - 禁用态:状态切换依赖表单保存,未保存不生效。
- **校验与文案**:
  - 删除确认 → 「确定要删除这个商品吗?」「删除后无法恢复，请谨慎操作。」;
  - 删除成功 → 「删除成功」;失败 → 「删除失败」。
**验收测试用例**:
