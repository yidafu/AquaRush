# 商品域(PRO)

> 商品是桶装水订购与配送体系的起点,覆盖用户端浏览与收藏、送水工端代客下单选品、管理后台商品管理。按客户分组配置商品专属价(熟客价)为营销价格策略,归营销域(10-marketing.md §F-MKT-002、§R-MKT-01),本域商品价格为目录价,仅消费其展示。本域范围:F-PRO-001~F-PRO-012(2026-10 新增 F-PRO-010 水桶账户与退押、F-PRO-011 商品导出与批量导入、F-PRO-012 桶账台账与押金对账导出);规则:R-PRO-01~R-PRO-05、R-MON-03(交叉引用见 §4)。

### 1.2 域内角色与入口

- **普通用户**:用户端小程序 home / product-detail / favorites。浏览商品、查看详情、收藏/取消收藏,并在详情页发起下单(立即购买)与加购(目标形态);对应 01-overview.md §角色权限矩阵「商品浏览/下单/支付/收藏」。
- **送水工**:送水工端 App create-order。代客下单时为用户搜索并选择商品、数量与库存核对(见 02-business-flows.md §代客下单流程)。
- **管理员**:管理后台 产品管理(products/list + detail)。商品的创建、编辑、上下架、删除,维护库存、状态、价格;配送规则统一由运营配置域配置(F-OPS-005 配送费规则,见 12-operations-config.md),商品不再维护商品级配送设置;水桶押金由「押金管理」按规格独立维护(见 14-misc.md §G06)。

### 1.3 域级验收清单

用户端浏览/详情/收藏可用;后台增删改查/上下架生效,库存联动正确(迁移自原 PRD §11.1「商品」域验收行)。

## 2. 域内业务规则

### 2.1 商品与库存

**R-PRO-01 库存规则**: 下单必须校验库存充足,扣减库存为原子操作,防超卖;支付超时、订单取消自动恢复库存;售罄商品用户端不可下单
| 适用功能:F-PRO-002、F-PRO-005、F-PRO-007、F-PRO-008
| 校验与数值:库存为非负整数;下单数量 ≤ 当前库存;售罄(库存≤0)商品详情页「立即购买」禁用(R-PRO-03)
| 并发与边界:扣减为原子操作,同一商品并发下单库存只能扣至 0(见 14-misc.md §库存与并发);恢复库存由订单域取消/支付超时触发(见 R-ORD-02,定义于 04-order.md §2)
| 现状与目标:现状下单即扣库存、取消/超时恢复由订单域实现;「是否支付成功才扣减」为开放问题(见 02-business-flows.md §现状与目标差异)
| 缺口关联: —

**R-PRO-02 库存预警**: 库存低于阈值(默认 10 件)视为低库存,后台预警展示,阈值可配置
| 适用功能:F-PRO-006
| 校验与数值:默认阈值 10 件;后台商品列表库存 <10 红色、<50 橙色、≥50 绿色
| 并发与边界: —
| 现状与目标:现状后台列表库存标签已按阈值着色预警;阈值可配置暂无后台配置入口,目标形态提供配置项
| 缺口关联: —

### 2.2 商品状态

**R-PRO-03 商品状态**: 商品状态仅在售/下架/售罄三者间流转;下架与售罄商品不进入用户端列表
| 适用功能:F-PRO-001、F-PRO-006、F-PRO-008
| 校验与数值:状态枚举 ONLINE(在售)/OFFLINE(下架)/OUT_OF_STOCK(售罄);用户端列表仅通过 `activeProducts` 查询在售且库存>0 的商品;后台另存 ACTIVE(活跃)值,仅内部兼容使用
| 并发与边界:下架/售罄不影响已生成订单
| 现状与目标:现状前后端状态枚举基本对齐,后台表单下拉仅提供在售/下架/缺货三选;目标形态统一枚举定义(见 14-misc.md §核心实体 商品)
| 缺口关联: —

### 2.3 水桶押金与空桶回收(循环水桶)

**R-MON-03 水桶押金与空桶回收**: 水桶押金是用户使用**循环水桶**缴纳的**可退保证金**(2026-10 按行业惯例由「一次性水桶费」恢复为「押金桶」)——用户首次使用某规格水桶时按规格缴纳押金,送水工上门配送时回收空桶,用户申请退桶且空桶完好的,押金**全额退还**;押金线上登记、可追溯、可跨地址转移 [见 14-misc.md §G06]
| 适用功能:F-PRO-007(押金按规格独立配置、与商品解耦)、F-ORD-001/004/005(订单费用明细展示押金行)、F-ORD-011(完成配送时可登记回收空桶)、14-misc.md §G06(押金模块)
| 校验与数值:押金按水桶规格配置(如「19L 桶 押金 ¥40」),金额以分存储;范围 0~99999 元,精度 2 位(与 R-MON-01 金额精度一致,见 01-overview.md §全局约束);同一用户**同一规格在租押金桶只收一次押金**(已有未退押金的同规格桶不再重复收取),随首单快照计入实付(payAmountCents);退押金额=该规格押金 × 回收桶数,押金收取/退还均**不计入营收**(独立押金账本)
| 并发与边界:押金随单收取(deposit_records PENDING→HELD),退押由用户申请、空桶回收后经管理员在后台确认退还(HELD→REFUNDED,记 DEPOSIT_REFUND 独立退款账本,不计入营收/退款统计);空桶回收在送水工「完成配送」时可登记回收数量(非强制);订单取消/退款时随单押金一并退回;退押以押金记录状态幂等,防并发重复退还
| 现状与目标:2026-10 按行业惯例修订——恢复「押金随单收取 + 空桶回收 + 退桶退押」模型(重建 deposit_records 收取→退还闭环、后台「押金管理」:押金价目 CRUD + 押金记录 + 空桶回收与退押确认 + 手动退还),废弃一次性水桶费语义(barrel_fees/barrel_purchases 回退)
| 缺口关联: 见 14-misc.md §G06

### 2.4 水桶账户与桶账

**R-PRO-04 水桶账户与退押申请**: 为用户建立**桶账**(按规格的在租押金桶数、欠桶数、押金合计),用户可查询并自助发起**退桶退押申请**;申请经门店回收空桶并确认后,按完好桶数**全额退还**对应押金(损坏/缺失扣减规则为开放问题);桶账与押金记录、空桶回收登记、订单三者一致,退押全程留痕可追溯 [2026-10 新增]
| 适用功能:F-PRO-010(用户端水桶账户/退押申请)、R-MON-03(押金收取与退还)、F-ORD-011(完成配送登记回收空桶)
| 校验与数值:桶账口径——在租押金桶数 = 该规格押金「已收取未退还」的押金记录数之和;欠桶数 = 应回收未回收的空桶数(送水工配送登记为准);押金合计 = Σ(在租桶数 × 规格押金);退押金额 = 回收完好桶数 × 规格押金(损坏/缺失扣减为开放问题);金额以分计(R-MON-01)
| 并发与边界:退押申请状态机=待处理 → 已回收 → 已退还 / 已驳回;退还以押金记录状态幂等,防并发重复退还(R-MON-03);申请与送水工回收并发以退押记录状态为准;退押不计入营收/退款统计(独立押金账本 DEPOSIT_REFUND)
| 现状与目标:规划中——押金模型 2026-10 已恢复(R-MON-03,`deposit_records` 收取→退还闭环、送水工完成配送可登记回收空桶、后台「押金管理」);用户端「水桶账户」页与「退押申请」入口未实现,现状入口 `barrel-shop/barrel-mine` 文案仍为「一次性购买塑料水桶」,需按押金桶口径统一
| 缺口关联: 见 14-misc.md §G75

**R-PRO-05 桶账台账与导出规则**: 后台按**客户维度**建立循环水桶台账——逐客户展示在租押金桶数(按规格)、欠桶数(应回收未回收)、押金合计与押金余额,支持筛选、排序与**导出台账**(用于对账、催收与清退);台账口径与押金记录(deposit_records)、空桶回收登记、订单三者一致 [2026-10 新增]
| 适用功能:F-PRO-012(桶账台账与导出)、R-PRO-04(桶账口径)、R-MON-03(押金收取与退还)
| 校验与数值:在租桶数 = 该客户/规格「已收取未退还」的押金记录数;欠桶数 = 应回收未回收空桶数(送水工配送登记为准);押金合计 = Σ(在租桶数 × 规格押金)、押金余额 = 押金合计 − 已退押金;金额以分计(R-MON-01),导出为元两位小数
| 并发与边界:台账为实时聚合视图,退押/回收后即时刷新;导出为只读快照,不改变数据;导出含客户姓名/手机号等个人信息时须**脱敏**(合规,先脱敏再输出);导出留痕
| 现状与目标:规划中——押金模型已恢复(R-MON-03,后台「押金管理」含押金价目/押金记录/空桶回收与退押确认),但**无按客户的桶账台账视图与导出**;「某客户欠桶几个、押金多少」需人工跨表核对
| 缺口关联: 见 14-misc.md §G87

  3. 新增/编辑弹窗:选项值(1-100 字符必填,同类型内唯一)、排序号(缺省排末尾)、启用开关;
  4. 商品表单:规格(必选 Select showSearch)/水源地(可选 Select showSearch allowClear),选项=配置字典启用项 + 商品当前值兜底,无候选时提示「暂无配置,请点击『管理』添加…」。

- **关键交互流程**:
  1. 配置页加载:单页单请求(规则 #10)一次取回两类全量选项(含禁用项);

  3. 禁用选项:不在商品表单下拉中展示;已使用该值的商品详情/编辑回显不受影响(当前值兜底补入选项);
  4. 删除选项:仅移除候选,商品上已保存的值不受影响(商品快照值保留)。
- **状态呈现**:
  - 空态:某类无配置时表格空态「暂无配置选项,点击右上角『新增』添加」;
  - 加载态:列表/保存 loading;
  - 错误态:保存失败 message(重复值「选项值在同类型内已存在」);
  - 禁用态:已禁用选项在商品表单不出现。
- **校验与文案**:
  - 选项值必填、1-100 字符 → 「选项值长度应在1-100个字符之间」;
  - 同类型内值唯一 → 服务端校验拦截(「Duplicate product option value …」);
  - 删除确认 → 「确定删除该选项吗?」「删除后商品表单下拉不再展示;已引用该值的商品不受影响」。
