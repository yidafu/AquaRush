# 收银与对账域(COL)

> 收银与对账域覆盖送水工每日收款日报的提交/确认与按日对账的匹配/差异/审核闭环。本域范围:F-COL-001/002/003(送水工端收款与统计)、F-COL-010/011(管理后台收银对账);规则:R-COL-01~04(交叉引用见 §4)。

### 1.2 域内角色与入口

- **送水工**:使用送水工端小程序。「我的」页进入「每日收款」(daily-collection)、「对账记录」(reconciliation-records);底部 TabBar「统计」(statistics)。对应 01-overview.md §角色权限矩阵「接单/配送/收款/日报」。
- **管理员**:使用管理后台。导航「收银对账」(daily-collection)查看/确认日报并执行/复核对账。对应 01-overview.md §角色权限矩阵「收银对账(确认/审核/执行对账)」。

### 1.3 域级验收清单

- 对账匹配/差异/审核闭环;

> 注:「争议处理闭环」当前受 R-COL-02 状态偏差影响不可达(DISPUTED 从未赋值),见 §2.1 与 §4 候补缺口。

## 2. 域内业务规则

### 2.1 日报规则(R-COL-01、R-COL-02)

**R-COL-01 日报唯一性**: 定义:同一送水工同一日仅能提交一份日报,重复提交拦截。
| 适用功能:F-COL-001、F-COL-010。
| 校验与数值:以「送水工 + 收款日期」唯一;重复提交提示「今日已提交」。
| 并发与边界:服务端唯一约束兜底,防止并发重复提交。
| 现状与目标:送水工端提交后本地状态置「已提交」并展示,前端未显式禁用按钮,重复提交由服务端拦截。
| 缺口关联:—。

**R-COL-02 容差规则**: 定义:日报填报值与系统计算值的差异在容差内正常提交;超容差进入「有争议」状态,由管理员审核处理。
| 适用功能:F-COL-001、F-COL-010、F-COL-011。
| 校验与数值:容差默认 0 分、可配置;实现现状前端与后端容差固定 ±100 分(1 元),水票数量须精确匹配(≠0 张即弹差异确认)。
| 并发与边界:现金/扫码按分比较绝对值,水票按张数精确比较。
| 现状与目标:实现偏差——后端 `submitDailyCollection` 超容差将记录置为「草稿」(DRAFT)而非「有争议」(DISPUTED),DISPUTED 从未被赋值(见 facts.md §3);目标形态为超容差进入「有争议」并交由管理员审核处理。
| 缺口关联:—(偏差待修复或文档确认,已列入候补缺口)。

### 2.2 对账规则(R-COL-03、R-COL-04)

**R-COL-03 对账闭环**: 定义:对账结果必须经过管理员审核才能完结;有差异对账记录保留差异明细供追溯。
| 适用功能:F-COL-002、F-COL-011。
| 校验与数值:对账状态 PENDING/MATCHED/DISCREPANCY/REVIEWED,界面文案「待对账/匹配/有差异/已复核」(与 PRD 原文「待处理/已匹配/已审核」措辞不同);差异明细由 `ReconciliationDiscrepancy` 实体留痕。
| 并发与边界:已复核记录不再显示复核入口,防止二次审核。
| 现状与目标:对账由调度器每日凌晨 3 点对昨日自动执行(`DailyCollectionScheduler`),后台亦可手动触发;对账详情当前仅展示汇总金额与差异总额,未呈现逐单差异明细。
| 缺口关联:—。

**R-COL-04 收款方式**: 定义:配送收款方式为现金/水票/扫码三选一,与订单支付方式相互独立(在线支付订单不产生现场收款)。「水票」收款方式对应电子票(线上核销,见 10-marketing.md §R-MKT-08);实体票(线下纸票)不在本规则范围。
| 适用功能:F-COL-001、F-COL-011。
| 校验与数值:日报三栏=现金(元)/水票(张)/扫码(元);系统预计算按完成配送时选择的收款方式汇总当日已完成订单——电子票核销订单自动计入水票张数,实体票数量由送水工手动登记(开放问题,见 10-marketing.md §F-MKT-007)。
| 并发与边界:—。
| 现状与目标:现状三栏应收来源于当日已完成订单的收款方式汇总,与订单流水一致。
| 缺口关联:—。

## 3. 功能需求详述

### 3.1 送水工端:收款与日报

#### F-COL-001 每日收款提交 [已实现]

**需求描述**: 送水工按日提交收款日报:系统按当日本人已完成订单自动预计算应收(现金/水票数量/扫码收款三栏),送水工填写实际收款,差异自动展示;提交后进入审核。三栏金额与实际不符时展示差异并给出说明入口;今日已提交时展示提交状态,不可重复提交(R-COL-01)。验收要点:系统计算值与订单流水一致;差异超容差进入争议状态(R-COL-02);提交幂等。
现状:日报提交全链路真实(系统预计算、容差 ±1 元、差异说明必填),见 facts.md §3。
**页面与入口**: 每日收款页(daily-collection)| 送水工端小程序 | 入口:「我的」页「每日收款」→ daily-collection。
**UI与交互**:
- **页面布局**: 自上而下:
  1. 顶部说明条 AtNoticebar:三条提示「1. 现金和扫码收款将自动与今日完成订单金额对比」「2. 差异在1元以内视为正常」「3. 提交后可由管理员确认审核」。
  2. 收款日期区:「收款日期」+ 当日日期(YYYY-MM-DD)。
  3. 当前状态卡:「当前状态」+ 状态文本(草稿/已提交/已确认/有争议,按状态着色),仅当日已有记录时展示。
  4. 今日收款录入:「今日订单情况」区块(OrderInfoRow:订单总数、现金应收、扫码应收、水票应收,来源系统预计算)+ AtForm 三栏输入(现金收款-元/水票数量-张/扫码收款-元)+「合计」实时计算现金+扫码。
  5. 底部主按钮 AtButton「提交收款」(提交中显示「提交中...」)。
  6. 金额差异确认弹窗 AtModal:展示现金/水票/扫码差异 + 差异说明输入(≤200 字)。
- **组件清单**: PageContainer、AtNoticebar、AtForm、AtInput、AtButton、AtModal、OrderInfoRow(taro-ui + 本地 components)。
- **关键交互流程**:

  1) useAuth 取送水工身份,getTodayCollection 加载今日收款记录,有已填写数据自动回填三栏并展示状态;
  2) 填写三栏,合计实时计算;
  3) 提交校验:三栏全零 → toast「请填写收款金额」;否则按分计算与系统计算值的差异(现金/扫码超 ±100 分或水票 ≠0 张)→ 弹差异确认弹窗;容差内直接提交;
  4) 差异弹窗内说明必填(空 → toast「请输入情况说明」),点「确定」带说明提交;
  5) 提交成功 toast「提交成功」并刷新本地状态为「已提交」;失败 toast「提交失败」。

- **状态呈现**: 空态:今日无订单时「今日订单情况」全为 0;加载态:数据加载中;错误态:加载失败、提交失败 toast;禁用态:提交中按钮 loading 防重复提交(服务端 R-COL-01 兜底幂等);已提交时「当前状态」卡显示「已提交」。
- **校验与文案**: 三栏全零 →「请填写收款金额」;差异说明为空 →「请输入情况说明」;重复提交 →「今日已提交」(服务端);提交成功 →「提交成功」;提交失败 →「提交失败」。

### 3.2 管理后台:收银对账

  3) 收款记录 Table 列:配送员ID/收款日期/现金金额/水票数量/扫码金额/订单数量/订单金额/系统计算现金/系统计算扫码/系统计算水票/系统计算订单金额/差异/状态/操作;
  4) 操作列仅对「已提交」行显示「确认」链接按钮。

- **组件清单**: Card、Statistic、Tabs、Table、Tag、Button、Modal.confirm、message(antd)。
- **关键交互流程**:

- **校验与文案**: 确认弹窗文案「确认配送员 {id} 的收款记录吗?」;成功「确认成功」。争议日报处理(查看差异说明/驳回)当前无 UI。

#### F-COL-011 每日对账与审核 [已实现]

**需求描述**: 按日执行对账:系统自动比对订单收款与日报,生成对账结果(已匹配/有差异);管理员审核差异并标记处理结果;对账结果与订单/日报数据一致;审核状态流转完整(待处理→已匹配/有差异→已审核)。
现状:对账由调度器每日凌晨 3 点对昨日自动执行,后台可手动触发;对账执行、复核(REVIEWED)链路真实。
**页面与入口**: 后台收银对账(daily-collection)「对账记录」Tab | 管理后台 | 入口:后台导航「收银对账」→「对账记录」Tab。
**UI与交互**:
- **页面布局**:

  1) 右上「手动执行对账」按钮(loading 态);
  2) 对账记录 Table 列:对账日期/订单总数/订单金额/总收款金额/现金收款/水票数量/扫码收款/差异金额/状态/操作(查看详情);
  3) 「对账详情」Modal:订单总数/订单金额/现金收款/扫码收款/差异金额/状态 Tag + 复核备注 TextArea + 「确认复核」按钮(非「已复核」时显示),已复核展示复核时间与复核备注。

- **组件清单**: Card、Table、Tag、Button、Modal、Form/Input.TextArea、Statistic、message(antd)。
- **关键交互流程**:

  1) 「手动执行对账」→ Modal.confirm「确定要执行对账吗?重复执行会更新已有数据」→ EXECUTE_DAILY_RECONCILIATION(默认昨日日期)→ 成功 message「对账执行成功」/失败「对账执行失败: …」并 refetch;
  2) 点「查看详情」→ 打开对账详情 Modal;
  3) 填复核备注 →「确认复核」→ REVIEW_RECONCILIATION → message「复核成功」,状态置「已复核」并展示复核时间/备注;
  4) 每日 03:00 调度器自动对昨日执行对账(`DailyCollectionScheduler`)。

- **状态呈现**: 空态:无对账记录表格为空;加载态:Table loading + 按钮 loading;错误态:对账执行失败 message;禁用态:已「已复核」记录不显示「确认复核」按钮;差异金额 |差异|≤1 元绿/否则红。
- **校验与文案**: 执行对账确认文案「确定要执行对账吗?重复执行会更新已有数据」;复核备注 TextArea 占位「请输入复核备注」;成功「对账执行成功」「复核成功」。
