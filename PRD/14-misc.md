### 数据一致性要求

- **订单 ↔ 库存**:下单扣减、取消/超时恢复,两者必须一致,防止超卖与库存虚高;
- **日报 ↔ 订单流水**:系统预计算的应收金额来源于当日已完成订单的收款方式汇总,与订单数据必须一致;
- **对账 ↔ 日报/订单**:对账以订单流水与日报为基准比对,差异必须有明细可追溯;
- **评价 ↔ 订单**:一单一评,评价数据与订单、送水工一一关联;
- **送水工统计 ↔ 订单**:送水工的完成单量、收入、评分均来源于订单与评价,实时或准实时同步;
- **分组价 ↔ 订单成交价**:订单成交价按下单时的分组价/实收价快照,后续分组价调整不追溯已生成订单(R-MKT-01);
- **营销优惠 ↔ 订单成交价**:订单记录活动/优惠券优惠明细快照,后续营销配置变更不追溯已生成订单;优惠券核销幂等,一单一券不可叠加(R-MKT-02/07);
- **系统参数 ↔ 业务行为**:参数变更按声明生效,不追溯已生成业务数据(订单成交价/运费/履约参数按下单时快照);参数与运营内容修改全程审计留痕(R-SYS-01、R-OPS-01,见 11-system-settings.md、12-operations-config.md);

## 异常处理与边界场景

> 跨域异常场景集中定义,域文件通过 `14-misc.md §小节` 文本引用。每行标注关联规则/缺口;`[规划中]` 行为目标形态。

### 支付类

| 场景                 | 处理策略                                                           |
| -------------------- | ------------------------------------------------------------------ |
| 支付超时             | 自动取消订单并恢复库存,通知用户(R-ORD-04)                          |
| 支付回调延迟/丢失    | 以订单待支付状态兜底,用户侧支持主动查询支付结果后重发回调 [规划中] |
| 重复回调             | 幂等处理,不重复变更状态(R-PAY-01)                                  |
| 回调金额与订单不一致 | 拒绝放行并告警,订单保持待支付                                      |
| 已支付订单取消       | 必须走退款流程,退款到账前订单显示"退款中" [规划中]                 |
| 退款失败             | 状态标记失败,后台人工介入重试                                      |

### 履约类

| 场景                           | 处理策略                                                                          |
| ------------------------------ | --------------------------------------------------------------------------------- |
| 订单长时间无人接单             | 后台可人工派单;超时提醒 [规划中]                                                  |
| 配送员离线                     | 派单列表不可选;已派单订单不受影响                                                 |
| 完成配送未拍照                 | 硬性拦截(R-ORD-07)                                                                |
| 配送中订单异常(用户联系不上等) | 送水工联系客服,后台可介入调整订单状态                                             |
| 重复接单/重复派单              | 幂等拦截,提示"该订单已被处理"                                                     |
| 实时推送断线/离线              | 降级为定时轮询(默认 30s)与离线消息补发,推送与轮询按幂等键去重不重复渲染(R-ORD-10,通知域映射 R-NTF-02/03,见 13-notification.md) |
| 订阅消息发送失败/access-token 过期 | 发送失败按幂等键重试(WeChatProperties maxRetries);access-token 缓存失效自动刷新;用户已拒收/未授权不发送,降级站内查看(R-NTF-01) [规划中] |
| 定位权限被拒                   | 送水工端提示开启定位;轨迹上报停止,配送主流程不受影响(R-ADR-03)                    |

### 对账类

| 场景                 | 处理策略                                                                                                                               |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 日报差异超容差       | 进入「有争议」,管理员审核差异说明后处理(R-COL-02;**现状差异**:代码超容差置「草稿」,「有争议」未赋值,见 06-collection.md §域内业务规则) |
| 重复提交日报         | 拦截,提示今日已提交(R-COL-01)                                                                                                          |
| 日报已提交后发现填错 | 联系管理员驳回后重新提交 [规划中]                                                                                                      |
| 对账不匹配           | 标记「有差异」并保留差异明细,管理员人工核对                                                                                            |

### 库存与并发

| 场景           | 处理策略                                |
| -------------- | --------------------------------------- |
| 库存不足下单   | 拦截并提示"库存不足";详情页展示缺货     |
| 并发下单超卖   | 原子扣减,同一库存只能被扣至 0(R-PRO-01) |
| 取消与支付并发 | 以状态机合法性为准,非法流转拒绝         |

### 地址与范围

| 场景                 | 处理策略                            |
| -------------------- | ----------------------------------- |
| 无收货地址下单       | 引导先添加地址                      |
| 地址不可达(范围外)   | 拦截并提示更换地址 [规划中](G07)    |
| 地图选点失败         | 允许手动填写地址,经纬度可空         |
| 地址删除时被订单引用 | 订单保留地址快照,删除不影响历史订单 |

### 用户行为

| 场景             | 处理策略                           |
| ---------------- | ---------------------------------- |
| 重复点击提交订单 | 幂等,仅产生一单(R-ORD-06)          |
| 游客直接下单     | 引导登录后回跳继续下单             |
| 下单后反悔       | 未支付可取消;已支付走退款 [规划中] |
| 催单刷屏         | 防抖限制,短时间内仅生效一次        |
