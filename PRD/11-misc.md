### 数据一致性要求

- **订单 ↔ 库存**:下单扣减、取消/超时恢复,两者必须一致,防止超卖与库存虚高;
- **日报 ↔ 订单流水**:系统预计算的应收金额来源于当日已完成订单的收款方式汇总,与订单数据必须一致;
- **对账 ↔ 日报/订单**:对账以订单流水与日报为基准比对,差异必须有明细可追溯;
- **评价 ↔ 订单**:一单一评,评价数据与订单、送水工一一关联;
- **送水工统计 ↔ 订单**:送水工的完成单量、收入、评分均来源于订单与评价,实时或准实时同步;
- **分组价 ↔ 订单成交价**:订单成交价按下单时的分组价/实收价快照,后续分组价调整不追溯已生成订单(R-MKT-01);
- **营销优惠 ↔ 订单成交价**:订单记录活动/优惠券优惠明细快照,后续营销配置变更不追溯已生成订单;优惠券核销幂等,一单一券不可叠加(R-MKT-02/07);

## 异常处理与边界场景

> 跨域异常场景集中定义,域文件通过 `11-misc.md §小节` 文本引用。每行标注关联规则/缺口;`[规划中]` 行为目标形态。

### 支付类

| 场景                 | 处理策略                                                           |
| -------------------- | ------------------------------------------------------------------ |
| 支付超时             | 自动取消订单并恢复库存,通知用户(R-ORD-04)                          |
| 支付回调延迟/丢失    | 以订单待支付状态兜底,用户侧支持主动查询支付结果后重发回调 [规划中] |
| 重复回调             | 幂等处理,不重复变更状态(R-PAY-01)                                  |
| 回调金额与订单不一致 | 拒绝放行并告警,订单保持待支付                                      |
| 已支付订单取消       | 必须走退款流程,退款到账前订单显示"退款中" [规划中]                 |
| 退款失败             | 状态标记失败,后台人工介入重试                                      |

### 履约类

| 场景                           | 处理策略                                                                          |
| ------------------------------ | --------------------------------------------------------------------------------- |
| 订单长时间无人接单             | 后台可人工派单;超时提醒 [规划中]                                                  |
| 配送员离线                     | 派单列表不可选;已派单订单不受影响                                                 |
| 完成配送未拍照                 | 硬性拦截(R-ORD-07)                                                                |
| 配送中订单异常(用户联系不上等) | 送水工联系客服,后台可介入调整订单状态                                             |
| 重复接单/重复派单              | 幂等拦截,提示"该订单已被处理"                                                     |
| 实时推送断线/离线              | 降级为定时轮询(默认 30s)与离线消息补发,推送与轮询按幂等键去重不重复渲染(R-ORD-10) |
| 定位权限被拒                   | 送水工端提示开启定位;轨迹上报停止,配送主流程不受影响(R-ADR-03)                    |

### 对账类

| 场景                 | 处理策略                                                                                                                               |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 日报差异超容差       | 进入「有争议」,管理员审核差异说明后处理(R-COL-02;**现状差异**:代码超容差置「草稿」,「有争议」未赋值,见 06-collection.md §域内业务规则) |
| 重复提交日报         | 拦截,提示今日已提交(R-COL-01)                                                                                                          |
| 日报已提交后发现填错 | 联系管理员驳回后重新提交 [规划中]                                                                                                      |
| 对账不匹配           | 标记「有差异」并保留差异明细,管理员人工核对                                                                                            |

### 库存与并发

| 场景           | 处理策略                                |
| -------------- | --------------------------------------- |
| 库存不足下单   | 拦截并提示"库存不足";详情页展示缺货     |
| 并发下单超卖   | 原子扣减,同一库存只能被扣至 0(R-PRO-01) |
| 取消与支付并发 | 以状态机合法性为准,非法流转拒绝         |

### 地址与范围

| 场景                 | 处理策略                            |
| -------------------- | ----------------------------------- |
| 无收货地址下单       | 引导先添加地址                      |
| 地址不可达(范围外)   | 拦截并提示更换地址 [规划中](G07)    |
| 地图选点失败         | 允许手动填写地址,经纬度可空         |
| 地址删除时被订单引用 | 订单保留地址快照,删除不影响历史订单 |

### 用户行为

| 场景             | 处理策略                           |
| ---------------- | ---------------------------------- |
| 重复点击提交订单 | 幂等,仅产生一单(R-ORD-06)          |
| 游客直接下单     | 引导登录后回跳继续下单             |
| 下单后反悔       | 未支付可取消;已支付走退款 [规划中] |
| 催单刷屏         | 防抖限制,短时间内仅生效一次        |

### 可用性与兼容性

- 用户端与送水工端适配主流微信小程序版本(基础库 ≥ 2.x),iPhone/Android 两端体验一致;
- 弱网环境给出加载/失败重试反馈,不出现白屏;
- 后台兼容主流浏览器(Chrome/Edge/Safari 近两年版本)。

### 安全与合规

- **金额安全**:金额以分存储,展示层换算;支付回调验签防篡改(R-PAY-01);
- **权限隔离**:三端数据按角色隔离,送水工不可见非本人数据(R-AUTH-02);
- **微信合规**:订阅消息模板、用户隐私(手机号/位置/相册)使用须符合微信小程序审核规范,隐私授权明示;
- **日志审计**:关键操作全程留痕,后台日志满足追溯要求。

### 可维护性

- 三端与后端版本协同发布;单服务器轻量化部署,支持备份恢复;
- 业务规则集中在服务端,前端不承载关键金额计算(配送费校验为规划项,R-MON-02);
- 订单状态机等核心枚举单一来源,三端共享一致(02-business-flows.md §订单状态机)。

### 端到端验收场景

> 场景内步骤引用 `AC-E2E-xx` 作为端到端用例编号,便于排期引用。前置条件依赖 `[规划中]`/`[部分实现]` 链路的,标注受阻塞的缺口。

#### AC-E2E-01 用户在线下单全链路(P0 验收,当前受 G01/G02/G17 阻断)

```text
前置:有在售商品、有库存、有配送区域、有在线送水工、有收货地址
步骤:用户浏览商品 → 立即购买 → 确认订单(费用明细正确:满30免5元)
     → 提交订单(进入待支付)→ 微信支付 → 订单进入待派单
     → 后台派单给在线送水工 → 送水工端可见并开始配送
     → 送水工拍照+选收款方式完成配送 → 用户端订单显示已完成并可跟踪全程
     → 后台可核验配送照片与支付信息 → 当日对账匹配
预期:全链路数据一致、状态流转合法、金额分毫不差
```

#### AC-E2E-02 送水工代客下单与自提

```text
前置:送水工已登录且绑定手机号
步骤:送水工代客下单(选商品/地址/数量/自提)→ 订单进入待派单
     → 自提订单标记已收款 → 送水工完成配送(自提无需现场收款)
     → 当日日报中该笔计入对应收款方式
预期:自提标记正确;日报计算与订单一致
```

#### AC-E2E-03 对账差异处理(受 G28/G30 阻断)

```text
前置:送水工当日完成订单且有现金收款
步骤:送水工提交日报(现金金额与系统计算值差异超容差)→ 状态为有争议
     → 后台查看差异说明 → 管理员确认/驳回 → 日报状态更新
     → 执行当日对账 → 标记差异 → 管理员审核 → 对账完结
预期:差异全程可追溯;状态流转完整
```

### 附录C:术语表

| 术语                   | 含义                                                                               |
| -------------------- | -------------------------------------------------------------------------------- |
| 水票                   | 预购的「桶数凭证」,一票抵一桶,用户购票入票包、下单核销抵扣,被核销桶计入送水工日报"水票数量"栏(R-MKT-08,见 10-marketing.md)    |
| 日报                   | 送水工每日提交的收款记录(现金/水票/扫码),与系统计算值比对                                                  |
| 对账                   | 按日将订单收款流水与日报比对,发现并处理差异的流程                                                        |
| 容差                   | 日报填报值与系统计算值允许的差异范围,超容差进入争议状态                                                     |
| 代客下单                 | 送水工代替用户(如电话订水)在小程序创建订单                                                           |
| 自提                   | 用户到店自取,订单标记为已收款,免配送                                                              |
| 押金                   | 购买桶装水时收取的桶押金,退桶时退还(规划中)                                                          |
| 客户分组                 | 对客户的归类(如熟客/VIP),为订单计价提供分组维度(R-MKT-01,见 10-marketing.md)                          |
| 熟客价                  | 面向客户分组的商品专属价,下单时自动应用并优先于目录价,代客下单可手动覆盖(规划中)                                       |
| 优惠券                  | 用户持有的抵扣凭证(现金券/折扣券),确认订单时勾选使用,一单一券(R-MKT-03)                                      |
| 满减/满折                | 订单金额达到门槛后自动减免固定金额或按折扣率优惠的营销活动(R-MKT-04)                                          |
| 限时特价                 | 商品在指定时间窗内的活动价,活动期自动应用并划线原价展示(R-MKT-05)                                           |
| 会员折扣                 | 面向客户分组/会员等级自动应用的订单级百分比折扣(R-MKT-06)                                               |
| 满赠/买赠                | 订单达标后自动赠送指定商品(赠品),赠品为附加 0 价行随单配送(R-MKT-09,见 10-marketing.md)                     |
| 首单立减(新人专享价)          | 新用户首次下单自动享受的专属优惠,订单级立减或商品级新人价,一单一享(R-MKT-10,见 10-marketing.md)                   |
| 待派单/待配送/配送中          | 订单履约三阶段:等待分配送水工 / 已接单未出发 / 配送中                                                   |
