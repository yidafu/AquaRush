### 数据一致性要求

- **订单 ↔ 库存**:下单扣减、取消/超时恢复,两者必须一致,防止超卖与库存虚高;
- **日报 ↔ 订单流水**:系统预计算的应收金额来源于当日已完成订单的收款方式汇总,与订单数据必须一致;
- **对账 ↔ 日报/订单**:对账以订单流水与日报为基准比对,差异必须有明细可追溯;
- **评价 ↔ 订单**:一单一评,评价数据与订单、送水工一一关联;
- **送水工统计 ↔ 订单**:送水工的完成单量、收入、评分均来源于订单与评价,实时或准实时同步;
- **分组价 ↔ 订单成交价**:订单成交价按下单时的分组价/实收价快照,后续分组价调整不追溯已生成订单(R-MKT-01);
- **营销优惠 ↔ 订单成交价**:订单记录活动/优惠券优惠明细快照,后续营销配置变更不追溯已生成订单;优惠券核销幂等,一单一券不可叠加(R-MKT-02/07);
- **系统参数 ↔ 业务行为**:参数变更按声明生效,不追溯已生成业务数据(订单成交价/运费/履约参数按下单时快照);参数与运营内容修改全程审计留痕(R-SYS-01、R-OPS-01,见 11-system-settings.md、12-operations-config.md);
- **套餐卡 ↔ 订单**:套餐卡核销与订单核销明细一致,幂等防重复核销;未核销/已核销张数与卡余一致(R-MKT-11,对齐 R-MKT-08);
- **积分 ↔ 订单(2026-10 新增)**:积分随已完成订单实付金额获取、随退款按比例回退,积分账户余额=Σ积分流水(R-MKT-13);
- **桶账 ↔ 押金记录/订单(2026-10 新增)**:在租押金桶数 = 押金「已收未退」记录数;欠桶数 = 应收未收回空桶数,与押金记录、空桶回收登记、订单一致(R-PRO-04、R-MON-03);
- **周期订购 ↔ 订单(2026-10 新增)**:计划与生成订单按「计划 id + 期次」一一对应,同期次幂等仅生成一单(R-ORD-13);
- **企业客户 ↔ 应收账款/发票(2026-10 新增)**:月结订单金额与账期账单应收一致,开票金额 ≤ 账单已结金额,退款触发红冲;信用额度「已用 + 本单 ≤ 上限」校验(R-ORD-14);
- **工资结算 ↔ 日报/订单(2026-10 新增)**:结算单计件/金额须与日报、已完成订单对账一致,差异挂起告警;同周期同人唯一 + 发放幂等,发放记录可核对(R-COL-05);
- **水票核销 ↔ 订单/日报(2026-10 新增)**:每张票全局唯一票号,核销记录(票号 × 时间 × 核销人 × 订单)唯一且不可重复;核销张数与订单抵扣、日报水票栏一致(R-MKT-08);
- **桶账 ↔ 押金对账导出(2026-10 新增)**:后台桶账台账与押金记录、空桶回收登记、订单一致,导出为只读快照且个人信息脱敏(R-PRO-05);

### AC-E2E-01 用户下单到完成主链路

| 项 | 内容 |
| ---- | ---- |
| Given | 用户已登录;商品在售且有库存;收货地址在配送范围内 |
| When | 提交订单 → 完成微信支付 → 管理员派单或送水工抢单(均进入「待配送」)→ 开始配送 → 完成配送(上传照片 + 选收款方式)→ 送达即完成 |
| Then | 订单状态严格按 `待支付→待派单→待配送→配送中→已完成` 单向流转、无回跳;`order_items` 落库;支付回调与主动查询双通道一致;库存正确扣减;营收在完成配送时按 `completed_at` 即时计入(2026-10 送达即完成,自提同为完成即计入),与统计口径一致 |

### AC-E2E-02 营销计价与日报结算一致性

| 项 | 内容 |
| ---- | ---- |
| Given | 营销域已配置商品分组专属价/优惠券/满减/水票;用户属某客户分组;送水工当日有已完成订单 |
| When | 用户下单并勾选用券或核销水票 → 送水工完成配送 → 提交当日收款日报(现金/水票张数/扫码三栏) |
| Then | 成交单价按 R-MKT-01 链路解析并按下单时快照留痕;优惠叠加封顶不超应付(R-MKT-02~10);被核销水票的桶收款方式计为「水票」并计入日报(R-COL-04);系统预计算与订单流水一致,差异按 R-COL-02 容差处理(超容差置「有争议」);对账状态按 R-COL-03 流转 |

### AC-E2E-03 轨迹上报与消息触达

| 项 | 内容 |
| ---- | ---- |
| Given | 送水工账号已登录独立 App;订单处于 `配送中`;后台账号具备 `PERMISSION_DELIVERY_WORKER_READ` |

### 附录 B 术语表

| 术语 | 定义 / 口径 |
| ---- | ---- |
| **送水工** | 履约侧角色(`AdminRoleModel.DELIVERY_WORKER`),使用送水工端独立 App。全库统一用词(2026-10-08 定稿);原「送水员」表述已按本表全局归一(2026-10-08),后台菜单/组件文案若仍为「送水员」需同步跟进 |
| 普通用户 | 用户端微信登录用户,走 `isAuthenticated()` + 本人数据隔离(R-AUTH-02),不授予后台权限码 |
| 熟客价 / 分组商品专属价 | 按客户分组配置的商品专属价(F-MKT-002),进 R-MKT-01 单价链第 ② 级 |

| 水票(桶水票 / 电子票) | 预购「桶数凭证」,一票抵一桶;被核销桶的收款方式计为「水票」(R-COL-04) |

| 日报 / 对账 | 送水工每日三栏(现金/水票张数/扫码)收款上报,与系统计算值比对;超容差进入「有争议」(R-COL-01~04) |
| 送达即完成 | 2026-10 按行业惯例取消「待确认收货」中间态:非自提订单送达、自提订单取水当场即进入「已完成」并即时计入营收(R-ORD-11) |
| 缺口(G-编号) | 未解决/部分实现项的登记项,**唯一归属本文件 §现状缺口与后续规划** |
| 储值余额 | **本项目不做**(2026-10-09 合规决策):属单用途预付卡资金类业务,需备案/资金存管资质,公司无资质,小程序上架与运营有合规风险;余额充值/余额支付/余额抵扣/组合支付均不实现,预收资金由水票与套餐卡(货物凭证)承接 |
| 套餐卡 / 次卡(2026-10 新增) | 预购的桶次/月卡/季卡,下单核销抵扣,未核销可退(R-MKT-11) |
| 会员等级 / 成长值(2026-10 新增) | 按累计消费/完成订单数划分的会员层级,决定权益(折扣率/免配送费/优先派单等)(R-MKT-12) |
| 积分(2026-10 新增) | 消费/活动获得的虚拟分,可兑换与抵扣,随订单完成获取、退款回退(R-MKT-13) |
| 一键复购 / 再来一单(2026-10 新增) | 以历史订单商品明细重建待下单数据、价格按当前链路重算的复购路径(R-ORD-12) |
