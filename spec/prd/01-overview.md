## 产品概述

### 背景

桶装水订购与配送是高频、刚需的本地生活服务。传统经营模式依赖电话、微信群人工接单,存在以下痛点:

- **用户侧**:下单流程繁琐、无法随时查看订单进度、支付不便;
- **配送侧**:送水工接单靠人工分配、配送过程无记录、收款与对账依赖纸质记账;
- **经营者侧**:订单、库存、营收、送水工业绩缺乏可视化管理,日报对账耗时且容易出错。

AquaRush 以微信小程序为载体,为小型桶装水门店提供"订购 → 配送 → 收款 → 对账"全链路数字化方案,面向单服务器、轻量化运营场景。

### 产品定位

微信生态内桶装水**订购 + 配送履约 + 运营管理**一体化系统,由三个端协同构成:

| 端             | 形态            | 定位     | 核心诉求                       |
| -------------- | --------------- | -------- | ------------------------------ |
| 用户端小程序   | Taro 微信小程序 | 订购入口 | 像点外卖一样方便地买水         |
| 送水工端独立 App | React Native + Expo(delivery-app) | 履约工具 | 接单、配送、收款一气呵成       |
| 管理后台       | Web(React)      | 运营中枢 | 订单、库存、对账、营收可视可控 |

### 业务闭环

业务主链路(跨三端):

```text
用户端:浏览商品 → 下单支付 → 等待配送 → 查看跟踪 → 送达即完成 → 评价
送水工端:接单/被派单 → 配送 → 拍照验证 → 收款 → 提交每日收款日报
管理后台:维护商品/地址 → 派单 → 核验配送照片 → 确认日报 → 对账审核 → 查看统计
```

### 当前阶段说明

系统主体框架与主要业务链路已建成并可用:商品展示与下单、微信支付与退款、派单与配送履约、拍照核验、日报与对账、统计看板、消息通知(订阅消息 + 三端消息中心 + WebSocket 实时推送)、营销玩法(分组价/优惠券/满减折扣/限时特价/水票/买赠/首单立减)、意见反馈闭环、配送轨迹上报与后台轨迹回放均已落地(2026-08~2026-09)。当前未关闭项集中在:**配送范围校验未启用、后台地址与商品的批量操作、日志筛选与错误提示、会员折扣、公告管理、系统设置接口补齐、用户端配送跟踪复用真实轨迹、APNs/FCM 远程推送凭证**等(逐项登记见 14-misc.md §现状缺口与后续规划),是后续迭代重点。2026-10 依据《送水小程序行业惯例功能对比与差异分析》补充 7 项行业惯例功能规划(一键复购、周期订购、配送范围与片区校验、用户端真实配送追踪、水桶账户与退押、套餐卡与会员等级积分(原「储值与套餐」,**用户储值 2026-10-09 决策不做**——无预付卡资质,小程序合规风险,见 10-marketing.md §1.1 合规决策),另含补水与续购提醒;仅在线客服 IM 未纳入),缺口登记 G75-G82,详各域文件。2026-10 续:依据同一差异分析的 **Top 8 之外剩余项**补充规划——企业客户下单(F-ORD-027,含批量下单/月结/开票)、送水工转单(F-ORD-028)、送水工地图导航(F-ORD-029)、订单导出(F-ORD-030)、商品导出与批量导入(F-PRO-011)、桶账台账与押金对账导出(F-PRO-012)、送水工工资结算(F-COL-012)、配送区域热力图/区域维度(F-ADR-022 扩充)、水票核销点位修订与票号唯一性/防重核销(R-MKT-08 修订),缺口登记 G83-G92(其中多门店 G90、在线客服 IM G92 为**本期不做**);公告管理现状校准为「用户端展示已具备、后台维护链路未闭环」(F-OPS-002/G62)。2026-10-10 产品决策:**周期订购(F-ORD-026/G77)与企业客户下单(F-ORD-027/G83)暂缓**。2026-10-11 依《送水(桶装水)小程序行业惯例功能调研报告 v2》(11 个具名来源)对齐:**周期订购/企业月结移入暂缓档**;**新安排实现 4 项**(接单超时预警 F-NTF-008、订单联系方式隐私保护/号码保护 F-ORD-032、起送门槛与距离阶梯运费 F-OPS-005 扩充/R-OPS-03、水票运营策略 R-MKT-08 修订,缺口 G94~G97,均 P2 排期待定);其余未规划项(含订单小票打印——本轮决策暂不实现)登记备查,详见 14-misc.md §未规划备查项。详各域文件。

## 产品目标与成功指标

### 产品目标

1. **打通全链路闭环**:实现"用户下单 → 在线支付 → 派单 → 配送 → 拍照验证 → 收款 → 日报对账"端到端可运营;
2. **订单数据真实化**:用户端订单列表、详情、配送跟踪全部对接真实业务数据,替代当前模拟数据;
3. **收款对账零差错**:通过系统预计算与人工填报的比对、差异申诉、管理员审核,将日报对账差异率降到最低;
4. **体验对标外卖平台**:下单流程 ≤ 3 步,订单进度全程可见,支付安全可靠。

### 分端目标

| 端       | 目标                                              |
| -------- | ------------------------------------------------- |
| 用户端   | 下单付得了款、订单看得见、进度追得到、送达有通知  |
| 送水工端 | 接单配送收款一气呵成,日报提交不费心,业绩一目了然  |
| 管理后台 | 商品/订单/派单/对账/统计全维可控,经营状况实时可见 |

### 成功指标(建议)

| 指标         | 说明                             | 目标值(建议)              |
| ------------ | -------------------------------- | ------------------------- |
| 日完成订单数 | 当日进入「已完成」状态的订单数   | 上线 3 个月后日均 ≥ 50 单 |
| 支付成功率   | 支付成功订单 / 发起的支付订单    | ≥ 95%                     |
| 对账差异率   | 存在差异的日报数 / 当日日报总数  | ≤ 5%                      |
| 订单履约时长 | 派单至「已完成」的平均耗时       | ≤ 4 小时                  |
| 库存准确率   | 盘点库存与系统库存一致率         | ≥ 99%                     |
| 用户留存     | 月内下单 ≥ 2 次的用户 / 活跃用户 | ≥ 30%                     |

### 角色层级关系

- **超级管理员 > 管理员**:超管可管理管理员账号(ADMIN_USER_*)与系统配置(SYSTEM_CONFIG_*),普通管理员不可;
- **管理员 > 送水工**:管理员创建/停用送水工账号,查看送水工订单与业绩,向送水工派单;
- **管理员 > 普通用户**:管理员可查看用户信息与订单,处理售后问题;
- 送水工与普通用户之间**无直接管理关系**,送水工仅在配送履约(接单后)看到用户配送信息。
