页面说明

所属端：用户端小程序（目标形态）

入口：我的页「我的资产 → 水桶账户」；退押申请流程为页内

跳转：提交退押申请 → 生成退押申请记录（待处理）；门店 / 送水工上门回收

口径：入口文案由「一次性购买塑料水桶」统一为「押金桶 / 水桶账户」（现状 barrel-shop / barrel-mine 语义不一致）

布局结构

  1. 顶部：.mp-status + 白底二级页 .mp-nav（带 .mp-nav__back + 微信胶囊）
  2. 桶账概览：.mp-statgrid（在租押金桶 / 欠桶数 / 押金合计，金额用 .weui-price--sm）
  3. 押金记录：.weui-cells__title + .weui-cells（规格 / 押金 .weui-price / 状态 .weui-tag--* / 时间 / 关联订单）
  4. 主操作：.weui-btn_area 内 .weui-btn_primary「申请退桶退押」
  5. 退押申请记录：.weui-cells（待处理 / 已回收 / 已退还 / 已驳回）
  6. 退押申请表单：.weui-mask + .weui-half（规格 + 退还桶数 .weui-stepper + 回收地址 + .weui-textarea 备注 + 提交）
  7. 空态：.weui-empty「暂无押金桶」，主操作禁用

关键交互与状态

  1. 进入页面加载桶账与押金记录（R-AUTH-02 仅本人）
  2. 「申请退桶退押」→ 半屏表单选规格与退还桶数（≤ 在租桶数）→ 提交 → 生成待处理申请
  3. 上门回收空桶并登记数量 → 状态「已回收」
  4. 后台确认退还 → 押金原路退回（记 DEPOSIT_REFUND，不计营收）→ 状态「已退还」，桶账与记录同步更新

空态：「暂无押金桶」（无在租）/「暂无押金记录」；加载态：列表 loading；错误态：提交 / 加载失败 toast。

禁用态：在租桶数为 0 时「申请退桶退押」用 .weui-btn_disabled 不可点。状态机：待处理 → 已回收 → 已退还 / 已驳回；退还以押金记录状态幂等防重复。

组件与度量

数据格：.mp-statgrid 三等分列，数值 .mp-statgrid__num 19px / 标签 12px 灰，列间 0.5px 竖发丝线；金额用 .weui-price--sm 15px 红。

列表：.weui-cells 主文字 17px / 行高 1.41 、内缩 16px、行间 0.5px 发丝线；纵向单元格 .weui-cell_vertical 用于「规格 + 状态 + 金额 + 时间」多行。

标签：押金状态 .weui-tag--green（已收取）/ --orange（待收取）/ --done（已退还）；申请状态 --assign（待处理）/ --deliver（已回收）/ --done（已退还）/ --cancel（已驳回）。

表单：.weui-label--req 必填红星；.weui-stepper 高 28px；.weui-textarea 最小高 96px / 白底内缩 16px + .weui-textarea__counter 右对齐计数。

弹层与按钮：.weui-mask + .weui-half（圆角 12px、max-height 78%）；按钮区 .weui-btn_area，主按钮 .weui-btn_primary 高 48px / 圆角 8px。

设计要点 / 禁忌

交互主色统一品牌蓝 --weui-BRAND；金额用微信电商红 #FA5151；危险用 --weui-RED；成功 / 配送中用 --weui-GREEN。本页不使用强调橙 --action。

R-MON-01：金额以分计、展示为元两位小数，统一走 .weui-price，不手拼 ¥。

R-AUTH-02：仅返回本人数据、他人数据不可见；退押不计入营收 / 退款统计（独立押金账本 DEPOSIT_REFUND）。

目标形态：用户端「水桶账户」页与「退押申请」入口未实现；缺口 G75；开放问题：退押损坏 / 缺失扣减规则、退押空桶上门方式。
