页面说明

所属端：用户端小程序（Taro）

入口：我的页 →「我的水票」

跳转：空态「去水票商城」→ ticket-mall；确认订单页（order-confirm）「水票抵扣」区读取可用张数

数据：票号（SP + YYYYMM + 8 位序号）、票种、规格限定、有效期、状态、关联订单（已核销）

布局结构

  1. 顶部汇总：可用张数 / 总张数 / 即将过期（.mp-statgrid）
  2. 状态 Tab：可用 / 已核销 / 已过期（.weui-tabs）
  3. 票夹卡（.weui-cells）：票名 + 规格限定 + 剩余张数 + 有效期 +「可退票」（.weui-tag--green）
  4. 票号明细：每张票独立展示票号（等宽字体 --font-num）+「长按复制」，用 .weui-cells 行
  5. 已核销票：使用记录（核销时间 / 核销订单 / 核销点位），用 .weui-cells 列表
  6. 空态：.weui-empty「暂无可用水票」+「去水票商城」

关键交互

  1. 长按票号可复制（线下核验对账）
  2. 可用票在确认订单页可选择核销张数（≤ 下单桶数 ∩ 可用张数）
  3. 已过期票置灰不可核销；已核销票可回溯使用记录
  4. 待激活票（复购激活票）不可核销，完成复购后自动激活（已实现 2026-10 G97，服务端派生展示态 pendingActivation）；单次核销上限票在下单侧限制单笔可勾选张数（已实现，preview 可用数按票种截断）
  5. 切换 Tab 过滤票状态

状态与规则

可用 / 已核销 / 已退回 / 已过期：四态并存（.weui-tag--green 可退 / .weui-tag--done 已核销）；空态：「暂无可用水票」；待激活（复购激活票，.weui-tag--orange，已实现 2026-10 G97）置灰展示并提示激活条件，可用张数统计剔除待激活。

票有效期：过期作废不可使用；即将过期（如 30 天内）以警示色提示。

退回规则：订单取消 / 退款 → 已核销未过期票退回票夹；已过期作废。

票号：唯一且可复制，格式 SP + YYYYMM + 8 位序号。

组件与度量

基准：微信官方 WeUI 2.x；票夹卡形态（票名、剩余张数）用品牌蓝 var(--brand)，「可退票」用语义绿 .weui-tag--green。

关键度量：导航 44px + 胶囊 87×32；.mp-statgrid__num 19px；.weui-cell 最小高 56px、0.5px 内缩 16px 发丝线；票号等宽字体 --font-num。

本页组件：.mp-nav / .mp-capsule、.mp-statgrid、.weui-tabs、.weui-cells、.weui-cell、.weui-tag（--green / --done）、.weui-empty。

设计要点 / 禁忌

水票用品牌蓝：票名、剩余张数、票号提示使用品牌蓝 var(--brand)，「可退票」用语义绿 .weui-tag--green，不使用强调橙。

票号唯一且需可复制便于线下核验，用等宽字体（--font-num）呈现；过期票置灰但可回溯。

「可退票」为合规 / 权益标识，需醒目但不用强调橙，避免与券品牌混淆。

金额统一用 .weui-price，禁止手拼「¥」字符串；非券元素一律不上强调橙。

待激活状态（缺口 G97，R-MKT-08 修订，已实现 2026-10）：须显著区别于可用票（置灰 opacity:.75 + 警示橙标签），避免用户误以为可核销；激活判定口径已裁决——当前已完成订单数 − 购票时基线 ≥ N 自动激活（见 PRD R-MKT-08 运营策略行）。
