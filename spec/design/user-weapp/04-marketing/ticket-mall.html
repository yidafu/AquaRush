页面说明

所属端：用户端小程序（Taro）

入口：首页 / 我的页「水票」入口 → 水票商城

跳转：购票成功 → 我的水票 ticket-mine；确认订单页「水票抵扣」区（order-confirm）读取可用张数

数据：票种名、类型、张数、购票价（分）、赠送张数、有效期、限购、已购张数

布局结构

  1. 顶部导航：「水票商城」（.mp-nav）+ 通兑 / 限规格说明条（.weui-notice--brand）
  2. 票种卡（.weui-cells）：票名 + 规格限定（.weui-tag--brand）+ 单张面值 + 套餐价（.weui-price--lg）+ 划线原价 +「买 10 送 1」（.weui-tag--red）+「立即购买」（.weui-btn_mini）
  3. 通兑 / 限规格说明、购票须知（.weui-cells__tips）
  4. 购买确认半屏（.weui-mask + .weui-half）：票种 / 规格 / 张数（.weui-stepper）+ 金额明细 + 微信支付 +「确认支付」

关键交互

  1. 选择张数（1~10，受限购约束）→ 点击「立即购买」→ 弹出购买确认半屏
  2. 确认 → 微信支付 → 支付成功逐张生成水票记录（唯一票号）→ 票包入账 → toast
  3. 停用票种不可购；超限提示「购票张数无效」；可核销不足提示「可核销水票不足」
  4. 半屏内可调整张数，金额明细实时联动

状态与规则

可购 / 限购达上限：达上限按钮置灰并提示「已达限购」；支付 loading：按钮转「支付中…」；票状态：可用 / 已核销 / 已退回 / 已过期。

规则：单次购票张数上限 10（GraphQL / 服务层双重约束）；「买 N 送 M」赠送张数随单入账。

R-MON-01：金额以分存储与计算，展示转元（两位小数）。

组件与度量

基准：微信官方 WeUI 2.x；票卡形态、规格标签、购买按钮用品牌蓝 var(--brand)。

关键度量：导航栏 44px + 胶囊 87×32；.mp-capsule 87×32；.weui-half 顶部圆角 12px、最大高 78%；.weui-btn_mini 高 28px；.weui-stepper 高 28px。

本页组件：.mp-nav / .mp-capsule、.weui-cells、.weui-tag--brand / --red、.weui-price--lg / --origin、.weui-btn_mini / .weui-btn_primary、.weui-notice--brand、.weui-mask + .weui-half、.weui-stepper、.weui-radio、.weui-media-box__thumb。

设计要点 / 禁忌

水票用品牌蓝：票卡形态、规格限定标签、购买按钮统一使用品牌蓝 var(--brand)，不使用强调橙（非券品牌元素，规避「强调橙仅限 CTA」红线）。

金额：套餐价与单张面值统一用 .weui-price（微信电商红），划线原价用 .weui-price--origin；禁止手拼「¥」字符串。

运营策略标识（缺口 G97，R-MKT-08 修订，规划中）：引流票「拉新专享」、复购激活票「需复购 1 单后可核销」须在购票前明示（防歧义）；画布内两处策略标签为目标形态。

套餐卡金额与「买 N 送 M」是决策关键，需突出；有效期与退款规则须明示（合规）；通兑票按规格限定，禁止跨容量套利。

票 / 商品图一律用 .weui-media-box__thumb 占位并标注「实拍图占位」，严禁卡通插画。
