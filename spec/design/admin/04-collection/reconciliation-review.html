页面说明

所属端：管理后台（React + Ant Design 5）

入口：左侧菜单「收银对账」→ 对账记录 Tab

跳转：「审核」打开审核抽屉；「查看详情」展示对账详情

权限：PERMISSION_COLLECTION_READ / PERMISSION_COLLECTION_REVIEW

布局结构

  1. 日期 +「手动执行对账」按钮
  2. 汇总卡：系统预计算合计 / 实际填报合计 / 差异合计 / 差异率
  3. 差异明细表格：送水工 / 系统预计算 / 实际填报 / 差异 / 差异率 / 状态 / 操作
  4. 差异申诉流转说明（R-COL-03）
  5. 第二状态：审核抽屉（逐单比对 + 差异原因 + 申诉记录 + 审核意见 + 审核通过 / 驳回）

关键交互

  1. 「手动执行对账」→ 二次确认「确定要执行对账吗?重复执行会更新已有数据」→ 执行并刷新
  2. 点「审核」→ 打开抽屉，查看逐单比对与配送员申诉
  3. 填写审核意见 →「审核通过」置「已复核」展示复核时间 / 备注
  4. 「驳回」退回配送员重新提交；每日 03:00 调度器自动对昨日执行对账

状态与规则

状态标签：待对账 / 匹配 / 有差异 / 已复核。

差异着色：|差异| ≤ 1 元绿、否则红。

空态：无对账记录表格为空；加载态：Table loading + 按钮 loading；错误态：对账执行失败 message；禁用态：已复核记录不显示复核入口。

重新执行对账会重算结果并清除复核痕迹，需在交互中提示。

设计要点 / 禁忌

管理端不出现强调橙：主操作用品牌蓝，驳回用 error 色，差异用语义红 / 绿。

差异比对须显式（系统计算 vs 日报填报口径）；已复核记录须隐藏复核入口防二次审核；复核备注为追溯依据。

差异基数 = 填报（现金 + 扫码）vs 系统计算（现金 + 扫码），水票订单金额不计入（2026-08-24 口径修正）。
