  • 状态机：可用 → 已核销 / 已退回 / 已过期，单向流转

桶水票 · 规则说明

电子票核销 / 退票 / 票号唯一性
核销点位（下单侧预扣 vs 送达侧扫码）
  • 下单侧预扣：确认订单页选核销张数（≤ 下单桶数 ∩ 可用张数），下单即预扣对应张数
  • 送达侧扫码：送水工送达扫码核销，预扣转正式核销（幂等，不二次扣减）
  • 订单取消 / 退款：已核销未过期票退回票夹；过期作废
票状态机
可用（未使用） 已核销 已退回 已过期

票种状态：上架 / 停用；停用票种不可购。

票号唯一性与防重核销机制
票号规则
SP + YYYYMM + 8 位序号
生成方式
购票 1~10 张逐张生成记录
唯一约束
票号入库唯一，不可重复
核销幂等
同票号重复请求返回既有结果
非法核销
可用水票不足时提示「可核销水票不足」
票种效验
票种无效 / 购票张数无效 拦截

页面说明

所属端：管理后台（React + Ant Design 5）

入口：营销管理 → 桶水票

跳转：行「详情」→ 票种销售 / 使用统计详情页（F-MKT-007 详情）；用户详情「水票」Tab（F-USR-022）

组件：Table、Modal、Form、InputNumber、Select、DatePicker、Stepper

布局结构

  1. 顶部：「新建票种」按钮
  2. 票种列表：票种名 / 类型 / 适用规格 / 面值 / 套餐 / 售价 / 划线价 / 买 N 送 M / 有效期 / 限购 / 已售 / 状态 / 操作
  3. 新建 / 编辑弹窗表单（逐字段，见状态二）
  4. 规则说明：可退票规则与核销点位（下单侧预扣 vs 送达侧扫码）
  5. 票号唯一性与防重核销机制说明

关键交互

  1. 配置票种 → 上架 → 用户端水票商城可见
  2. 用户购票（1~10 张）→ 逐张生成水票记录（唯一票号 SP+YYYYMM+8 位序号）→ 票包入账
  3. 确认订单选核销张数（≤ 下单桶数 ∩ 可用张数）
  4. 订单取消 / 退款 → 已核销未过期票退回票夹；过期作废

状态与规则

票种：上架 .tag-ok / 停用 .tag-neutral；票状态：可用 / 已核销 / 已退回 / 已过期（待激活——复购激活票，目标形态）。

校验：「票种无效」「购票张数无效」「可核销水票不足」；单次购票上限 10 张（双重约束）。

退票：未核销且未过期的票可退；已消费不可退。

设计要点 / 禁忌

电子票与实体票区分（本功能仅电子票）；通兑票按规格限定，禁止跨容量套利。

管理端不出现强调橙：票种视觉标识用品牌蓝 / 中性色，票号用等宽字体便于线下核验。

缺口 G58 已解决；实体票（线下纸票）不在范围。

水票运营策略（缺口 G97，R-MKT-08 修订，2026-10-11 依调研报告 v2 B1/S4 立项，排期待定）：引流票 / 复购激活票 / 单次核销上限三形态为票种级可配开关、默认不启用；复购激活票生成「待激活」票状态，完成复购自动激活。
