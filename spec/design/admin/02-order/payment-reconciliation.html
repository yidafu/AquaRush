页面说明

所属端：管理后台（React + Ant Design 5）

入口：左侧菜单「支付管理」→ 支付对账（与退款管理同级；2026-10 新增导航分组）

跳转：任务行「详情」→ 详情弹窗；差异行「处理」→ 处置弹窗（解决 / 忽略 + 备注必填）

权限：PAYMENT_RECONCILIATION_READ（可见任务列表）/ PAYMENT_RECONCILIATION_EXECUTE（重跑 / 处置；无权限时入口不可见，R-AUTH-04）

状态：规划中（缺口 G93；支付 / 退款链路已实现 R-PAY-01/02，微信侧账单核对为目标形态）

布局结构

  1. 页面标题 +「手动对账」按钮（限 T-1~T-30，窗口外提示「仅支持近 30 天账单」）
  2. 筛选区：账单类型（支付 / 退款）+ 账单日范围 + 任务状态
  3. 任务列表：账单日 / 类型 / 状态 / 微信总笔数 / 微信总金额 / 本地总金额 / 差异数 / 执行时间 / 操作（详情、重跑）
  4. 对账口径说明卡（R-PAY-04：四类差异 + 与日报对账相互独立）
  5. 第二状态：详情弹窗（三方校验汇总卡：微信账单汇总 / 逐笔解析合计 / 本地合计 + 差异列表）→ 差异行「处理」弹窗（解决 / 忽略 + 备注必填）

关键交互

  1. 每日凌晨调度自动执行支付对账（02:00）与退款对账（02:05），任务列表呈现结果
  2. 点任务行「详情」→ 下钻报表汇总与差异明细（三方校验）
  3. 差异逐条处置：解决 = 已核实无资金损失或已修复；忽略 = 确认为跨日边界等可解释差异；均须备注（「请填写处理说明」）
  4. 「重跑」同账单日任务 → 确认「重跑将重算该日对账结果，已处理的差异记录保留，确认继续？」→ 幂等重算（已处置差异保留留痕，未处置差异重算）
  5. 执行与处置均记业务日志（操作人 / 任务 / 差异）

状态与规则

任务状态：成功 / 失败（展示失败原因 + 重跑入口）/ 执行中；差异处理状态：未处置 / 已解决 / 已忽略。

关键口径：差异数 > 0 的任务状态仍为「成功」（对账完成 ≠ 无差异），差异数用语义红强调；差异保持未处置且持续可见，不自动闭环。

空态：「暂无对账记录」；加载态：表格 loading；错误态：任务失败展示失败原因并提供重跑；禁用态：无 EXECUTE 权限时重跑 / 处置入口不可见。

四类差异：短款（微信有本地无）/ 长款（本地有微信无）/ 金额不一致 / 状态不一致（如退款账单已退成功但本地退款单未完结）。

设计要点 / 禁忌

管理端不出现强调橙：主操作品牌蓝，差异金额 / 差异数用语义红，重跑为敏感动作加二次确认。

资金安全底线：漏单与金额不一致必须显式暴露，不允许静默吞掉；差异自动修复（自动补单 / 自动改状态）不做，一律人工处置留痕。

金额一律分存储、展示两位小数（R-MON-01）；与送水工收款日报对账（F-COL-011，内部收款口径）相互独立，本页为与微信渠道的账实核对。

资金账单（手续费 / 净额）与结算账单对账为后续增强（开放决策见 spec/tech/design/07-payment-reconciliation.md）。
