页面说明

所属端：管理后台（React + Ant Design 5）

入口：系统设置 → 数据维护；路由 system-config/data；仅超级管理员可见

数据来源：单查询 dataMaintenanceOverview 加载保留策略 + 三类日志分区 + 备份记录分页

状态：已实现

布局结构

  1. 日志保留策略：三类日志保留天数 + 自动备份开关 + 保存 / 重置
  2. 日志分区管理：Tabs（API 日志 / 用户操作日志 / 业务日志）+ 汇总表（表名 / 分区数 / 最老分区 / 占用空间）+ 分区明细表
  3. 离线备份记录表：时间 / 日志表 / 分区 / 冷表名 / 行数 / 文件 / 大小 / 状态 / 操作人 / 详情
  4. 手动触发备份按钮（危险操作 + 二次确认）

关键交互

  1. 进入页面 → 单请求加载保留策略 + 三类日志分区 + 备份记录分页
  2. 修改保留天数 / 开关 → 保存（审计留痕）→ 超期判定按新策略生效
  3. 点某历史超期分区「离线备份」→ 二次确认 → 转储冷表 + 导出文件 → 分区从热表移除 → 备份记录追加
  4. 每日 03:30 与启动时自动备份超期分区（开关关闭跳过；单分区失败记 FAILED 并继续其余）

状态与规则

空态：分区列表空时提示「日志表尚未按月分区」；备份记录空态。加载态：总览 / 保存 / 备份 loading。错误态：备份失败 toast + 备份记录 FAILED（数据仍在热表，未丢失）。禁用态：无 SYSTEM_CONFIG_WRITE 权限时只读；当前月 / DEFAULT / 未超期 / 已备份分区不可备份（Tooltip 说明原因）。

分区状态 Tag：默认分区 / 当前月 / 已超期 / 未超期。备份状态 Tag：成功 / 失败 / 进行中。

校验：「保留天数无效」（1-3650 整数）。

设计要点 / 禁忌

管理端不出现强调橙：手动备份为危险操作，用语义 error 色（.btn.danger），并二次确认。

保留天数 1-3650 整数，0 或负数拦截。备份语义 =「转储冷表 + 导出 gzip CSV（带 SHA-256）」，两步均成功后删除热表分区，不做在线删除。

已备份月份数据不再在线查询到（仅冷表 / 备份文件可见），须提示。自动备份受 log_cleanup_enabled 控制，关闭后仅跳过自动、不阻断手动。

缺口 G64：冷表保留 / 清理策略、备份文件在线下载与异地传输（建议保持运维侧）、按年份冷表分区化。恢复为运维侧操作（不在 UI 提供）。「备份文件在线下载」按钮现状为禁用占位。
