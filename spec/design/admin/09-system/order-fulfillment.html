页面说明

所属端：管理后台（React + Ant Design 5）

入口：系统设置 → 订单与履约参数；路由 system-config/order；仅超级管理员可见

下游消费：用户端确认订单页经 client deliverySlots 查询按配置渲染时段选项（已实现 2026-09）；订单详情时段文案按配置渲染（失败回退兜底文案）

状态：部分实现

布局结构

  1. 支付参数分组：支付超时
  2. 配送时段分组：立即配送（恒启用）+ 上午 / 下午 / 晚上三行（时间窗 + 启用开关 + 展示文案）
  3. 派单与确认分组：自动派单开关、派单超时提醒
  4. 配送范围与免运费楼层分组（目标形态）：最大配送距离、免运费楼层（默认 4 层）
  5. 保存按钮（二次确认）+ 修改记录表

关键交互

  1. 进入页面 → 回显当前参数
  2. 修改 → 确认保存 → 按声明热生效
  3. 用户端确认订单页配送时段选项按新配置渲染（F-ORD-001）
  4. 支付超时任务按新参数执行（R-ORD-04 接通后）
  5. 停用当前已选时段 → 用户端自动回退「立即配送」

状态与规则

空态：未配置时按默认值展示；加载态：回显 / 保存 loading；错误态：保存失败 toast；禁用态：无权限只读；时段启停：Switch 开 / 关。

校验：「参数无效」「时间窗不合法」；超时 / 时限必须 > 0；时间窗开始必须早于结束。

快照规则：时段修改只影响新订单，已生成订单按下单时快照，不追溯（R-ORD-04 / R-MON-02 同口径）。

设计要点 / 禁忌

管理端不出现强调橙：主操作用品牌蓝，「确定保存」二次确认文案须明示对已生成订单无影响。

立即配送恒启用，不可停用（无 Switch 或 Switch 置灰锁定）；上午 / 下午 / 晚上可各自启停。

「自动确认收货」参数已废弃（2026-10）：随「送达即完成」（R-ORD-11）取消「待确认收货」态与参数 auto_confirm_receipt_days，不得再出现在表单中。

缺口 G64：其余履约参数后台可配、前端与服务端统一消费（支付超时自动取消消费链路未接通）。开放问题：时段是否区分工作日 / 周末、每时段是否限量派单。
