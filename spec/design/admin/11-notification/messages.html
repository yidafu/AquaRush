页面说明

所属端：管理后台（React + Ant Design 5）

入口：通知与消息 → 消息列表；路由 notifications/messages

权限：NOTIFICATION_READ（管理员 / 超管）；失败重发 NOTIFICATION_WRITE（仅超管）

状态：已实现（缺口 G68 已解决）

布局结构

  1. 筛选区：渠道（订阅消息 / 站内 / WebSocket 推送）、模板、接收人、发送状态、已读状态、幂等键、时间范围（默认近 30 天）
  2. 消息表格：发送时间 / 渠道 / 模板名 / 接收人 / 摘要（省略）/ 状态 / 操作「查看详情」「失败重发」
  3. 消息详情抽屉：标题 / 类型 / 通道 / 接收人 / 关联单号 / 发送时间 / 已读时间 + channel_status + 失败原因 + 微信消息 ID + 模板参数 JSON + 幂等键
  4. 失败重发二次确认弹窗 + 分页

关键交互

  1. 进入页面 → 默认近 30 天全部消息（分页 10 / 页）
  2. 组合筛选 → 表格刷新
  3. 点「查看详情」→ 抽屉展示全文与状态；失败消息可点「失败重发」（复用 R-NTF-01 全部门控）
  4. 关联单号可点击跳订单详情（目标形态）

状态与规则

状态标签：发送成功 / 发送失败 / 已重发；已读 / 未读；渠道 订阅消息 / 站内 / WebSocket 推送。

channel_status：待发送 / 已发送 / 发送失败（FAILED/PENDING 的用户消息可重发）。

关键数据字段：时间、类型、标题、摘要、接收人、关联单号、状态、已读时间、channel_status、模板场景 / 页面 / 字段、幂等键。

设计要点 / 禁忌

管理端不出现强调橙：主操作用品牌蓝，失败重发为敏感动作，用语义 error 色 + 二次确认。

重发仅重试微信订阅消息通道（站内消息不重推）；无 NOTIFICATION_READ 不可进入。

消息与轮询按幂等键去重，不重复渲染；接收人默认脱敏展示。

缺口 G68 已解决；关联单号点击跳订单详情为目标形态。
