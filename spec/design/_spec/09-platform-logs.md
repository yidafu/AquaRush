# 09 平台与日志域 页面规格

> 来源：`spec/prd/09-platform-logs.md`（F-LOG-001~003，全部 [已实现]），仅管理后台端。
> 权限范围：管理员登录后经左侧「日志管理」子菜单进入；业务日志经 GraphQL `businessLogs`（admin 角色，`PERMISSION_LOG_READ`）。
> 三类日志数据源：API 日志 / 用户操作日志经前端 REST 查询（`/logs/api`、`/logs/user-actions`）；业务日志经 GraphQL `businessLogs`（REST `/logs/business` 控制器保留）。
> 通用缺口：三页请求失败目前仅 `console.error`，**无前端用户提示**（登记缺口 G74）；查询期间「搜索/重置」无显式禁用（现状）。
> 表结构背景：三张日志表（api_logs / user_action_logs / business_logs）按月 RANGE 分区，超期分区经「系统设置-数据维护」离线备份后不再在线查询（见 F-SYS-006）。

## 页面 1：管理后台 · API 日志（建议文件名 api-logs.html）
- 功能编号：F-LOG-001 [已实现]
- 所属端：管理后台
- 页面入口与跳转：左侧导航「日志管理」→「API日志」；路由 `/logs/api`；行内「详情」弹出弹窗（不跳页）
- 布局结构（从上到下）：
  1. 筛选区（Card）：请求类型 / 请求方法 / 用户 ID / 时间范围 + 搜索 / 重置
  2. 日志表格（Table，横向滚动 x=1200）
  3. 分页（默认 20/页）
  4. 详情弹窗（Modal「请求详情」）
- 组件清单：
  - 筛选：Card、Space、Select（请求类型、请求方法）、Input（用户 ID）、DatePicker.RangePicker（含时间）、Button（搜索 / 重置）；均 allowClear
  - 表格：Table、Tag（类型 / 状态）
  - 弹窗：Modal、Descriptions（两列）、JsonViewer（请求体：格式化 / 可折叠 / 可复制）
- 关键交互：
  1. 进入页面 → 按默认第 1 页/20 条请求 `/logs/api` → 渲染列表与总数。
  2. 设置任一筛选条件（可组合）→ 点击「搜索」→ 回到第 1 页重新请求。
  3. 点击「重置」→ 清空全部筛选并回到第 1 页重新加载。
  4. 点击某行「详情」→ 打开弹窗展示该条完整请求信息。
  5. 翻页 / 切换每页条数 → 按新分页参数重新请求。
- 状态与标签：
  - 空态：无匹配记录 → antd 默认空态
  - 加载态：请求期间 Table 置 loading（转圈）并复用旧数据
  - 错误态：请求失败仅 `console.error`，无前端用户提示（缺口 G74）
  - 禁用态：请求期间「搜索/重置」无显式禁用（现状）
  - 状态着色：2xx 绿 Tag / 4xx 橙 Tag / 5xx 红 Tag / 其余 default
  - 类型 Tag：HTTP 蓝 / GraphQL 紫
- 关键数据字段：
  - 列表列：时间（本地化 zh-CN）、类型、方法、状态（responseStatus）、URI、耗时（durationMs）、用户（用户名或 ID）、IP、操作
  - 详情字段：请求类型 / 方法 / URI / Query / 状态码 / 耗时 / 用户ID / 用户名 / IP / UserAgent / 关联ID / 操作类型 / 操作名称 / 请求体 / 错误信息 / 时间
- 表格列名（逐列）：时间 | 类型 | 方法 | 状态 | URI | 耗时 | 用户 | IP | 操作（「详情」）
- 筛选条件：请求类型（HTTP/GraphQL）、请求方法（GET/POST/PUT/DELETE）、用户 ID（Input）、时间范围（RangePicker，含时间）；均可选、无必填与格式校验，时间范围缺省不限。
  - 备注：状态筛选维度后端查询参数层已定义 `responseStatus`，但页面筛选区未暴露（开放问题）；如需「按 4xx/5xx 快速定位异常接口」，标**目标形态**补状态筛选下拉。
- 图表规格：本页无图表（纯表格 + 弹窗）。
  - 导出按钮：无（如需导出为**目标形态**）。
- 页面文案：
  - 弹窗标题「请求详情」；按钮「搜索」「重置」「详情」
  - 分页页脚「共 N 条记录」；耗时列无值显示「-」
  - Tag 文案：类型「HTTP」「GraphQL」；状态按码段着色
- 设计要点/禁忌：
  - 状态码着色严格 2xx 绿 / 4xx 橙 / 5xx 红，避免与类型 Tag 配色混淆（类型用蓝/紫）。
  - URI / 请求体超长须省略或滚动 + 复制，禁止撑破布局。
  - 时间以服务端时间为准，前端仅做本地化展示（zh-CN），**不换算时区**。
  - 错误信息红色、可滚动且可复制；敏感字段脱敏（配合 R-SYS-02）。
- 备注：目标形态——状态筛选（4xx/5xx 快速定位）、错误态前端提示、查询期间按钮禁用、导出。缺口 G74 为本域错误态缺陷。疑似 UI 口径差异见 PRD §4 开放问题（不占用 G 编号）。

## 页面 2：管理后台 · 用户操作日志（建议文件名 user-action-logs.html）
- 功能编号：F-LOG-002 [已实现]
- 所属端：管理后台
- 页面入口与跳转：左侧导航「日志管理」→「用户操作」；路由 `/logs/user-actions`；行内「详情」弹出弹窗
- 布局结构（从上到下）：
  1. 筛选区（Card）：操作类型 / 用户 ID / 用户名 / 目标 / 时间范围 + 搜索 / 重置
  2. 操作表格（Table）
  3. 分页（默认 20/页）
  4. 详情弹窗（Modal「操作详情」）
- 组件清单：
  - 筛选：Card、Space、Select（操作类型）、Input（用户 ID、用户名、目标）、DatePicker.RangePicker（含时间）、Button（搜索 / 重置）
  - 表格：Table、Tag（操作类型）
  - 弹窗：Modal、Descriptions（两列）、JsonViewer（附加属性：格式化 / 可折叠 / 语法着色 / 可复制）
- 关键交互：
  1. 进入页面 → 按默认第 1 页/20 条请求 `/logs/user-actions` → 渲染列表与总数。
  2. 选择操作类型 / 输入用户 ID、用户名 / 选择时间范围（可组合）→ 点击「搜索」→ 回到第 1 页重新请求。
  3. 点击「重置」→ 清空全部筛选并回到第 1 页。
  4. 点击某行「详情」→ 弹窗展示该条操作的元素级信息与附加属性。
  5. 翻页 / 切换每页条数 → 按新分页重新请求。
- 状态与标签：
  - 空态：无匹配记录 → antd 默认空态
  - 加载态：请求期间 Table 置 loading
  - 错误态：请求失败仅 `console.error`，无前端用户提示（缺口 G74）
  - 禁用态：请求期间「搜索/重置」无显式禁用（现状）
  - 操作类型 Tag 色：页面浏览 蓝 / 点击 绿 / 表单提交 橙 / 搜索 紫 / 分享 青 / 滚动 品红 / 文件操作 红；未命中枚举显示原值 + default 色
- 关键数据字段：
  - 列表列：时间（zh-CN）、操作类型、用户（用户名或 ID）、页面（pageUrl）、目标（target）、元素 ID（elementId）、IP、操作
  - 详情字段：操作类型 / 用户ID / 用户名 / IP / 页面URL / 目标 / 元素ID / 元素类型 / 元素文本 / UserAgent / 附加属性（properties）/ 时间
- 表格列名（逐列）：时间 | 操作类型 | 用户 | 页面 | 目标 | 元素 ID | IP | 操作（「详情」）
- 筛选条件：操作类型（Select：页面浏览 / 点击 / 表单提交 / 搜索 / 分享 / 滚动 / 文件操作，另含用户登录 / 登出、系统配置保存 / 恢复等后端自定义类型）、用户 ID（Input）、用户名（Input）、目标（Input，匹配 target 列）、时间范围（RangePicker，含时间）；均可选、无必填校验，时间范围缺省不限。
  - 说明：上报侧枚举以**前端行为维度**为主（PAGE_VIEW / CLICK / FORM_SUBMIT / SEARCH / SHARE / SCROLL / FILE_OPERATION）；需求所列业务操作（登录/下单/取消/支付/地址变更）与当前枚举口径存在差异（PRD §4 开放问题）。对齐「业务操作维度筛选」标**目标形态**（新增业务操作类型 / 或引入枚举映射）。
- 图表规格：本页无图表（纯表格 + 弹窗）。
  - 导出按钮：无（如需导出为**目标形态**）。
  - 注：本页**不提供**用户时间线视图；时间线视图仅在 F-LOG-003 业务日志页（见页面 3）。
- 页面文案：
  - 弹窗标题「操作详情」；按钮「搜索」「重置」「详情」
  - 分页页脚「共 N 条记录」；用户列无值显示「-」
  - 操作类型文案：页面浏览 / 点击 / 表单提交 / 搜索 / 分享 / 滚动 / 文件操作
- 设计要点/禁忌：
  - 操作类型 Tag 配色须稳定映射（见上），新增后端自定义类型走 default 色并显示原值。
  - 页面 URL / 目标 / UserAgent 超长须省略或滚动 + 复制。
  - 追溯三要素「操作人 + 时间 + 对象（target/页面URL/元素ID）」须完整可读。
  - 附加属性（properties）格式化 JSON 展示，敏感键被后端剔除后落库。
  - 时间以服务端时间为准，前端仅本地化，不做时区换算。
- 备注：目标形态——业务操作维度筛选（枚举映射）、错误态前端提示、查询期间按钮禁用、导出。缺口 G74 为错误态缺陷。跨端上报 SDK：`@aquarush/common/tracking`（小程序 / 管理后台 PC / 配送 RN 三端已接入）。分页字段问题见 PRD §4 开放问题（不占用 G 编号）。

## 页面 3：管理后台 · 业务日志（建议文件名 business-logs.html）
- 功能编号：F-LOG-003 [已实现]
- 所属端：管理后台
- 页面入口与跳转：左侧导航「日志管理」→「业务日志」；路由 `/logs/business`；行内「详情」弹出弹窗
  - 注：业务操作记录仅在日志管理页查看，用户详情页不提供操作记录。
- 布局结构（从上到下）：
  1. 筛选区（Card）：业务域 / 操作类型 / 日志级别 / 用户 ID / 时间范围 + 搜索 / 重置
  2. 视图切换：Segmented「表格 / 时间线」
  3. 视图区：业务日志表格（Table）或 时间线（Timeline）
  4. 分页（表格 20/页，时间线 10/页）
  5. 详情弹窗（Modal「日志详情」）
- 组件清单：
  - 筛选：Card、Space、Select（业务域、操作类型、日志级别）、Input（用户 ID）、DatePicker.RangePicker（含时间）、Button（搜索 / 重置）
  - 切换：Segmented（「表格 / 时间线」）
  - 表格：Table、Tag（级别）、Pagination
  - 时间线：AntD Timeline（mode="left"，`BusinessLogTimeline` 组件，含域→操作类型映射 `DOMAIN_OPERATIONS` 与操作文案映射 `OPERATION_CONFIG`）
  - 弹窗：Modal、Descriptions（两列）、JsonViewer（消息可解析时格式化）、pre（堆栈跟踪）、Empty（时间线空态）
- 关键交互：
  1. 进入页面 → 经 GraphQL `businessLogs` 按默认第 1 页/20 条请求 → 渲染列表与总数。
  2. 选择业务域 → 操作类型下拉联动为该域类型（未选域展示全部）；再选操作类型 / 日志级别 / 输入用户 ID / 选择时间范围（可组合）→ 点击「搜索」→ 回到第 1 页重新请求。
  3. 点击「重置」→ 清空全部筛选并回到第 1 页。
  4. 点击某行「详情」→ 弹窗展示消息全文与堆栈跟踪。
  5. 切换「时间线」视图 → 以时间线展示当前筛选结果（恒 createdAt 倒序）；按用户 ID 筛选后即以该用户为视角查看其全部业务操作轨迹。
  6. 翻页 / 切换每页条数 → 按新分页参数重新请求。
- 状态与标签：
  - 空态：表格 antd 默认空态；时间线视图 Empty「暂无操作记录」
  - 加载态：请求期间 Table/Timeline 置 loading（转圈）并复用旧数据
  - 错误态：请求失败仅 `console.error`，无前端用户提示（缺口 G74）
  - 禁用态：请求期间「搜索/重置」无显式禁用（现状）
  - 级别 Tag 色：TRACE default / DEBUG 绿 / INFO 蓝 / WARN 橙 / ERROR 红
  - 时间线条目：操作类型（图标 + 色 + 中文文案）、级别 Tag、用户 Tag、消息、关联ID、本地化时间
- 关键数据字段：
  - 列表列：时间（zh-CN）、级别、操作类型、Logger（loggerName）、消息、用户（用户名或 ID）、关联ID（correlationId）、操作
  - 时间线条目：操作类型、级别、用户、消息、correlationId、时间（倒序）
  - 详情字段：日志级别（Tag）/ 时间 / Logger / 关联ID / 用户ID / 用户名 / 消息 / 堆栈跟踪
- 表格列名（逐列）：时间 | 级别 | 操作类型 | Logger | 消息 | 用户 | 关联ID | 操作（「详情」）
- 筛选条件：业务域（订单 / 支付 / 配送 / 用户 / 认证，映射自后端 loggerName）、操作类型（与业务域联动，登录 / 提交订单 / 查看产品等，未选域展示全部）、日志级别（TRACE / DEBUG / INFO / WARN / ERROR）、用户 ID（Input）、时间范围（RangePicker，含时间）；均可选、无必填校验，时间范围缺省不限。
  - 时间范围提交格式：`YYYY-MM-DDTHH:mm:ss`（本地时间，弃用 `.toISOString()` 的 UTC 偏移，关联 G40）。
  - **时间线切换开关**：Segmented「表格 / 时间线」——切换保留筛选，分页回第 1 页并按视图调整每页条数（表格 20 / 时间线 10）；时间线恒 createdAt 倒序。
- 图表规格：本页无图表（表格 / 时间线 + 弹窗）。
  - 导览：时间线视图（AntD Timeline，mode="left"）即「用户业务操作轨迹」可视化；按用户 ID 筛选后以该用户为视角。
  - 导出按钮：无（如需导出为**目标形态**）。
- 页面文案：
  - 弹窗标题「日志详情」；视图切换「表格」「时间线」；按钮「搜索」「重置」「详情」
  - 时间线空态「暂无操作记录」；分页页脚「共 N 条记录」
  - 级别文案：TRACE / DEBUG / INFO / WARN / ERROR
  - 业务域文案：订单 / 支付 / 配送 / 用户 / 认证
- 设计要点/禁忌：
  - 表格与时间线两视图须共用同一筛选状态，切换时保留筛选、分页回第 1 页。
  - 操作类型中文文案：老数据（operation 列为 NULL）前端回退解析 message 前缀 `Operation: X`；不可显示为空。
  - 消息以 `{` / `[` 开头且可解析时用 JsonViewer 格式化，否则保留原文 pre；堆栈跟踪 pre、可滚动、可复制。
  - 关联ID（correlationId）用于与订单操作时间线 / 请求链对齐，须完整展示（可省略但可悬停/复制）。
  - 统计时间聚合之外，本页时间不做时区换算。
- 备注：目标形态——错误态前端提示、查询期间按钮禁用、导出。缺口 G43 已解决（时间线视图与业务域 / 操作类型筛选）；G40 在 F-LOG-003 侧消除（分页字段 + 时间格式），用户操作日志侧保留。业务域枚举：ORDER / PAYMENT / DELIVERY / USER / AUTH / PRODUCT / MARKETING / OPS / RECONCILIATION。
