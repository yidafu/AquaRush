# 05 地址与配送域 页面规格

> 来源：`spec/prd/05-address-delivery.md`（F-ADR-001~003、010~013、020~022；R-ADR-01~04）。
> 说明：F-ADR-011 订阅消息通知已归口通知与消息域（13-notification.md §F-NTF-001），本域页面仅保留配送场景的订阅授权入口，标注「目标形态」。

## 页面 1：用户端 · 地址列表（建议文件名 address-list.html）
- 功能编号：F-ADR-001 [已实现]
- 所属端：用户端小程序
- 页面入口与跳转：入口「我的」页「地址管理」；选择模式由确认订单页地址卡 navigateTo `address-list?select=true`；编辑跳 `address-edit?id=xx`；导入微信地址后跳 `address-edit?fromWechat=true`；选择模式点击「选择此地址」后 navigateBack 回确认订单页回填。
- 布局结构（从上到下）：
  1. 顶部搜索栏一行（左侧放大镜图标 + 输入框，placeholder「搜索手机号或地址」）。
  2. 搜索栏下方右侧或整行「导入微信地址」次级小按钮。
  3. 地址卡片列表（每张卡：左上「默认」标签（仅默认地址显示）+ 收货人姓名 + 手机号；卡身完整地址一行/两行；卡右下操作区：默认地址 / 编辑 / 删除；编辑态：选择模式时卡片整体可点，附带「选择此地址」操作）。
  4. 页面底部悬浮/吸底「新增收货地址」主按钮（全宽主色）。
  5. 删除确认弹窗（覆盖层居中）。
  6. 轻提示 Toast（顶部或居中）。
- 组件清单：AtSearchBar（搜索栏）；AtButton（secondary small「导入微信地址」；主按钮「新增收货地址」）；AddressCard 地址卡片（默认标签 AtTag、联系人、电话、完整地址、操作区）；AtModal 删除确认弹窗；AtToast 各提示；AtIcon（搜索/编辑/删除图标）。
- 关键交互：
  1. useDidShow 拉取地址列表（从编辑页返回自动刷新），支持下拉刷新。
  2. 选择模式（select=true）：点卡片「选择此地址」→ 写入本地 `selectedAddress` 缓存 → navigateBack 回确认订单页回填。
  3. 非选择模式：点卡片主体不触发选择，仅展示默认地址/编辑/删除操作。
  4. 点击「编辑」→ 跳转 `address-edit?id=xx`。
  5. 点击「删除」→ 弹「确认删除」→ 确认后调 deleteAddress → Toast 并从列表移除该卡。
  6. 点击「默认地址」→ 调 setDefaultAddress → 本地即时更新默认标识（R-ADR-01）。
  7. 搜索：按手机号 / 收货人姓名 / 完整地址本地过滤，清空恢复全部。
  8. 点击「导入微信地址」→ Taro.chooseAddress 授权后预填充跳转 `address-edit?fromWechat=true`。
- 状态与标签：
  - 空态：空图 +「暂无收货地址」+「添加您的收货地址，方便快速下单」。
  - 搜索无结果：「未找到匹配地址」+「试试其他搜索词」。
  - 加载态：「加载中...」。
  - 错误态：Toast「获取地址列表失败」。
  - 标签：默认地址卡片显示「默认」标签，其余不显示。
- 关键数据字段：收货人姓名、手机号、省/市/区、详细地址（完整地址拼接）、是否默认（isDefault）、地址 id、选择模式标记（select）。
- 页面文案：搜索「搜索手机号或地址」；导入按钮「导入微信地址」；主按钮「新增收货地址」；删除确认「确定要删除这个地址吗？删除后无法恢复。」；删除成功「删除地址成功」；设置默认成功「设置默认地址成功」；微信授权被拒「需要获取您的微信地址信息，请在设置中开启授权」；空态「暂无收货地址」/「添加您的收货地址，方便快速下单」；搜索空「未找到匹配地址」/「试试其他搜索词」；失败「获取地址列表失败」。
- 设计要点/禁忌：默认标签必须显眼且全列表唯一；删除属破坏性操作，红色文案 + 二次确认；选择模式与非选择模式视觉需区分（选择模式卡片带明确「选择此地址」按钮）；「至少保留一个可用地址」为业务期望，当前未强制（见备注）。
- 备注：目标形态标注——选择模式依赖本地 `selectedAddress` 缓存桥接确认订单页（与 F-ORD-001 地址卡回显联动）。缺口：删除「最后一个地址」未强制拦截（新缺口候选，R-ADR-01 扩充）。

## 页面 2：用户端 · 地址新增与编辑（建议文件名 address-edit.html）
- 功能编号：F-ADR-002 [已实现]
- 所属端：用户端小程序
- 页面入口与跳转：入口地址列表「新增收货地址」/「编辑」（编辑态 `?id=xx`）；微信地址导入（fromWechat=true）；保存成功 1.5s navigateBack 回地址列表。
- 布局结构（从上到下，表单逐行）：
  1. 收货人输入行（文本输入）。
  2. 手机号输入行（数字键盘，校验失败行内红字）。
  3. 所在地区行（点击拉起三级联动 Picker；展示已选省市区，未选时右侧灰字「请选择省市区」）。
  4. 详细地址输入行（多行文本，maxlength=100，下方提示「请输入详细的收货地址，不少于5个字符」）。
  5. 地址预览地图区（高 200px，带地图控件，支持手动点选）。
  6. 「设为默认地址」开关行。
  7. 底部「保存地址」主按钮（全宽，保存中显示「保存中...」）。
- 组件清单：AtForm、AtInput（收货人文本 / 手机号 phone）、Picker（multiSelector 三级联动）+ AtListItem（展示选值）、AtInput（详细地址 maxlength=100）、AddressMap（地图选点组件，高 200px、showControls）、AtSwitch（设为默认）、AtButton（保存）、AtToast / AtMessage / AtActivityIndicator（加载与提示）、useRegionSelector（省市区联动 hook）。
- 关键交互：
  1. 进入：有 `id` 加载详情（isEdit）回填并初始化三级联动；`fromWechat=true` 预填微信地址；无参为新增。
  2. 三级联动：onColumnChange 逐列联动、onChange 确认选值。
  3. 地图：自动按地址定位，可手动选点 → 逆地理编码回填详细地址并记录经纬度。
  4. 保存：校验通过 → create/update → Toast → 1.5s navigateBack。
  5. 坐标体系：存储/接口统一 WGS-84；小程序内微信地图（GCJ-02）在选点/定位回调边界转 WGS-84 后提交，展示后端坐标前转回 GCJ-02。
- 状态与标签：
  - 加载态：编辑详情「正在加载地址详情...」、地区「加载地区数据...」、保存「保存中...」。
  - 错误态：字段校验行内红字；Toast「保存失败，请重试」「地区加载失败: ...」。
  - 禁用态：提交 loading 期间按钮 disabled。
  - 空态：无。
- 关键数据字段：收货人姓名、手机号、省、市、区（三级联动值）、详细地址、经度 longitude、纬度 latitude（可空）、isDefault、地址 id。
- 页面文案：地区占位「请选择省市区」；详细地址提示「请输入详细的收货地址，不少于5个字符」；收货人「请输入收货人姓名」/「收货人姓名至少2个字符」/「收货人姓名不能超过20个字符」；手机号「请输入手机号」/「手机号格式不正确」；地区「请选择省份」/「请选择城市」/「请选择区域」；详细地址「请输入详细地址」/「详细地址至少5个字符」/「详细地址不能超过100个字符」；地图「地图位置已更新」/「已选择地图位置」；保存成功「地址添加成功」/「地址更新成功」。
- 设计要点/禁忌：三级联动与地图为两个独立选点通道，需清晰区分「行政区划」与「地图坐标」；地图选点失败允许手动填详细地址（经纬度可空不影响入库）；提交期间禁止重复点击。
- 备注：目标形态标注——坐标边界转换（gcj02ToWgs84 / wgs84ToGcj02）为既有实现细节。缺口：无。

## 页面 3：用户端 · 配送范围校验（确认订单页校验区）（建议文件名 order-confirm-range.html）
- 功能编号：F-ADR-003 [规划中]（目标形态）
- 所属端：用户端小程序
- 页面入口与跳转：位于下单确认页（order-confirm）地址卡下方校验结果提示区；提交订单前触发校验；范围外「更换地址」跳地址列表选择模式，「联系客服」拉起客服会话。
- 布局结构（从上到下）：
  1. 确认订单页既有地址卡（收货人/电话/完整地址）。
  2. 地址卡下方校验结果提示区：正常态不展示或展示浅色「配送范围内」；范围外态整块标红提示条。
  3. 范围外提示条内：「该地址暂不支持配送」文案 + 右侧/下方「更换地址」「联系客服」两个操作按钮。
  4. 提交订单主按钮（范围外时禁用或点击即拦截）。
- 组件清单：AddressDisplay（确认页地址卡，校验扩展）；提示条（图标 + 文案 + 操作按钮）；「更换地址」「联系客服」按钮。
- 关键交互：
  1. 提交订单前调范围校验接口。
  2. 不在范围 → 地址卡标红 + 提示「该地址暂不支持配送」+「更换地址」「联系客服」按钮。
  3. 点击「更换地址」→ 跳地址列表选择模式重新选地址。
  4. 点击「联系客服」→ 拉起客服会话。
- 状态与标签：空态——无可达区域时全部地址不可下单；加载态——校验中（按钮 loading / 提示骨架）；错误态——校验接口异常时降级放行，避免误拦；禁用态——无。
- 关键数据字段：收货地址省/市/区、是否落入任一启用片区、可达标记（inRange）。
- 页面文案：范围外「该地址暂不支持配送」；引导按钮「更换地址」「联系客服」。
- 设计要点/禁忌：校验异常必须降级放行（不可误拦正常下单）；拦截提示要给出明确出路（换地址/客服），避免死胡同；范围拦截优先在后端提交链路执行，前端提示与之对齐。
- 备注：目标形态——现状 `isAddressInDeliveryArea()` 恒返回 true（G07），校验关闭，前端无拦截，UI 全部为规划形态。依赖 F-ADR-013 配送片区数据先落地。

## 页面 4：管理后台 · 配送区域维护（建议文件名 delivery-areas.html）
- 功能编号：F-ADR-003 [规划中]（目标形态；R-ADR-02 配送区域维护）
- 所属端：管理后台
- 页面入口与跳转：侧边菜单「配送区域」（目标形态，参考 addresses 页结构）；新增/编辑弹窗；启停用行内操作。
- 布局结构（从上到下）：
  1. 顶部操作栏：「新增区域」按钮（右上）。
  2. 区域表格区（全宽）。
  3. 新增/编辑弹窗（覆盖层居中）：名称、省、市、区、启用状态。
  4. 删除/停用二次确认（Popconfirm 或 Modal）。
- 组件清单：Card、Button、Space、Table、Modal、Form、Select（省/市/区）、Switch（启用状态）、Popconfirm、message（antd）。
- 关键交互：
  1. 新增区域：填表单（名称/省/市/区/启用）→ 保存 → 列表刷新。
  2. 编辑区域：回填 → 保存生效。
  3. 启停用：切换启用状态即时生效，停用后该校验视为不可达（R-ADR-02）。
- 状态与标签：空态表格空；加载态表格 loading；错误态 message 保存失败；状态标签——启用/停用（Tag 着色）。
- 关键数据字段（表格列）：区域名称 / 省 / 市 / 区 / 启用状态 / 操作（编辑、启停用）。
- 页面文案：新增「新增区域」；保存成功/失败 message（沿用 addresses 页口径）；删/停确认文案参考「确定删除该片区吗?删除后该范围地址将不可下单」。
- 设计要点/禁忌：省市区为精确匹配口径（省+市+区），表单需强制三级都选；启用状态需一眼可辨。
- 备注：目标形态——现状无区域维护模型，校验关闭（G07）。与 F-ADR-013 配送片区为同一数据底座，实施时可能合并。

## 页面 5：用户端 · 配送跟踪（建议文件名 delivery-tracking.html）
- 功能编号：F-ADR-010 [部分实现]（真实轨迹接入为「本期目标」2026-10）
- 所属端：用户端小程序
- 页面入口与跳转：入口订单详情「查看配送进度」；参数 `delivery-tracking?orderId=xx`；无 orderId 时 Toast 并返回。
- 布局结构（从上到下）：
  1. 地图区（顶部大方块）：双标记（送水工 icon + 配送地址 icon），启用定位/比例尺/指南针控件；地图右下角两个圆形控制按钮：刷新位置、查看路线。
  2. 配送员信息卡：头像 + 姓名 + 电话 + 当前位置地址 + 电话拨打按钮 +「配送中」标签 +「预计 xx 送达」。
  3. 配送地址卡：收货人 / 电话 / 完整地址。
  4. 实时跟踪提示条：「实时跟踪中，每10秒更新位置」。
- 组件清单：Map（地图，双标记、定位/比例尺/指南针）、AtCard（配送员信息卡、配送地址卡）、AtButton（刷新位置、查看路线圆形按钮、电话拨打）、AtIcon、AtTag（「配送中」/「已送达」）、AtLoading、AtToast。
- 关键交互：
  1. 进入：读取 orderId，无则 Toast「订单ID缺失」1.5s 返回。
  2. 加载跟踪信息（现状为 mock，目标为真实轨迹数据源）。
  3. useDidShow 开启 10s 定时更新送水工位置，useDidHide 停止。
  4. 点电话按钮 makePhoneCall 拨打。
  5. 点路线按钮 openLocation 打开配送地址地图。
  6. 点刷新按钮 getCurrentLocation + 更新送水工位置，Toast「位置已更新」。
  7. 下拉刷新。
  8. 送达后展示「已送达」，停止位置刷新（R-ORD-11）。
- 状态与标签：空态——无 order 显示「订单不存在」+「返回」按钮；加载态——AtLoading「加载中...」；错误态——Toast「订单ID缺失」「获取位置信息失败」「加载跟踪信息失败」「位置信息不完整」「更新失败」；标签——配送中 / 已送达。
- 关键数据字段：orderId、送水工姓名、送水工电话、送水工当前位置（经纬度）、收货地址（经纬度+文案）、预计送达时间、订单状态（DELIVERING/已完成）。
- 页面文案：「实时跟踪中，每10秒更新位置」；「配送中」；「已送达」；「预计 xx 送达」；「订单ID缺失」；「位置信息不完整」；「订单不存在」。
- 设计要点/禁忌：地图上双标记必须可区分（送水工/收货地址不同图标与颜色）；「已送达」后不得继续刷新位置；状态门控——仅「配送中」可进入（现状 mock 绕过判断为目标缺口）；用户端只展示概略位置，不下发精确轨迹序列（隐私，开放问题）。
- 备注：目标形态——本期（2026-10）接入真实轨迹数据源 `deliveryTrajectories(orderId)` / `deliveryWorkerLatestLocation(workerId)`，启用「仅配送中可进入」门控；缺口 G02（现状订单/送水工/位置均为 mock）、G65（用户端未复用轨迹数据源）。

## 页面 6：用户端 · 订阅消息授权（建议文件名 subscribe-notice.html）
- 功能编号：F-ADR-011 [规划中]（已归口通知与消息域 §F-NTF-001，本域仅配送场景引用）
- 所属端：用户端小程序（+ 送水工端）
- 页面入口与跳转：下单确认页（order-confirm）提交订单时按微信规范申请订阅授权；送水工端接收新订单/派单提醒。
- 布局结构（从上到下）：
  1. 确认订单页提交前订阅授权弹窗/组件（一次性 / 长期模板按微信规范）。
  2. （送水工端）新订单 / 派单提醒的订阅授权入口。
- 组件清单：订阅授权组件（基于 Taro.requestSubscribeMessage）；授权结果提示。
- 关键交互：
  1. 提交订单时请求订阅授权。
  2. 用户接受 → 记录订阅状态并关联模板。
  3. 订单节点触发 → 调订阅消息发送服务推送。
  4. 未授权 → 不推送，节点信息在站内订单详情可见。
- 状态与标签：加载态/错误态——发送失败重试并幂等；禁用态——已拒绝或已达次数上限后不再弹授权。
- 关键数据字段：订阅授权状态、模板 id、订单节点类型（下单成功/配送员接单/开始配送/送达确认/退款结果）。
- 页面文案：各节点文案按微信模板；未授权降级站内查看。
- 设计要点/禁忌：订阅授权须按微信规范（与提交订单动作绑定，不可诱导）；未授权不得阻断下单主流程。
- 备注：目标形态——归口通知域，权威定义见 13-notification.md；历史编号 F-ADR-011 / AC-ADR-011-xx 保留。缺口 G08（仅脚手架，无发送服务、无 access-token 服务）。
