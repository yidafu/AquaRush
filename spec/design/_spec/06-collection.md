# 06 收银与对账域 页面规格

> 来源：`spec/prd/06-collection.md`（F-COL-001/002/003、010/011/012；R-COL-01~05）。
> 说明：金额以「分」存储与计算，展示两位小数（R-MON-01）；状态文案统一为「待对账/匹配/有差异/已复核」（2026-10-08 定稿），容差固定 ±100 分（1 元），水票按张数精确比对。

---

## 页面 1：送水工端 · 每日收款提交（建议文件名 daily-collection.html）
- 功能编号：F-COL-001 [已实现]
- 所属端：送水工端 App
- 页面入口与跳转：入口「我的」页「每日收款」→ daily-collection；提交成功刷新本地状态为「已提交」。
- 布局结构（自上而下）：
  1. 顶部说明条（三条提示）：「1. 现金和扫码收款将自动与今日完成订单金额对比」「2. 差异在1元以内视为正常」「3. 提交后可由管理员确认审核」。
  2. 收款日期区：「收款日期」+ 当日日期（YYYY-MM-DD）。
  3. 当前状态卡：「当前状态」+ 状态文本（草稿/已提交/已确认/有争议，按状态着色），仅当日已有记录时展示。
  4. 今日收款录入区：
     - 「今日订单情况」区块（订单总数 / 现金应收 / 扫码应收 / 水票应收，来源系统预计算）。
     - 三栏输入：现金收款（元）/ 水票数量（张）/ 扫码收款（元）。
     - 「合计」实时计算（现金 + 扫码）。
  5. 底部主按钮「提交收款」（提交中显示「提交中...」）。
  6. 金额差异确认弹窗：展示现金/水票/扫码差异 + 差异说明输入（≤200 字）。
- 组件清单：PageContainer、AtNoticebar（顶部说明条）、AtForm、AtInput（三栏数字输入）、AtButton（提交）、AtModal（差异确认弹窗）、OrderInfoRow（系统预计算展示行：订单总数/现金应收/扫码应收/水票应收）。
- 关键交互：
  1. useAuth 取送水工身份，getTodayCollection 加载今日收款记录，有已填写数据自动回填三栏并展示状态。
  2. 填写三栏，合计实时计算。
  3. 提交校验：三栏全零 → Toast「请填写收款金额」；否则按分计算与系统计算值的差异（现金/扫码超 ±100 分或水票 ≠0 张）→ 弹差异确认弹窗；容差内直接提交。
  4. 差异弹窗内说明必填（空 → Toast「请输入情况说明」），点「确定」带说明提交。
  5. 提交成功 Toast「提交成功」并刷新本地状态为「已提交」；失败 Toast「提交失败」。
- 状态与标签：
  - 空态：今日无订单时「今日订单情况」全为 0（应收均 ¥0.00 / 0 张），三栏输入为空。
  - 加载态：数据加载中。
  - 错误态：加载失败、提交失败 Toast。
  - 禁用态：提交中按钮 loading 防重复提交（服务端 R-COL-01 兜底幂等）。
  - 状态标签：草稿 / 已提交 / 已确认 / 有争议（按状态着色；送水工端以服务端状态回显）。
- 关键数据字段：收款日期、订单总数、现金应收、扫码应收、水票应收（系统预计算）、现金收款（填报）、水票数量、扫码收款、合计、差异（现金/水票/扫码）、差异说明 notes（≤200 字）、状态（草稿/已提交/已确认/有争议）。
- 页面文案：「1. 现金和扫码收款将自动与今日完成订单金额对比」「2. 差异在1元以内视为正常」「3. 提交后可由管理员确认审核」；「收款日期」；「当前状态」；「今日订单情况」；「合计」；「提交收款」/「提交中...」；「请填写收款金额」「请输入情况说明」「今日已提交」「提交成功」「提交失败」。
- 设计要点/禁忌：金额差异必须显式对比展示（系统预计算 vs 人工填报），差异项高亮；差异说明为超容差提交的必填项；提交按钮需防重复点击（幂等）；三栏全零需拦截。
- 备注：容差固定 ±100 分（前端 TOLERANCE_CENTS / 后端 TOLERANCE_AMOUNT_CENTS），「可配置化」为本期未做项（缺口 G73）；差异口径 = 填报(现金+扫码) − 系统计算(现金+扫码)，水票订单金额不计入金额差异基数，水票按张数单独精确比对。

## 页面 2：送水工端 · 对账记录（建议文件名 reconciliation-records.html）
- 功能编号：F-COL-002 [已实现]
- 所属端：送水工端 App
- 页面入口与跳转：入口「我的」页「对账记录」→ reconciliation-records；点击卡片查看当日已送达订单流水（对账详情下钻）。
- 布局结构（自上而下）：
  1. 对账记录卡片列表（按日期倒序，每页 10 条）。
     - 每卡：头部（对账日期 + 状态彩色标签）；订单汇总（订单总数 / 订单金额）；收款汇总（现金收款 / 扫码收款）；差异行（水票数量 / 差异金额）；复核信息（复核时间 / 复核备注）。
  2. 上拉加载更多；下拉刷新；空态居中。
- 组件清单：PageContainer、reconciliation-card 卡片（statusColorMap 状态着色）。
- 关键交互：
  1. useDidShow 加载对账记录，按日期倒序排列，初始展示第一页。
  2. 上拉加载下一页。
  3. 下拉刷新重置并重新加载。
  4. 点击卡片 → 下钻查看当日已送达订单流水（逐单差异明细，服务端分页）。
  5. 后台复核后此处状态同步更新。
- 状态与标签：
  - 空态：无记录显示「暂无对账记录」。
  - 加载态：「加载中...」。
  - 错误态：Toast「加载失败」。
  - 禁用态：无更多数据时显示「没有更多了」。
  - 状态标签色：待对账黄 / 匹配绿 / 有差异红 / 已复核蓝。
  - 差异金额色：|差异| ≤ 1 元绿色、> 1 元红色（±100 分容差）。
- 关键数据字段：对账日期、状态（待对账/匹配/有差异/已复核）、订单总数、订单金额、现金收款、扫码收款、水票数量、差异金额、复核时间、复核备注。
- 页面文案：「暂无对账记录」「加载中...」「加载失败」「没有更多了」；状态「待对账/匹配/有差异/已复核」。
- 设计要点/禁忌：状态标签颜色必须与后台一致并一目了然；差异金额正负与超容差需红色强调；复核信息仅在已复核记录展示；列表倒序不可打乱。
- 备注：对账详情已呈现逐单差异明细（2026-08-24，G29 已解决）——卡片可下钻到具体订单；状态文案以 R-COL-03 定稿为准。缺口：无。

## 页面 3：送水工端 · 工作台统计概览（建议文件名 workbench.html）
- 功能编号：F-COL-003 [已实现]（并入工作台）
- 所属端：送水工端 App
- 页面入口与跳转：底部 TabBar「工作台」（原「统计」Tab 已移除）；点击统计卡跳转 history-orders 对应 Tab（今日总订单 → 待配送 Tab / 已完成 → 已完成 Tab / 未完成 → 未完成 Tab）。
- 布局结构（自上而下）：
  1. 今日统计卡组（2×2 或一行四卡）：今日总订单（→历史订单待配送 Tab）/ 已完成（→已完成 Tab）/ 未完成（→未完成 Tab）/ 今日营收（highlight 高亮）。
  2. 近 7 天统计区：标题「近7天送水数据」+ 汇总（订单 / 营收）+ 双折线图（订单数 / 营收两条线）。
- 组件清单：StatCardGrid（统计卡栅格）、StatCard（单卡，数值 + 文案 + 跳转）、WeekLineChart（近 7 天双折线图）。
- 关键交互：
  1. 进入工作台 getWorkbenchData 加载今日统计与周统计并渲染（单请求取回）。
  2. 点击统计卡 navigateTo history-orders 对应 Tab。
  3. 聚焦 / 下拉刷新重取数据；30 秒轮询刷新。
- 状态与标签：空态——无数据时各卡为 0、周图为空；加载态——数据加载中；错误态——加载失败提示；禁用态——无；「今日营收」卡高亮。
- 关键数据字段：今日总订单、已完成、未完成、今日营收（现金+扫码，水票以张数计）、近 7 天逐日订单数、近 7 天逐日营收。
- 页面文案：「工作台」「今日总订单」「已完成」「未完成」「今日营收」「近7天送水数据」「订单」「营收」。
- 设计要点/禁忌：今日营收与订单资金口径一致（来源当日已完成订单收款汇总）；周趋势图为双线（订单数/营收），双轴需区分；数值金额换算为元展示。
- 备注：独立「统计」Tab 已移除（2026 去重调整），收敛到工作台首页；口径与 PRD 原文「待配送/配送中/已完成」分栏不同（开放问题）；缺口：无。

## 页面 4：管理后台 · 收银对账-每日收款记录（建议文件名 admin-daily-collection.html）
- 功能编号：F-COL-010 [已实现]
- 所属端：管理后台
- 页面入口与跳转：后台导航「收银对账」→ daily-collection；Tab「每日收款记录」；对争议日报可「确认/驳回」；同页另有「对账记录」Tab（见页面 5）。
- 布局结构（自上而下）：
  1. 顶部 4 张汇总卡：现金收款 / 扫码收款 / 水票数量 / 订单金额（基于今日收款记录汇总）。
  2. Tabs：「每日收款记录」|「对账记录」。
  3. 收款记录表格区（全宽，行数多时横向滚动）。
  4. 确认弹窗（Modal.confirm）；驳回弹窗（必填原因）。
- 组件清单：Card、Statistic（4 张汇总卡）、Tabs、Table、Tag、Button、Modal.confirm、message（antd）。
- 关键交互：
  1. GET_DAILY_COLLECTIONS 加载全部日报。
  2. 点「确认」→ Modal.confirm「确认配送员 {id} 的收款记录吗?」→ CONFIRM_DAILY_COLLECTION(recordId) → message「确认成功」并 refetch。
  3. 点「驳回」→ 驳回弹窗（必填原因）→ REJECT_DAILY_COLLECTION(recordId, reason) → 状态回「草稿」并展示驳回信息。
  4. 操作列对「已提交」「有争议」行显示「确认」「驳回」链接按钮（争议处理闭环 G28）。
- 状态与标签：
  - 空态：无日报时表格为空。
  - 加载态：表格 loading。
  - 错误态：确认失败 message 提示。
  - 禁用态：非「已提交」行不显示确认按钮。
  - 状态 Tag 色：草稿 default / 已提交 processing / 已确认 success / 有争议 error。
  - 差异列色：|差异| ≤ 1 元绿 / 否则红。
- 关键数据字段与表格列：配送员ID / 收款日期 / 现金金额 / 水票数量 / 扫码金额 / 订单数量 / 订单金额 / 系统计算现金 / 系统计算扫码 / 系统计算水票 / 系统计算订单金额 / 差异 / 差异说明 / 状态 / 驳回信息 / 操作。
- 筛选项（建议，目标形态）：配送员、收款日期范围、状态（草稿/已提交/已确认/有争议）。
- 页面文案：确认弹窗「确认配送员 {id} 的收款记录吗?」；成功「确认成功」；驳回弹窗必填原因、成功「已驳回」；差异说明（notes）列展示配送员提交的差异原因；驳回信息列展示驳回原因/时间。
- 设计要点/禁忌：系统计算值列必须与配送员填报值并列展示，差异列高亮（金额差异比对）；「有争议」行需突出显示并提供差异说明查看；已确认行不可再确认；驳回后回草稿可改可重提。
- 备注：驳回自 2026-08-24 起在 delivery-app 管理端收银对账页（admin-collection）同步落地；差异口径同 R-COL-02 补充；订单金额列保留全量展示（标注含水票）。缺口：无（G28/G30 已解决）。

## 页面 5：管理后台 · 收银对账-对账记录（建议文件名 admin-reconciliation.html）
- 功能编号：F-COL-011 [已实现]
- 所属端：管理后台
- 页面入口与跳转：后台导航「收银对账」→「对账记录」Tab；「查看详情」打开对账详情 Modal。
- 布局结构（自上而下）：
  1. 右上「手动执行对账」按钮（loading 态）。
  2. 对账记录表格区（全宽）。
  3. 「对账详情」Modal：订单总数 / 订单金额 / 现金收款 / 扫码收款 / 差异金额 / 状态 Tag + 复核备注 TextArea + 「确认复核」按钮（非「已复核」时显示）；已复核展示复核时间与复核备注；含逐单差异明细（当日已送达订单流水，分页）。
- 组件清单：Card、Table、Tag、Button、Modal、Form/Input.TextArea、Statistic、message（antd）。
- 关键交互：
  1. 「手动执行对账」→ Modal.confirm「确定要执行对账吗?重复执行会更新已有数据」→ EXECUTE_DAILY_RECONCILIATION（默认昨日日期）→ 成功 message「对账执行成功」/失败「对账执行失败: …」并 refetch。
  2. 点「查看详情」→ 打开对账详情 Modal。
  3. 填复核备注 →「确认复核」→ REVIEW_RECONCILIATION → message「复核成功」，状态置「已复核」并展示复核时间/备注。
  4. 每日 03:00 调度器自动对昨日执行对账（DailyCollectionScheduler）。
- 状态与标签：
  - 空态：无对账记录表格为空。
  - 加载态：Table loading + 按钮 loading。
  - 错误态：对账执行失败 message。
  - 禁用态：已「已复核」记录不显示「确认复核」按钮。
  - 状态标签：待对账 / 匹配 / 有差异 / 已复核。
  - 差异金额色：|差异| ≤ 1 元绿 / 否则红。
- 关键数据字段与表格列：对账日期 / 订单总数 / 订单金额 / 总收款金额 / 现金收款 / 水票数量 / 扫码收款 / 差异金额 / 状态 / 操作（查看详情）。
- 筛选项（建议，目标形态）：对账日期范围、状态（待对账/匹配/有差异/已复核）。
- 页面文案：「手动执行对账」；「确定要执行对账吗?重复执行会更新已有数据」；复核备注占位「请输入复核备注」；「对账执行成功」「对账执行失败: 具体错误」「复核成功」。
- 设计要点/禁忌：差异比对须显式（系统计算 vs 日报填报口径）；已复核记录须隐藏复核入口防止二次审核；重新执行对账会重算结果并清除复核痕迹，需在交互中提示；复核备注为追溯依据。
- 备注：对账生成逻辑——比对订单流水（按收款方式汇总）与日报，差异在 ±100 分内且水票张数精确匹配判「匹配」，否则「有差异」；差异基数 = 填报(现金+扫码) vs 系统计算(现金+扫码)，水票订单金额不计入（2026-08-24 口径修正）。缺口：无（G29 已解决）。

## 页面 6：管理后台 · 工资结算（建议文件名 payroll.html）
- 功能编号：F-COL-012 [规划中]（目标形态，2026-10 新增，资金类）
- 所属端：管理后台
- 页面入口与跳转：侧边菜单「收银对账 → 工资结算」（payroll）；结算单详情可下钻关联日报/对账；「导出」下载结算台账。
- 布局结构（自上而下）：
  1. 筛选区：结算周期（月份 / 自定义区间）、送水工（多选 / 全部）、状态（待生成/已生成/已确认/已发放）。
  2. 操作按钮：「生成结算单」「导出台账」。
  3. 结算单列表表格区（全宽）。
  4. 结算单详情弹窗 / 页面：工资项明细（计件 = 完成订单数 × 单价、补贴、扣款、应发合计）+ 关联的日报/对账入口 + 发放记录。
  5. 发放确认二次弹窗。
- 组件清单（目标形态）：Card、Table、Tag、Button、Modal、Form/InputNumber、Statistic、DatePicker、message（antd）。
- 关键交互：
  1. 选择周期 → 点「生成结算单」→ 系统按规则汇总 → 生成各送水工结算单（幂等：同周期同人唯一）。
  2. 复核明细（可下钻查看订单/日报/对账）→「确认」。
  3. 记录发放（填发放方式/凭证）→ 状态「已发放」。
  4. 导出台账。
- 状态与标签：
  - 空态：「暂无结算单,请先选择周期生成」。
  - 加载态：生成 / 列表 loading。
  - 错误态：生成失败 / 对账不一致提示。
  - 禁用态：已发放结算单不可再确认/发放。
  - 状态标签：待生成 / 已生成 / 已确认 / 已发放。
- 关键数据字段与表格列：送水工 / 周期 / 计件数 / 底薪 / 提成 / 补贴 / 扣款 / 应发合计 / 状态 / 操作（生成 / 查看 / 确认 / 发放 / 导出）。
- 筛选项：结算周期（月份/自定义区间）、送水工（多选/全部）、状态（待生成/已生成/已确认/已发放）。
- 页面文案：周期必选；应发合计 = 底薪 + 计件提成 + 补贴 − 扣款（可为负时告警，开放问题）；重复生成「该周期结算单已存在」；发放确认弹窗「确认发放送水工 {name} 本期工资 ¥{amount} 吗?」；成功「已发放」；空态「暂无结算单,请先选择周期生成」。
- 设计要点/禁忌（资金底线，不可砍）：计算口径须与日报/订单对账一致（对账）；同周期同人唯一 + 发放幂等（防重复发放，状态机 待生成→已生成→已确认→已发放，已发放不可重复发放）；差异/负值告警（资损监控），计件数据与日报/对账不一致时挂起告警、不静默发放；发放记录留痕（方式/时间/操作人）与线下打款凭证可核对；金额以分存储与计算，禁止浮点（R-MON-01），展示两位小数。
- 备注：目标形态——现状无工资规则配置、无结算单、无发放记录，送水工报酬依赖线下人工核算；工资规则配置（底薪/计件单价或比例/补贴/扣款）后台可配；跨周期订单按完成时间归属；结算单生成后日报被驳回时已确认结算单是否重算为开放问题；缺口 G88（送水工端「收入提现」为后续，见 14-misc.md §G88 注记）。
