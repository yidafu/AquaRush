页面说明

所属端：送水工端 App（Expo React Native，亮色）

入口：「我的」页「每日收款」/ 工作台快捷入口「提交日报」→ daily-collection。

跳转：提交成功刷新本地状态为「已提交」，由管理员在后台确认 / 驳回。

布局结构

  1. 顶部说明条（三条提示）
  2. 收款日期区：「收款日期」+ 当日日期
  3. 当前状态卡：「当前状态」+ 状态文本（仅当日已有记录时展示）
  4. 今日订单情况（系统预计算）：订单总数 / 现金应收 / 扫码应收 / 水票应收
  5. 今日收款录入：现金收款（元）/ 水票数量（张）/ 扫码收款（元）+ 合计实时计算
  6. 差异比对：系统预计算 vs 实际填报，超容差高亮
  7. 底部主按钮「提交收款」（提交中「提交中...」）
  8. 金额差异确认弹窗：现金 / 水票 / 扫码差异 + 差异说明输入

关键交互

  1. getTodayCollection 加载今日记录，有数据自动回填三栏并展示状态。
  2. 填写三栏 → 合计实时计算。
  3. 提交校验：三栏全零 → 「请填写收款金额」；否则按分计算差异（现金 / 扫码超 ±100 分或水票 ≠ 0 张）→ 弹差异确认弹窗；容差内直接提交。
  4. 差异弹窗内说明必填（空 → 「请输入情况说明」），点「确定」带说明提交 → 「提交成功」并刷新状态。

状态与规则

状态标签：草稿 / 已提交 / 已确认 / 有争议（按状态着色，以服务端回显）。

空态：今日无订单时「今日订单情况」全为 0（应收均 ¥0.00 / 0 张），三栏输入为空。

禁用态：提交中按钮 loading 防重复（服务端 R-COL-01 兜底幂等）；错误态：加载失败 / 提交失败 toast。

差异口径 = 填报（现金 + 扫码）− 系统计算（现金 + 扫码）；水票订单金额不计入金额差异基数，按张数单独精确比对；容差固定 ±100 分。

设计要点 / 禁忌

金额差异必须显式对比展示（系统预计算 vs 人工填报），差异项高亮；差异说明为超容差提交的必填项。

送水工端完全不出现强调橙：提交按钮走品牌蓝（--brand），差异超限用 error 色，容差内用绿色。

提交按钮需防重复点击（幂等）；三栏全零需拦截；金额统一「¥xx.xx」两位小数。
