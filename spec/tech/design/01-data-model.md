# 01 · 数据库设计

> 依据 PRD v0.30 各域「核心实体」与 14-misc §核心实体（45 实体）推导的全量表设计。字段口径与数字均引自 PRD；PRD 未定的以 **【开放决策】** 标注并给出建议默认值。

## 0. 全局约定

| 项 | 约定 |
| --- | --- |
| 主键 | `id BIGINT`。**现状**:DDL 一代表为 `GENERATED BY DEFAULT AS IDENTITY` 兜底,但所有仓储统一**应用侧 Snowflake 生成**后显式插入（`SnowflakeIdGenerator`,40+ 处）,语义以应用侧雪花为准;拍板 5.4「全面迁移 Snowflake」列 B5 批次（须先做 JS 精度 spike,63 位 ID > 2^53）。ORM 为 **Exposed**（非 JPA） |
| 金额 | 一律 `*_cents BIGINT`（分），禁止 float/double；展示层 ÷100（R-MON-01） |
| 时间 | `created_at` / `updated_at` `TIMESTAMP`，JVM/JDBC/部署三处钉死 Asia/Shanghai |
| 枚举 | `VARCHAR` 存枚举名（可读、可扩展），服务层守卫合法值 |
| 软删除 | 列名 **`is_deleted BOOLEAN`**（非 `deleted`）;两档基类:`SoftDeleteFlagTable`（仅 is_deleted,日报/对账两表）与 `SoftDeletableTable`（+ `deleted_at`/`deleted_by`,多数表）。查询入口自动过滤（`selectAll()`/`select()` 自带 `is_deleted=false`,追加条件用 `.andWhere{}`;读已删行走 `selectAllIncludingDeleted()`,AGENTS 规则 #13）;日志/流水类只增不删 |
| 快照 | 订单持有商品、单价、优惠、运费、时段的**下单时快照**，不以外键关联的实时值为准;地址为 `address_id` 引用（**现状无地址快照列**,订单地址修正回写 addresses 行——与快照目标的已知差异,F-ORD-024 现状口径） |
| 命名 | 表/列 snake_case；索引 `idx_表_列`，唯一索引 `uk_表_列` |
| 迁移 | Liquibase changelog（Kotlin DSL,启动自动执行，无手动 update 任务），变更只追加 |
| 禁全表 | 无 `findAll()` 式查询；列表必带分页+过滤；调度/导出用键集分页（游标） |

### 3.5 `deposit_records` 押金记录（押金账本）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| user_id | BIGINT → users | |
| order_id | BIGINT → orders | 随单收取来源 |
| deposit_amount_cents | BIGINT | 收取金额快照（列名 `deposit_amount_cents`;G06 后历史行只读） |
| status | VARCHAR(20) | 现状默认 `COLLECTED`(已收取) → `REFUNDED`(已退还);目标态机 PENDING(待收取) → HELD(已收取) → REFUNDED 随 B2 恢复 |
| collected_at / refunded_at | TIMESTAMP | |
| refunded_by / refund_remark | BIGINT / VARCHAR(500) | 退还留痕（现状为管理员手动退,B2 改申请-审核流） |

索引：`idx_deposit_user_spec(user_id, specification, status)`（目标;现状列组按 deposit 查询）。
口径公式（R-PRO-04/05，桶账台账同源,B2 恢复后生效）：
- **在租押金桶数** = Σ(bucket_count WHERE status=HELD)（目标列 `specification + unit_deposit_cents + bucket_count`,现状表无规格/桶数列——B2 扩列）
- **押金合计** = Σ(在租桶数 × 规格押金)；**押金余额** = 押金合计 − 已退押金
- 收取规则：下单含某规格商品且该用户该规格**无 HELD 记录**时随单收取（「同一规格在租只收一次押金」）；【开放决策】收取桶数口径 → 建议按本单该规格购买桶数 × 单价收取（与「在租桶数=记录桶数」公式一致）
- 退押以记录状态幂等（条件更新 `WHERE status='HELD'`），防并发重复退还；退押**不计入营收/退款统计**（独立 DEPOSIT_REFUND 账本）

### 7.4 `delivery_fee_rules` 配送费规则（F-OPS-005,单行）

`free_floor_limit INT DEFAULT 4（列名 free_floor_limit,非 free_floor） + surcharge_cents BIGINT DEFAULT 200（兜底单档,0-999 元,仅 tiers 为空时参与计价） + tiers JSON（**V345 已落列**,结构 #6/R-MON-02 分档:）`:
`tiers: [{fromFloor:5,toFloor:6,feeCents:200},{fromFloor:7,toFloor:9,feeCents:500},{fromFloor:10,toFloor:null,feeCents:800}]`（存量行已回填该默认三档）;校验（服务层）：free_floor ≥0;档位非空、按起始楼层严格升序、区间不重叠、起始楼层 > 免费楼层、末档 toFloor=null（不封顶）、各档 0-999 元 ≤2 位小数。
计费口径（R-MON-02 2026-10 分档修订）：楼层为空 → 0；楼层 ≤ free_floor → 0；否则命中档位 [fromFloor..toFloor|null=∞] 取 feeCents,tiers 为空回退 surcharge_cents；自提 → 0。下单服务端快照落 `orders.delivery_fee_cents`，配置变更不追溯。

**规划列**（R-OPS-03 起送门槛与距离阶梯运费,G96 排期待定,与楼层分档互补叠加计算）：

- `minimum_order_cents BIGINT DEFAULT 0`——起送门槛（0=不启用,默认）。createOrder 前置校验：商品金额（未扣优惠）< 门槛 → 拦截下单（BUSINESS_RULE「未达起送金额」）；自提订单不受限（R-OPS-03）；
- `distance_tiers JSON`——按距离阶梯加价表,结构与 tiers 同构：`[{fromKm:0,toKm:3,feeCents:0},{fromKm:3,toKm:5,feeCents:300},{fromKm:5,toKm:null,feeCents:600}]`（默认示例=PRD 示例,存量行回填全 0 档等效不启用）;校验（服务层）：按起始距离升序、区间不重叠、末档 toKm=null（不封顶）、各档金额 ≥0 且 ≤2 位小数。距离 = 收货地址经纬度与门店经纬度（store_profiles 规划列）的**直线距离（Haversine）**【开放决策：PRD 留口径开放,默认直线;若改骑行/驾车需外部路径服务,与单服务器轻量定位冲突】。坐标体系：地址 WGS-84（提交端已转换）对门店 WGS-84,同系直接计算。

计价叠加顺序（R-MON-02 扩展,快照语义不变）：楼层分档运费 + 距离阶梯加价 → `orders.delivery_fee_cents` 一次快照合计；配置变更即时生效但不追溯已生成订单。
