## 页面 1：用户端 · 确认订单页（建议文件名 order-confirm.html）
- 功能编号：F-ORD-001 [已实现]（确认订单与提交下单）、F-ORD-004 [已实现]（多商品下单复用本页）、F-ORD-025 [规划中]（一键复购回填本页）、F-ORD-026 [规划中]（周期订购确认来源复用）、F-ORD-027 [规划中]（企业客户「月结(账期)」支付方式）、F-ORD-023 [部分实现]（熟客分组价/计价应用层）
- 所属端：用户端小程序
- 页面入口与跳转：
  - 入口：商品详情（product-detail）「立即购买」；购物车结算（F-ORD-004，cart 页）；订单列表/订单详情「再来一单/再次购买」（F-ORD-025 规划）；周期订购计划确认（F-ORD-026 规划）。
  - 可跳转：收货地址列表（address-list?select=true，选择模式）、订单详情（order-detail?orderId=xx，提交成功后 redirectTo）、首页（无商品异常时自动返回）。
  - 目标形态复用：购物车结算多商品也进入本页。
- 布局结构（从上到下逐行）：
  1. 顶部导航栏（返回 + 标题「确认订单」）。
  2. 收货地址卡：无地址显示「请选择收货地址」+「选择地址」按钮；有地址显示 联系人 / 电话 / 完整地址 / 右箭头（紧凑两行布局，白卡无内嵌卡片），有默认地址时加「默认」标签。
  3. 商品卡：封面图 + 名称 + 规格 + 优惠价（有营销价时旁边划线目录价）× 数量；标题右侧「共 N 件」；多商品（F-ORD-004）为多行商品清单，行内可调数量。
  4. 配送时间区：2×2 芯片选择（选中 = 主色描边 + tint 底），选项由后台 F-SYS-002 配置驱动（立即配送时限 / 上午 / 下午 / 晚上，仅渲染启用时段），默认「立即配送」。
  5. 支付方式区：仅微信支付（「推荐」标签，默认选中）；**无余额支付选项**（用户储值不做，2026-10-09 合规决策，原「余额支付置灰即将上线」占位移除）；企业客户（F-ORD-027 规划）额外出现「月结(账期)」选项，选中时不进入微信支付。
  6. 备注区：多行输入（≤200 字，两行高）。
  7. 费用明细卡（见文末「订单金额构成」）：商品金额（按成交单价计）→ 营销优惠（满减 / 首单立减 / 优惠券，有则逐项展示「-¥x」，优惠券可改选）→ 水票抵扣（展示「-¥x」，桶数入标签）→ 赠品行（¥0.00）→ 配送费（免费楼层内显示「免配送费」，超出按配置分档加价）→ 水桶押金（首次为该规格购桶时收取并展示押金行，可退）→ 实付合计。
  8. 服务条款 Checkbox「我已阅读并同意《用户服务协议》和《隐私政策》」。
  9. 底部操作栏：合计金额（有订单层优惠时展示「已优惠 ¥x」）+「提交订单」按钮（加载中显示「提交中...」）。
- 组件清单（具体形态）：AddressDisplay（收货地址卡，空态/有值态两形态）、ProductList（单商品紧凑行 / 多商品可调数量清单）、DeliveryTimeSelector（2×2 芯片组）、PaymentMethodSelector（单选卡片，仅微信支付，无禁用占位——余额支付不做）、OrderRemark（多行输入 ≤200 字）、CostSummary（金额明细行组）、CouponSelector（优惠券选择器，引擎推荐最优券可改选）、TicketRedeemSection（水票核销区，勾选张数 + 抵扣金额 + 桶数标签）、TermsAgreement（单复选框 + 富文本协议链接）、BottomActions（合计 + 提交按钮）、AtToast（taro-ui 轻提示）。均见 order-confirm/components/。
- 关键交互：
  1. useReady 读本地 pendingOrder：有商品则渲染；无则 toast「订单数据异常，请重新选择商品」后回首页。
  2. useDidShow 读 selectedAddress 缓存回填，否则取默认地址；点地址卡 → navigateTo address-list?select=true。
  3. 切换配送时间 / 支付方式 / 填备注为本地 state；商品或地址变化触发 orderPreview 重算（防抖 + 序号防竞态）。
  4. 提交：依次校验 地址 → 商品 → 条款 → 置 loading → 调 createOrder 变更（回传 preferredCouponId / ticketRedeemCount，金额以服务端预检与引擎核算为准，携带 clientRequestId 幂等键）→ 清 pendingOrder → toast「订单创建成功」→ 跳转 order-detail?orderId=xx；失败 → toast 后端错误并停留本页。
  5. 配送时间选项来自 client deliverySlots 查询（请求失败回退兜底文案：立即配送(30分钟内)/上午(9:00-12:00)/下午(14:00-18:00)/晚上(18:00-21:00)）。
  6. 复购来源：进入本页时商品/地址来自历史订单模板，商品按当前营销链路重算价（不沿用历史成交价），水票/优惠券需当期重新选择（F-ORD-025）。
- 状态与标签：
  - 空态：地址为空时地址卡显示「请选择收货地址」并引导添加。
  - 加载态：预检 loading；提交中按钮显示「提交中...」且禁用。
  - 错误态：toast（订单数据异常 / 加载失败 / 创建失败 / 后端校验信息 / 预检失败可重试）。
  - 禁用态：loading 期间提交按钮 disabled 防重复提交。
  - 订单状态：本页创建的订单落入「待支付」（R-ORD-01，G09 已修复）。
- 关键数据字段：地址快照（联系人 / 电话 / 省市区+详细地址 / 楼层 / 默认标记）、商品快照（order_items：商品、规格、数量、成交单价 unitPriceCents、priceSource、划线目录价）、配送时段 deliveryTimeSlot、支付方式 paymentMethod、备注 remark、金额字段（amount 商品金额 / promotion 满减 / firstOrderDiscount 首单立减 / coupon 优惠券 / ticketRedeemCount 水票桶数 / deliveryFeeCents 配送费 / 水桶押金 / 实付合计）、服务端预检返回（priceSource / unitPriceCents）、clientRequestId 幂等键。
- 页面文案：「请选择收货地址」「选择地址」「默认」「共 N 件」「立即配送」「上午」「下午」「晚上」「微信支付」「推荐」「免配送费」「已优惠 ¥x」「提交订单」「提交中...」「我已阅读并同意《用户服务协议》和《隐私政策》」「请选择收货地址」「订单中没有商品」「请同意服务条款」「订单创建成功」「库存不足」「订单数据异常，请重新选择商品」。
- 设计要点/禁忌：地址卡须为「紧凑两行 + 白卡无内嵌卡片」；配送时段芯片选中态 = 主色描边 + tint 底；金额明细区「营销优惠/水票抵扣」用减项红色（-¥x），「赠品行」显示 ¥0.00；提交按钮 loading 态文案固定「提交中...」；条款未勾选不得提交；同一时刻只能有一个提交请求（防重）。
- 备注：F-ORD-023（订单计价与熟客分组价）在本页以「单价按登录用户分组价解析展示（有则展示熟客价 + 划线目录价）」形态呈现，2026-08 已实现（orderPreview 返回 priceSource/unitPriceCents）；代客下单手动改价的订单层兜底不在本页。缺口：G02（订单列表入口数据 mock，与本页无关）；开放问题：多商品结算复用本页（已实现，R-ORD-05 items 化）。

## 页面 2：用户端 · 购物车（结算）页（建议文件名 cart.html）
- 功能编号：F-ORD-004 [已实现]（多商品下单（购物车结算））
- 所属端：用户端小程序
- 页面入口与跳转：入口「我的」/首页购物车入口（pages/cart，本地存储）；跳转 → 确认订单页（order-confirm，结算时组装多商品明细）。
- 布局结构（从上到下逐行）：
  1. 顶部导航栏（返回 + 标题「购物车」+ 管理/编辑入口，可选）。
  2. 商品列表：每行 商品图 + 名称 + 规格 + 单价 + 数量步进器 + 勾选圈。
  3. 底部结算栏：全选勾选 + 已选合计 + 「结算」按钮。
- 组件清单（具体形态）：商品行（勾选 + 图 + 名称规格 + 单价 + 数量步进）、全选控件、底部结算栏（合计 + 结算按钮）、空态插画 + 「去逛逛」。数据由 utils/cart（本地存储合并/勾选/结算）驱动。
- 关键交互：
  1. 勾选/取消商品、全选切换 → 实时重算已选合计。
  2. 调整数量 → 实时重算小计与合计。
  3. 点「结算」→ 组装多商品明细 → 进入确认订单页（复用 F-ORD-001）。
- 状态与标签：
  - 空态：购物车为空时提示并引导去购物。
  - 禁用态：未选任何商品时结算按钮禁用。
  - 缺货态（提交后由确认页反馈）：缺货项标红提示。
- 关键数据字段：商品（productId / 名称 / 规格 / 单价 / 数量 / 勾选状态 / 库存）、已选合计。
- 页面文案：「购物车」「结算」「合计」「去逛逛」「以下商品库存不足:xxx」。
- 设计要点/禁忌：数量步进器需限制库存上限；勾选态与合计须强关联；结算栏固定在底部安全区之上。
- 备注：购物车为 F-PRO-004（商品域）能力，本地存储（pages/cart + utils/cart）；F-ORD-004 的核心链路在确认订单页（多商品 items）。缺口：G03 已解决（单商品下单限制——items 化后单商品 = items 单元素）。

## 页面 3：用户端 · 我的订单列表页（建议文件名 order-list.html）
- 功能编号：F-ORD-002 [已实现]（订单列表）、F-ORD-005 [已实现]（「立即支付」入口）、F-ORD-006 [已实现]（「取消订单」入口）、F-ORD-025 [规划中]（「再来一单」入口）
- 所属端：用户端小程序
- 页面入口与跳转：入口「我的」页订单入口；下单成功跳转亦到达。跳转 → 订单详情（点订单卡片）、确认订单页（「再次购买/再来一单」写 pendingOrder）、支付发起（「立即支付」）。
- 布局结构（从上到下逐行）：
  1. 顶部状态 Tab 栏：全部 / 待付款 / 待配送 / 配送中 / 已完成（2026-10 移除「待收货」Tab；「已取消」在「全部」中以状态标签呈现）。
  2. 订单卡片列表（每卡）：
     - 第 1 行：订单号 + 状态标签 + 下单时间。
     - 第 2 行：商品图 + 名称 + 规格 + 优惠价（有营销价时划线目录价）× 数量。
     - 第 3 行：收货人 + 电话 + 地址。
     - 第 4 行：实付金额（displayCents，有订单层优惠时标注「已优惠 ¥x」）+ 操作按钮组。
  3. 底部安全区。
- 组件清单（具体形态）：AtTabs（顶部状态栏）、AtCard（订单卡）、AtTag（状态标签）、AtButton（操作按钮组）、AtIcon、AtToast；金额格式化 displayCents（utils/money）。
- 关键交互：
  1. componentDidShow / 下拉刷新重载第一页。
  2. 切换 Tab 重置分页并按状态过滤（statuses 为空 = 全部；「待配送」口径 = 待派单 + 待配送）。
  3. 触底加载下一页（pageSize=10），末尾显示「没有更多订单了」。
  4. 按状态渲染操作：待付款 → 「取消订单」+「立即支付」；待配送 → 「查看详情」+「取消订单」；配送中 → 「查看详情」；已完成 → 「再次购买」（「删除订单」已按 G21 裁剪）。
  5. 「立即支付」调 createOrderPayment（假支付自动完成 / 未配置提示）；「取消订单」调真实 cancelOrder 后刷新；「再次购买」写入 pendingOrder 并跳 order-confirm。
- 状态与标签：
  - 空态：「暂无订单」+「去逛逛」按钮。
  - 加载态：「加载中...」。
  - 错误态：toast「获取订单列表失败」。
  - 禁用态：加载中禁止重复拉取。
  - 状态标签：待付款 / 待配送 / 配送中 / 已完成；已取消（在「全部」Tab 内以标签呈现）；无「待收货」标签/操作。
- 关键数据字段：订单号、状态标签、下单时间、商品图/名/规格/优惠价/划线价 × 数量、收货人/电话/地址、实付金额 displayCents、订单层优惠（「已优惠 ¥x」）、分页游标。
- 页面文案：「全部」「待付款」「待配送」「配送中」「已完成」「取消订单」「立即支付」「查看详情」「再次购买」「已优惠 ¥x」「暂无订单」「去逛逛」「加载中...」「获取订单列表失败」「没有更多订单了」「订单已取消」。
- 设计要点/禁忌：卡片第一行订单号可截断但需完整可查；配送中订单仅「查看详情」，不得出现「确认收货」（该中间态已取消，R-ORD-11）；已完成订单直接呈现「已完成」；金额展示需精确到分。
- 备注：状态 Tab 口径已与 7 态状态机对齐（2026-10：「待收货」Tab 移除，送达即完成）。缺口：—（G02/G21 已解决）。开放问题：「再来一单」是否对进行中订单开放（R-ORD-12）。

## 页面 4：用户端 · 订单详情页（建议文件名 order-detail.html）
- 功能编号：F-ORD-003 [已实现]（订单详情）、F-ORD-005 [已实现]（「立即支付」）、F-ORD-006 [已实现]（「取消订单」）、F-ORD-007 [已实现]（「评价/查看评价」）、F-ORD-008 [部分实现]（催单已实现 / 联系客服规划）、F-ORD-025 [规划中]（「再来一单/再次购买」）
- 所属端：用户端小程序
- 页面入口与跳转：入口 订单列表点击订单；下单成功 redirectTo。跳转 → 支付发起（「立即支付」）、评价页（order-review）、确认订单页（「再次购买/再来一单」）、拨号（送水工电话 / 客服）。
- 布局结构（从上到下逐行）：
  1. 状态区：状态标签（待付款 / 待配送 / 配送中 / 已完成 / 已取消）+ 进度条（下单 → 支付 → 派单 → 配送 → 完成）。
  2. 收货地址与联系人卡。
  3. 商品信息卡（图 / 名 / 规格 / 优惠价 + 划线价 × 数量）。
  4. 配送信息卡（送水工姓名 / 电话可拨打 / 实时位置入口，跟踪数据为模拟 G22）。
  5. 费用明细卡（原价合计 / 营销优惠明细（满减·首单立减·优惠券）/ 配送费 / 水桶押金 / 实付合计）。
  6. 订单信息卡（订单编号可复制、下单 / 支付等节点时间）。
  7. 操作记录时间线（AtTimeline）。
  8. 底部操作区（按状态显示：取消订单 / 立即支付 / 查看配送 / 再次购买 / 评价）。
- 组件清单（具体形态）：AtCard、AtIcon、AtButton、AtToast、AtTag、AtTimeline（时间线）、AtProgress（进度条）、状态步骤条、复制订单号条目。
- 关键交互：
  1. componentDidMount 读 orderId → 加载详情（真实 API 优先，mock 回退）；orderId 缺失 → toast「订单ID缺失」并返回。
  2. 点「复制订单号」→ 写入剪贴板并 toast「复制成功」。
  3. 按状态渲染操作按钮集（见「状态与标签」）。
  4. 「立即支付」→ createOrderPayment（假支付自动完成 / 未配置提示「支付功能待接入」）。
  5. 催单 / 联系客服见 F-ORD-008（催单已实现，联系客服目标形态）。
- 状态与标签：
  - 状态操作集合：待支付 = 「取消订单」+「立即支付」；待配送 = 「再次购买」；配送中 = 「查看配送」+「催单」（催单按钮非配送中不展示）；已完成 = 「评价/查看评价」+「再次购买」+「继续购物」；已取消 = 「再次购买」。
  - 空态：orderId 缺失提示并返回。
  - 加载态：「加载中...」。
  - 错误态：toast 加载失败。
  - 禁用态：非配送中不展示催单按钮。
  - 时间线节点：下单 → 支付 → 派单 → 配送 → 「已送达」→「订单完成」（送达即完成，无「确认收货」节点）。

## 订单金额构成
> 金额以分存储与计算、服务端校验（R-MON-01）；下单时快照落库，后续配置变更不影响已生成订单。费用明细卡按以下行自上而下展示，减项用红色「-¥x」，实付合计突出。

| 明细行 | 口径 | 展示条件 | 文案 / 展示形式 |
| --- | --- | --- | --- |
| 商品金额（原价合计 / 按成交单价计） | 各商品成交单价 × 数量之和；成交单价按 R-MKT-02 计价链路解析（熟客价 / 特价 / 新人价），有营销价时商品卡展示优惠价 + 划线目录价 | 始终展示 | 商品金额；无优惠时「原价合计 = 实付合计」 |
