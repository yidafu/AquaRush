# 07 用户与账户域 页面规格

> 来源：`PRD/07-user.md`（F-USR-001~006、010~011、020~023）。本规格仅供 HTML UI 设计稿使用；功能编号与状态以 PRD §1.1 清单为准。
> 端划分：用户端小程序（微信小程序）/ 送水工端 App（delivery-app，React Native）/ 管理后台（Web）。
> 覆盖页面共 15 个（用户端 6、送水工端 3、管理后台 6）。

## 全局结论（PRD §3.3 展示约定还原）

**「不使用 Tab / 使用 Tab」最终结论（以文档当前正文为准，v0.17~v0.19 反复已收敛）**
- **列表页——不使用 Tab 页切换展示**：账号列表 / 送水工列表统一以「用户类型」过滤参数（下拉 Select）筛选角色；用户列表为普通用户单类型，保持「搜索 + 分组筛选」。
- **详情页——使用 Tab 切换展示**（2026-09 起）：
  - 账号详情（`users/accounts/:id`）由「纵向区块」改为 **Tab 布局**，按角色渲染两套 Tab。
  - 用户详情（`users/:id`）保持 **Tab 布局**；PRD v0.15「详情页纵向区块」表述**作废**。
- 排除项：F-USR-004 主题设置 **[已移除]**（V1.0 UI 规范移除多套主题，固定品牌主色 `#3A9BD9`，无 theme-settings 页、我的页无「主题设置」入口）。本规格不产出该页设计稿。

## 页面 1：用户端小程序 · 微信登录授权（**不单独出页**——落在「我的」页内，见 my.html 状态三）
> **落地方案（2026-10-09 决策）**：不产出独立登录页，改为「我的」页内的**半屏授权引导弹层**，由用户**主动点击需登录动作**触发，非启动强制弹窗。
> ⚠️ **与 PRD 字面口径的张力**：PRD `07-user.md §F-USR-001` 写的是「静默微信登录（**免授权弹窗**，code 换 token）」，规格原文更写明「禁止设计授权弹窗页」。
> 调和口径：**登录本体仍是静默的**（启动 code 换 token，不弹窗、不拦截浏览）；弹层只承载「**手机号 + 订阅消息**」这类**需要用户手势的授权补充**，且仅在用户主动触发需登录动作时出现。若须严格贴合 PRD 字面，可把弹层降级为纯 toast +「正在登录...」。
- 功能编号：F-USR-001 [已实现]
- 所属端：用户端小程序
- 页面入口与跳转：**无独立登录页**，登录态在全局与「我的」页呈现。触发点：① app 启动 `app.tsx` 初始化（initSilentLogin）；② app onShow（checkLoginStatus）；③ network 拦截器 401 自动刷新并重试；④ 我的页未登录点击用户区（handleWeChatLogin）。
- 布局结构：
  1. 全局加载层：启动静默登录（无页面 UI，仅 toast）。
  2. 我的页用户区（未登录态）：头像占位 + 文案「点击头像登录」+「游客」昵称。
  3. toast 层：登录中「正在登录...」/ 成功「登录成功」/ 失败「登录失败」/ 网络异常「网络连接失败，请检查网络设置」。
- 组件清单：UserSection、AtAvatar、AtToast（均 `my/` 下，taro-ui）。设计稿建议以「我的页用户区（游客态 / 已登录态）」两张状态图呈现，不单独出登录页。
- 关键交互：
  1. 冷启动 silentLogin：已有 token 先 checkAndRefreshToken 校验，无效则 Taro.login 取 code → REST `/api/auth/wechat/login` → 存 token+userInfo；无 token 直接 code 换 token。
  2. 请求 401 → network 拦截器调 silentLogin 后自动重试原请求。
  3. 我的页未登录点击头像 → 显示「正在登录...」→ 成功 toast「登录成功」并回填头像/昵称。
  4. 首次进入后端自动创建用户并回填 userInfo。
  5. 游客可浏览商品；下单等需登录操作时引导登录后**回跳原页面**。
- 状态与标签：
  - 空态/游客态：昵称显示「游客」+「点击头像登录」；订单角标全 0。
  - 加载态：toast「正在登录...」。
  - 错误态：toast「登录失败」/「网络连接失败，请检查网络设置」。
  - 禁用态：登录请求单飞（silentLoginPromise），防并发重复请求（同一时刻仅一个登录请求）。
- 关键数据字段：token、userInfo（头像 avatar、昵称 nickname、手机号 phone）、openid。
- 页面文案：`点击头像登录`、`游客`、`正在登录...`、`登录成功`、`登录失败`、`网络连接失败，请检查网络设置`。
- 设计要点/禁忌：**登录本体免授权弹窗**（不调用 `wx.getUserProfile`，code 换 token 属静默登录），**无独立登录页**；游客态不得拦截浏览（可自由浏览商品）。
  - 授权引导弹层仅在用户**主动点击需登录动作**时出现（结算 / 我的订单 / 资产 / 收藏 / 地址），关闭后停留游客态，不做强制拦截；登录成功后就地返回原动作，不跳页。
  - 协议未勾选时用 `.weui-toptips` 拦截并中止；拒绝授权降级为「仅站内消息」，订单进度仍可在消息中心查看。
- 备注：无缺口关联。R-AUTH-01/02/03。目标形态：token 刷新由简化实现升级为 refreshToken（现状为 checkAndRefreshToken 校验）。

## 页面 2：用户端小程序 · 个人中心（我的）（建议文件名 my.html）
- 功能编号：F-USR-002 [已实现]
- 所属端：用户端小程序（tabBar 页）
- 页面入口与跳转：
  - 入口：tabBar「我的」。
  - 订单区点击 → `order-list?tab=类型`（类型：pending_payment 待付款等）。
  - 服务区 → `favorites`（我的收藏）/ `address-list`（收货地址）/ 拨打客服 400-800-8888 / `feedback`（意见反馈）/ `feedback-records`（反馈记录）/ `about`（关于我们）。
  - 消息中心 → `message-center`（**目标形态，未实现**，F-NTF-002）。
  - 用户区点击 → 未登录先微信登录；已登录弹 `AvatarNicknameForm` 编辑头像昵称。
  - 「退出登录」→ 确认弹窗 → authService.logout（调后端并清本地）。
- 布局结构（从上到下）：
  1. **用户信息区 UserSection**：头像（无图显示默认头像字母）+ 昵称 + 手机号 + 右箭头 `›`；未登录显示「游客」+「点击头像登录」。
  2. **订单区 OrderSection**：「我的订单」卡标题 + 四入口 全部 / 待付款 / 待配送 / 配送中，各带数字角标 AtBadge（>99 显示 `99+`）；点击跳 `order-list?tab=类型`。（切片目标为 待付款/待发货/配送中/已完成/已取消 五入口，现状为四入口，见备注）
  3. **常用服务区 ServiceSection**（列表项，均带 `›`）：我的收藏 / 收货地址 / 客服中心（拨号）/ 意见反馈 / 反馈记录 / 关于我们。
  4. **消息中心入口**（目标形态，未实现）：带未读角标，未读数与 F-NTF-002 联动。
  5. **其他卡**：「设置」列表项 → 现状指向不存在的 settings 页（**死链**）；「退出登录」入口（已补充）。
  6. 头像昵称表单弹层 AvatarNicknameForm；底部安全区。
- 组件清单：UserSection、OrderSection、ServiceSection、AvatarNicknameForm、AtCard、AtList、AtListItem、AtBadge、AtAvatar、AtToast、CustomIcon（taro-ui）。
- 关键交互：
  1. useDidShow 加载用户信息与订单统计；未登录回退游客态（角标全 0 且不发起需登录请求）。
  2. 点击订单入口 → navigateTo `order-list?tab=对应类型`，对应 Tab 高亮。
  3. 点击服务项 → 收藏/地址/反馈/反馈记录/关于；客服中心 makePhoneCall 拨打 400-800-8888。
  4. 点击用户区 → 未登录先微信登录；已登录弹 AvatarNicknameForm 编辑头像昵称。
  5. 下拉刷新重新加载用户信息与订单统计并停止下拉动画。
- 状态与标签：
  - 空态：无头像显示默认头像字母；无订单角标不显示数字；游客态角标全 0。
  - 加载态：页面「加载中...」。
  - 错误态：获取用户信息失败回退游客态。
  - 禁用态：登录中禁用重复触发。
  - 角标标签：`99+`（>99）。
- 关键数据字段：用户信息（头像/昵称/手机号）；订单统计 `myOrderStatistics`：total / pendingPayment（待付款）/ pendingDispatch + pendingDelivery（待配送口径=待派单+待配送）/ delivering（配送中）/ completed / cancelled / refunded（售后=已退款）。
- 页面文案：`我的`、`我的订单`、`全部`、`待付款`、`待配送`、`配送中`、`我的收藏`、`收货地址`、`客服中心`、`意见反馈`、`反馈记录`、`关于我们`、`设置`（死链）、`退出登录`、`登录成功`、`个人资料更新成功`。
- 设计要点/禁忌：
  - 用户区、订单区、服务区、其他卡、底部安全区自上而下分区清晰，卡片间距统一。
  - 「设置」为死链，但 PRD 未明确删除；设计稿可保留占位并标注「现状死链，待清理」。
  - 消息中心为**目标形态**，设计稿需呈现但标注未实现。
- 备注：**入口归属已收口（2026-10-09 决策）**——水桶账户 / 水票 / 套餐 / 积分 / 优惠券**不再在「我的」平铺**，统一聚合为**单一「我的资产」入口**（顶部单元格，副行显示券/票/套餐/积分/桶数摘要；**无余额**——用户储值不做，2026-10-09 合规决策），点击进入 `04-marketing/assets.html` 后再下钻。  - 理由：`07-user.md` 未定义券/票入口、而 10-marketing.md 有定义，两域口径不一致；聚合到资产页后「我的」页只剩一个资产入口，消除重复入口与归属争议。
  - 常用服务由 13 项收敛为 **8 项**：我的收藏 / 收货地址 / 周期订购 / 会员中心 / 消息中心 / 意见反馈 / 反馈记录 / 关于我们。
  - 订单入口现状四入口 vs 切片五入口不完全一致，目标按切片补全。漏斗：G02 已解决（2026-08-18，G31），角标已接真实统计。

## 页面 3：用户端小程序 · 资料编辑（建议文件名 profile-edit.html）
- 功能编号：F-USR-003 [已实现]
- 所属端：用户端小程序
- 页面入口与跳转：入口①我的页用户区弹 `AvatarNicknameForm`（仅头像昵称）；②独立 `profile-edit` 页支持完整资料编辑。保存成功 1.5s 后 navigateBack 返回上一页。
- 布局结构（从上到下）：
  1. **顶部栏**：左「取消」/ 中标题「编辑资料」/ 右「保存」（有修改才可点，无修改置灰）。
  2. **头像区**：AvatarUpload（相册选择 / 拍照上传，带进度反馈与失败重试）。
  3. **基本信息**：昵称输入（2-20 字符）；手机号输入（type=phone，11 位）。
  4. **账户信息只读区**：用户ID / 会员等级 / 积分 / VIP到期（依赖 UserInfo 接口字段，现状可能为空或渲染异常；**账户余额不再展示**——用户储值不做，2026-10-09 决策）。
  5. **底部安全区**。
- 组件清单：AvatarUpload、AtForm、AtInput、AtButton、AtToast、AtDivider（taro-ui）。
- 关键交互：
  1. componentDidShow 加载用户信息；未登录 toast「请先登录」后 1.5s 返回。
  2. 修改字段实时校验并标记 hasChanges；清除对应字段错误。
  3. 头像选择 → 上传 → 进度反馈；失败行内显示错误并可重试。
  4. 保存：validateForm → `updateProfile` 变更（avatarUrl 映射为 avatar 字段）→ toast「保存成功」→ 1.5s navigateBack。
- 状态与标签：
  - 空态：未登录提示后返回。
  - 加载态：页面「加载中...」/ 保存「正在保存...」。
  - 错误态：校验错误行内展示 + toast「请修正表单错误」。
  - 禁用态：无修改时「保存」置灰；loading 期间表单禁用。
  - 标签：会员等级 / VIP到期。
- 关键数据字段：头像 avatarUrl、昵称 nickname、手机号 phone；只读区 userId、level、balance、points、isVip（现状接口字段已注释）。
- 页面文案：`编辑资料`、`取消`、`保存`、`请输入昵称`、`昵称至少2个字符`、`昵称不能超过20个字符`、`昵称只能包含中文、英文、数字、下划线和空格`、`请输入手机号`、`请输入正确的手机号格式`、`没有修改内容`、`保存成功`、`请先登录`、`请修正表单错误`、`正在保存...`。
- 设计要点/禁忌：账户信息只读区是否保留为**开放问题**（UserInfo 接口 balance/points/level/isVip 已注释），设计稿需标注「可能为空/待确认保留」。手机号输入键盘为数字键盘。
- 备注：无缺口关联；R-AUTH-01/03。开放问题：「账户信息」只读区待确认是否保留。

## 页面 4：用户端小程序 · 意见反馈（建议文件名 feedback.html）
- 功能编号：F-USR-005 [已实现]
- 所属端：用户端小程序
- 页面入口与跳转：入口我的页「常用服务 → 意见反馈」；页脚「我的反馈记录 ›」→ `feedback-records`。提交成功后清空表单（不跳转）。
- 布局结构（从上到下）：
  1. **头部**：标题「意见反馈」+ 副标题「您的意见对我们很重要」。
  2. **反馈类型选择**：胶囊单选（必选，6 类）。
  3. **反馈内容**：Textarea（≥10 字，≤500 字，带字数统计）。
  4. **上传图片**（选填，≤3 张，相册/拍照，可删除）。
  5. **提交按钮**：「提交反馈」/「提交中...」。
  6. **底部说明**：处理时效「我们会在1-2个工作日内处理您的反馈」+ 客服热线（店铺信息动态读取，未配置兜底常量）+「我的反馈记录 ›」入口。
- 组件清单：Textarea、Button、Image、Taro.showToast、类型胶囊（type-option）、图片上传区（image-upload）。
- 关键交互：
  1. 选择类型 → 输入内容 → 选图/删图（超 3 张不再增加）。
  2. 提交：校验类型/内容长度 → 图片先经 FileUploadService 上传为平台存储 fileUrl → 调用 `submitFeedback` 落库 → toast「提交成功，感谢您的反馈」→ 清空表单。
  3. 提交需登录态（服务端 `isAuthenticated()` 强制，userId 取登录主体，防越权）。
  4. 幂等：提交中按钮 loading 且禁用，仅一次提交。
- 状态与标签：
  - 空态：表单初始为空，字数统计 0/500。
  - 加载态：提交按钮「提交中...」+ loading 禁用。
  - 错误态：提交失败 toast「提交失败，请重试」。
  - 禁用态：提交中禁用按钮防重复。
  - 类型胶囊 6 类：产品质量问题 / 配送服务问题 / 小程序使用问题 / 功能建议 / 投诉建议 / 其他问题。
- 关键数据字段：type（反馈类型）、content（内容 10-500 字）、images（≤3 张 fileUrl）、contact（联系方式，可选）、userId（登录主体）。
- 页面文案：`意见反馈`、`您的意见对我们很重要`、`请选择反馈类型`、`请输入反馈内容`、`反馈内容至少输入10个字`、`提交反馈`、`提交中...`、`提交成功，感谢您的反馈`、`提交失败，请重试`、`我们会在1-2个工作日内处理您的反馈`、`我的反馈记录 ›`。
- 设计要点/禁忌：类型为**胶囊单选**（非下拉）；图片区最多 3 张并显示删除角标；客服热线动态读取（文案与「关于页」一致口径）。
- 备注：G04 已实现（2026-08）。规则引用：—。

## 页面 5：用户端小程序 · 反馈记录（建议文件名 feedback-records.html）
- 功能编号：F-USR-005 [已实现]（处理结果回传闭环，2026-08）
- 所属端：用户端小程序
- 页面入口与跳转：入口①我的页「常用服务 → 反馈记录」；②意见反馈页页脚「我的反馈记录 ›」。列表项不跳转，直接展示处理结果。
- 布局结构（从上到下）：
  1. **顶部栏**：返回 + 标题（建议「我的反馈记录」）。
  2. **列表**：按提交时间倒序分页；每条含 类型 / 内容 / 状态 Tag / 提交时间 / 图片缩略图；已处理或处理中记录追加「处理结果 + 处理人 + 处理时间」区。
  3. **加载更多**：AtLoadMore（触底加载更多）；下拉刷新。
- 组件清单：BasePageLayout、AtLoadMore、状态 Tag（待处理 橙 / 处理中 蓝 / 已处理 绿）。
- 关键交互：
  1. 进入 → 列表分页加载**本人**反馈（`myFeedbacks`，仅返回本人数据，按提交时间倒序）。
  2. 已处理/处理中展示处理结果与处理人、处理时间；待处理记录不展示处理区。
  3. 下拉刷新；触底加载更多。
  4. 处理结果回传闭环：用户提交 → 后台处理（F-OPS-003，12-operations-config.md）→ 本页即时可见状态与处理结果。
- 状态与标签：
  - 空态：无数据空态「暂无反馈记录」。
  - 加载态：加载中 / 加载更多。
  - 错误态：加载失败可重试。
