# 13 通知与消息域 页面规格

> 来源：`PRD/13-notification.md`（只读提取，不修改原文）。功能状态标注沿用 PRD（[已实现]/[部分实现]/[规划中]）；本域不涉及金额。

## 页面 1：用户端 · 订阅消息授权（建议文件名 subscribe-auth.html）
- 功能编号：F-NTF-001 [已实现]（投递链路已接通，UI 为目标形态）
- 所属端：用户端小程序
- 页面入口与跳转：下单确认页(order-confirm)提交前订阅授权弹窗/组件；消息中心「订阅管理」区(F-NTF-002)
- 布局结构：
  1. 确认订单页提交前订阅授权弹窗/组件（一次性/长期模板按微信规范，默认展示需订阅的场景）
  2. 消息中心「订阅管理」区：列出可订阅场景与授权状态
- 组件清单：订阅授权组件（基于 Taro.requestSubscribeMessage）
- 关键交互：
  1. 提交订单时请求订阅授权
  2. 用户接受 → 记录订阅状态并关联模板
  3. 订单节点触发 → 消息网关调订阅消息发送服务推送（access-token 缓存、失败重试幂等）
  4. 未授权 → 不推送，节点信息在站内订单详情/消息中心可见
- 状态与标签：已授权 / 未授权 / 已拒绝 / 达次数上限（不再弹）；场景开关启用/停用
- 关键数据字段：可订阅场景、模板 ID、授权状态、授权剩余次数
- 页面文案：各节点文案按微信模板（下单成功 / 配送员接单 / 开始配送 / 送达确认 / 退款结果 / 催单）；未授权降级站内查看，不弹引导文案
- 设计要点/禁忌：授权弹窗须在提交订单时机触发；已拒绝或达上限不再打扰；未授权不阻塞下单
- 备注：投递链路已实现，UI 为目标形态；缺口 G08；场景与模板 ID 由后台配置(F-NTF-005)驱动

## 页面 2：用户端 · 消息中心（建议文件名 message-center.html）
- 功能编号：F-NTF-002 [已实现]
- 所属端：用户端小程序
- 页面入口与跳转：我的页(my)「消息中心」入口 + 未读角标；点击跳订单详情(order-detail) / 公告详情(notice-detail) / 反馈记录(feedback-records)
- 布局结构：
  1. 顶部第一行 Tab（类型）：全部 / 订单 / 系统；第二行 Tab（已读状态）：全部 / 未读 / 已读（两维度组合过滤）
  2. 消息列表：图标(按类型) + 标题 + 摘要(2 行省略) + 相对时间；未读加红点/高亮
  3. 列表项操作：左滑或长按「标为已读/删除」（目标形态）
  4. 顶部「全部已读」；空态「暂无消息」
- 组件清单：List/AtList、Badge(未读角标)、AtToast、SwipeAction、Tabs
- 关键交互：
  1. 我的页 onShow 拉取未读数，入口显示角标
  2. 进入消息中心 → 分页拉取本人消息（仅本人，R-AUTH-02）+ 下拉刷新
  3. 点击消息 → 标已读 → 跳转关联页（订单详情 / 公告详情 / 反馈记录）
  4. 全部已读 → 批量置已读 → 角标清零
- 状态与标签：已读 / 未读（高亮）；类型 全部/订单/系统（消息来源含优惠券即将过期 COUPON_EXPIRING）；空态「暂无消息」
- 关键数据字段：消息类型、标题、摘要、时间、已读状态、关联单号/页面
- 页面文案：「暂无消息」「全部已读」「加载失败，请重试」「消息中心」
- 设计要点/禁忌：双行 Tab 组合筛选需清晰；未读高亮与角标实时联动（WebSocket 推送与轮询按幂等键去重）；仅本人可见
- 备注：已实现；缺口 G66 已解决；F-NTF-007 目标新增「提醒」分类（见页面 7）

## 页面 3：送水工端 · 实时推送（任务页/系统通知）（建议文件名 task-push-banner.html）
- 功能编号：F-NTF-003 [已实现]
- 所属端：送水工端 App（RN）
- 页面入口与跳转：任务首页(订单 Tab)接收推送即时更新；系统通知栏点击 → 任务详情
- 布局结构：
  1. 任务列表实时更新（新订单/派单即时置顶）
  2. 系统通知栏提醒（前台本地通知，已实现，替代应用内 toast 横幅）
  3. 锁屏/后台系统通知（目标形态，依赖推送凭证）
- 组件清单：WebSocket 客户端（RN 直连）、任务列表现有组件、expo-notifications 系统推送
- 关键交互：
  1. 登录后建立 WebSocket 长连接（断线指数退避重连）
  2. 后端事件总线 → 推送网关 → 按幂等键分发（单号+事件类型+事件时间）
  3. 前端按幂等键去重渲染，任务列表即时更新
  4. 离线/弱网 → 定时轮询（默认 30s）+ 离线补发
  5. 锁屏/后台 → 系统推送提醒（依赖推送凭证，目标形态）
- 状态与标签：连接中/重连中提示；无网络时轮询兜底；推送场景（新订单广播 / 被派单 / 订单取消 / 用户催单 / 配送超时 / 支付超时）
- 关键数据字段：事件类型、关联订单号、事件时间、幂等键
- 页面文案：推送横幅按事件（「新订单」「被派单」「用户催单」等）
- 设计要点/禁忌：未连接不阻塞主流程（降级轮询）；推送与轮询去重不重复渲染；前台横幅 + 通知栏列表 + 点击跳转订单详情
- 备注：已实现；缺口 G44 / G69（锁屏/后台远程推送依赖推送凭证，目标形态）

## 页面 4：送水工端 · 消息中心（建议文件名 driver-messages.html）
- 功能编号：F-NTF-004 [已实现]
- 所属端：送水工端 App（RN）
- 页面入口与跳转：我的页/任务页消息入口 + 未读角标；点击跳任务详情/订单详情
- 布局结构：
  1. 顶部 Tab：任务 / 系统（默认任务）；第二行已读状态 Tab（全部 / 未读 / 已读，组合过滤）
  2. 消息列表：图标(按事件类型) + 标题 + 摘要 + 相对时间；未读高亮
  3. 顶部「全部已读」；空态「暂无消息」
- 组件清单：FlatList、Badge、Toast(Alert)、Swipeable
- 关键交互：
  1. 我的页/任务页展示未读角标
  2. 进入消息中心 → 分页拉取本人消息
  3. 点击消息 → 标已读 → 跳转任务详情/订单详情
  4. 全部已读 → 角标清零
- 状态与标签：任务 / 系统；已读 / 未读（高亮）；空态「暂无消息」
- 关键数据字段：消息类型、标题、摘要、时间、已读状态、关联单号
- 页面文案：「暂无消息」「全部已读」「任务」「系统」
- 设计要点/禁忌：与实时推送同源（推送即时触达、消息中心可回溯）；仅本人可见（R-AUTH-02）
- 备注：已实现；缺口 G67 已解决

## 页面 5：管理后台 · 通知与订阅消息配置（建议文件名 system-config-notifications.html）
- 功能编号：F-NTF-005 [部分实现]
- 所属端：管理后台
- 页面入口与跳转：系统设置 → 通知与订阅消息（仅超级管理员，NOTIFICATION_WRITE）
- 布局结构：
  1. 模板列表：业务场景（下单通知/配送完成/催单/支付结果）/ 模板 ID / 状态（启用/停用）/ 说明 / 操作「编辑」
  2. 编辑弹窗：模板 ID、启用开关、参数映射说明
  3. 用户通知设置预览：用户端订阅设置说明（user_notification_settings）
  4. 扩展区（目标形态）：站内消息保留时长、RN 推送凭证状态（已配置/未配置，密钥不可在线编辑）
- 组件清单：Table、Modal、Form、Input、Switch、Alert
- 表单字段：
  - 模板 ID（Input，必填，6-64 位格式合法，粘贴自微信公众平台，占位「模板 ID 不能为空」）
  - 启用开关（Switch）
  - 参数映射说明（只读文本）
  - 站内消息保留时长（InputNumber，天，默认 90，目标形态）
- 关键交互：
  1. 进入页面 → 回显模板配置
  2. 编辑模板 ID/启用 → 保存 → 列表状态更新
  3. 发送链路（已接通）按模板发送订阅消息
- 状态与标签：模板 启用/停用/未设置；密钥类不在线配置（受 R-SYS-02 保护）
- 关键数据字段：业务场景、模板 ID、启用状态、保留时长、RN 凭证状态
- 页面文案：「模板 ID 不能为空」「模板 ID 格式不正确」「未设置」「仅超级管理员可写」
- 设计要点/禁忌：6 场景模板 ID + 启用开关；密钥类（appsecret、APNs/FCM）走环境变量不在线配置；修改留审计
- 备注：部分实现；缺口 G08 / G69；保留时长与 RN 凭证配置为目标形态

## 页面 6：管理后台 · 消息列表页（建议文件名 notifications-messages.html）
- 功能编号：F-NTF-006 [已实现]
- 所属端：管理后台
- 页面入口与跳转：通知与消息 → 消息列表（NOTIFICATION_READ，管理员/超管）
- 布局结构：
  1. 筛选区：消息类型（订阅消息/站内消息/推送）、接收人类型（用户/送水工）、关键字（接收人昵称/手机号/关联单号）、状态（全部/已读/未读）、时间范围（默认近 30 天）
  2. 消息表格：时间 / 类型(Tag) / 标题 / 摘要(省略) / 接收人 / 关联单号 / 状态(Tag 已读·未读) / 操作「详情」
  3. 详情弹窗：Descriptions 展示 标题/摘要全文/类型/通道/接收人/关联单号/发送时间/已读时间 + 微信通道状态（待发送/已发送/发送失败）+ 失败原因 + 微信消息 ID
- 组件清单：Table、Select、DatePicker、Input、Modal、Descriptions、Tag（参照日志页 F-LOG-003 模式）
- 表单字段：筛选条件；详情弹窗「重发」操作（FAILED/PENDING 的用户消息，PERMISSION_NOTIFICATION_WRITE 仅超管）
- 关键交互：
  1. 进入页面 → 默认近 30 天全部消息（分页 10/页）
  2. 组合筛选 → 表格刷新
  3. 点「详情」→ 弹窗展示全文与状态；失败消息可点「重发」（复用 R-NTF-01 全部门控）
- 状态与标签：已读 / 未读；类型 订阅消息/站内消息/推送；channel_status 待发送/已发送/发送失败
- 关键数据字段：时间、类型、标题、摘要、接收人、关联单号、状态、已读时间、channel_status、模板场景/页面/字段
- 页面文案：「暂无消息」「重发」「详情」
- 设计要点/禁忌：关联单号可点击跳订单详情（目标形态）；重发仅重试微信订阅消息通道（站内消息不重推）；无 NOTIFICATION_READ 不可进入
- 备注：已实现；缺口 G68 已解决

## 页面 7：用户端 · 补水与续购提醒（建议文件名 notification-reminder.html）
- 功能编号：F-NTF-007 [规划中]（2026-10 新增）
- 所属端：用户端小程序（含送水工端触达）
- 页面入口与跳转：消息触达（微信订阅消息 + 站内消息中心 message-center）；后台通知配置(F-NTF-005)开关各场景；一键复购复用 F-ORD-025、周期订购 F-ORD-026、水票商城 ticket-shop、充值页 recharge
- 布局结构：
  1. 订阅消息卡片：补水提醒（标题 + 「去下单/一键复购」跳转）；周期订购提醒（计划摘要 + 「确认/调整」）；余量/余额提醒（剩余量 + 「去购买」）
  2. 消息中心新增分类「提醒」（与订单/系统并列）
- 组件清单：订阅消息模板（补水/周期/余量/余额）+ 消息中心分类 Tab + 跳转配置
- 关键交互：
  1. 调度扫描（分页/游标，禁全表）→ 按用户用水周期/计划/余量/余额判定是否触发
  2. 命中且未超频率上限 → 经消息网关落库并推订阅消息；未授权/超上限 → 降级站内消息或跳过
  3. 用户点击 → 一键复购 / 进入周期订购 / 进入水票商城 / 充值页
  4. 场景开关与阈值由后台配置(F-NTF-005)
- 状态与标签：场景 启用/停用；未授权降级站内；超频率上限不发送
- 关键数据字段：场景类型、触发条件（用水周期/计划/余量/余额阈值）、频率上限（默认每 7 天≤1 条）、幂等键（用户+场景+期次）
- 页面文案：「您上次订水已 X 天，该补水了~」「下单失败，请手动处理」「剩余水票不足，去购买」「余额不足，去充值」
- 设计要点/禁忌：频率上限为防骚扰底线，须可配不可缺省为空；补水与周期订购提醒场景互斥（开放问题）；未授权不弹引导
- 备注：规划中；缺口 G82；依赖 F-NTF-001/002、F-ORD-025/026、F-MKT-007/010
