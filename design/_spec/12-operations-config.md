# 12 运营配置域 页面规格

> 来源：`PRD/12-operations-config.md`（只读提取，不修改原文）。金额一律以「分」存储与服务端计算校验、展示层转元（R-MON-01）；功能状态标注沿用 PRD（[已实现]/[部分实现]/[规划中]）。

## 页面 1：管理后台 · 首页轮播图配置（建议文件名 banners.html）
- 功能编号：F-OPS-001 [已实现]
- 所属端：管理后台
- 页面入口与跳转：运营配置 → 首页轮播；用户端首页轮播位(home，消费于 F-PRO-001)
- 布局结构：
  1. 顶部：「新建轮播」按钮
  2. 轮播列表：缩略图 / 标题 / 跳转目标 / 排序 / 时间窗 / 状态（启用/停用）/ 操作（新建/编辑/删除/上移下移）
  3. 新建/编辑弹窗：图片上传、标题/副标题、跳转链接、排序号、时间窗、启用开关
- 组件清单：Table、Modal、Form、Upload、Input、InputNumber、Switch、DatePicker、Popconfirm
- 表单字段：
  - 轮播图片（Upload，必传，建议 750×360，≤5MB，jpg/png/webp，占位「请上传轮播图片」）
  - 标题（Input，≤20 字，占位「新用户首单立减」）
  - 副标题（Input，选填，≤20 字）
  - 跳转链接（Select 类型：商品详情 / 自定义页面 [+ 商品选择 / 页面地址]）
  - 排序号（InputNumber，整数，唯一，占位「1」）
  - 时间窗（DatePicker.RangePicker，开始<结束，空=长期）
  - 启用（Switch）
- 关键交互：
  1. 上传图片 → 填写标题/跳转/排序/时间窗 → 保存启用；
  2. 上移/下移或编辑排序号调整顺序；
  3. 停用/到期 → 用户端该轮播位不再展示；
  4. 用户端首页 Swiper 按配置渲染
- 状态与标签：启用/停用；时间窗内/已过期；无轮播配置时用户端轮播位隐藏（是否回退默认运营图为开放问题）
- 关键数据字段：图片 URL、标题、副标题、跳转目标、排序号、开始/结束时间、启用状态
- 页面文案：「请上传轮播图片」「时间窗不合法」「新建轮播」「上移」「下移」
- 设计要点/禁忌：需提示图片规格（750×360）；排序号唯一；停用/已过期条目编辑置灰
- 备注：已实现；缺口 G61 已解决；跳转目标「指定分类筛选」因商品无分类概念暂不实现，外部链接为开放问题

## 页面 2：管理后台 · 公告管理（建议文件名 notices.html）
- 功能编号：F-OPS-002 [部分实现]（用户端展示已具备，后台维护链路未闭环）
- 所属端：管理后台
- 页面入口与跳转：运营配置 → 公告；用户端首页公告栏(home)、公告详情页(notice-detail，目标形态)
- 布局结构：
  1. 顶部：「新建公告」按钮
  2. 公告列表：标题 / 类型（Tag）/ 置顶标识 / 时间窗 / 状态（草稿/已发布/已停用）/ 发布时间 / 操作（新建/编辑/发布/置顶/停用/删除）
  3. 新建/编辑弹窗：标题、内容、类型、置顶、时间窗
- 组件清单：Table、Modal、Form、Input、TextArea、Switch、DatePicker、Popconfirm
- 表单字段：
  - 标题（Input，必填，≤50 字，占位「公告标题不能为空」）
  - 内容（TextArea，必填，≤2000 字，占位「公告内容不能为空」）
  - 类型（Select：平台公告 / 停水通知 / 活动预告）
  - 置顶（Switch）
  - 时间窗（DatePicker.RangePicker，开始<结束，可选）
- 关键交互：
  1. 新建公告（草稿）→ 编辑 → 发布（时间窗内生效）
  2. 置顶公告在公告栏最前展示
  3. 停用/到期 → 用户端不再展示
- 状态与标签：草稿 / 已发布 / 已停用；置顶标识；时间窗内/已过期
- 关键数据字段：标题、内容、类型、置顶、开始/结束时间、发布时间、状态
- 页面文案：「公告标题不能为空」「公告内容不能为空」「时间窗不合法」「发布」「置顶」「停用」
- 设计要点/禁忌：类型「停水通知」建议独立色标识；已停用公告不可再编辑（开放问题）
- 备注：部分实现；缺口 G62；用户端展示已具备、后台维护链路为目标形态；公告为站内内容，与订阅消息不同通道

## 页面 3：用户端 · 首页公告栏（建议文件名 home-notice.html）
- 功能编号：F-OPS-002 [部分实现]
- 所属端：用户端小程序
- 页面入口与跳转：首页顶部公告栏 → 公告详情页(notice-detail)
- 布局结构：
  1. 公告栏（HomeNoticeBar）：图标 + 最近 1 条公告标题（单行省略或跑马灯）+ 右箭头
  2. 无公告时整条隐藏
- 组件清单：NoticeBar、图标、点击跳转
- 关键交互：点击公告栏 → 进入公告详情；仅展示最近已发布公告，置顶排最前
- 状态与标签：有公告/无公告（隐藏）；停用/过期不展示
- 关键数据字段：公告标题、类型、发布时间、置顶
- 页面文案：「【停水通知】xx 小区今日 14:00-17:00 停水」等
- 设计要点/禁忌：公告栏高度克制，不挤压首页主内容；展示条数（默认最近 1 条）为开放问题
- 备注：部分实现；缺口 G62；展示入口已具备，数据源待后台配置闭环

## 页面 4：用户端 · 公告详情页（建议文件名 notice-detail.html）
- 功能编号：F-OPS-002 [部分实现]（目标形态）
- 所属端：用户端小程序
- 页面入口与跳转：首页公告栏(home) → 公告详情；返回首页
- 布局结构：
  1. 顶部导航：返回
  2. 标题区：标题 + 类型标签 + 发布时间
  3. 正文区：公告内容（富文本/纯文本）
- 组件清单：导航栏、文本区、Tag
- 关键交互：滚动阅读；长内容自动换行；可选分享
- 状态与标签：类型标签（平台公告 / 停水通知 / 活动预告）
- 关键数据字段：标题、内容、类型、发布时间
- 页面文案：「公告详情」「发布时间：2026-10-08」
- 设计要点/禁忌：正文排版清晰、行距舒适；标题与正文层级分明
- 备注：部分实现；缺口 G62；目标形态

## 页面 5：管理后台 · 意见反馈管理（建议文件名 feedbacks.html）
- 功能编号：F-OPS-003 [已实现]
- 所属端：管理后台
- 页面入口与跳转：运营配置 → 意见反馈；用户详情「意见反馈」Tab(F-USR-022)；用户端反馈页(feedback，F-USR-005)与反馈记录(feedback-records)
- 布局结构：
  1. 筛选区：反馈类型 Select、状态 Select（待处理/处理中/已处理）、联系方式关键字 Input、时间范围 RangePicker、「搜索」/「重置」
  2. 反馈列表：类型(Tag) / 内容(省略) / 联系方式 / 图片数 / 状态(Tag 着色) / 提交时间 / 操作「详情」
  3. 详情弹窗：类型/内容全文/图片(可预览)/联系方式/提交时间 + 处理区（处理结果、状态流转）
- 组件清单：Card、Space、Select、Input、DatePicker、Button、Table、Tag、Modal、Image、RangePicker
- 表单字段：
  - 处理结果（TextArea，≤500 字，选填）
  - 状态流转（Select/按钮：待处理 → 处理中 → 已处理）
- 关键交互：
  1. 进入页面 → 反馈列表加载（默认第 1 页，分页）
  2. 组合筛选/搜索/重置
  3. 打开详情 → 查看内容与图片 → 填写处理结果 → 流转状态
- 状态与标签：待处理 / 处理中 / 已处理（Tag 着色）；空态「暂无反馈」
- 关键数据字段：类型、内容、图片、联系方式、提交时间、状态、处理结果、处理人/时间
- 页面文案：「暂无反馈」「搜索」「重置」「已处理」「处理结果」
- 设计要点/禁忌：联系方式默认脱敏（开放问题）；已处理反馈不可再修改（开放问题）
- 备注：已实现；缺口 G63 / G04 已解决

## 页面 6：管理后台 · 店铺信息配置（建议文件名 store-profile.html）
- 功能编号：F-OPS-004 [规划中]
- 所属端：管理后台
- 页面入口与跳转：运营配置 → 店铺信息；用户端关于页(about，F-USR-006)、意见反馈页(feedback)客服热线
- 布局结构：
  1. 表单区：店铺名称、LOGO、客服电话、营业时间、店铺简介、关于我们
  2. 保存按钮 + 修改记录（审计）
- 组件清单：Form、Input、Upload、TimePicker、Button
- 表单字段：
  - 店铺名称（Input，≤20 字，占位「xx 桶装水」）
  - LOGO（Upload，图片上传）
  - 客服电话（Input，格式校验，占位「400-xxx-xxxx」）
  - 营业时间（TimePicker/RangePicker，如 08:00-20:00）
  - 店铺简介（TextArea，≤100 字）
  - 关于我们（TextArea，≤2000 字）
- 关键交互：进入页面回显当前配置 → 修改 → 保存 → 用户端关于页/反馈页更新；修改留审计日志
- 状态与标签：未配置时用户端按默认值兜底；回显/保存 loading；保存失败 toast
- 关键数据字段：店铺名称、LOGO、客服电话、营业时间、简介、关于我们、审计记录
- 页面文案：「客服电话格式不正确」「保存」「修改记录」
- 设计要点/禁忌：客服电话为骨架校验项；修改留痕（操作人/时间/前后值）需可见
- 备注：规划中；缺口 G62；用户端消费点：关于页/反馈页底部；目标形态

## 页面 7：管理后台 · 配送费规则配置（建议文件名 delivery-fee-rule.html）
- 功能编号：F-OPS-005 [已实现 2026-08]
- 所属端：管理后台
- 页面入口与跳转：运营配置 → 运费规则；订单域消费（R-MON-02，F-ORD-001/020）；用户端确认订单页费用明细
- 布局结构：
  1. 规则表单：免费楼层 + 楼层分档加价表（可增删档位）
  2. 保存按钮（二次确认）+ 修改记录（审计）
  3. 用户端说明：确认订单页按地址楼层展示运费/「免配送费」
- 组件清单：Form、InputNumber、Button、Table（分档行增删）、Modal.confirm
- 表单字段：
  - 免费楼层（InputNumber，整数 ≥0，默认 4，占位「4」）
  - 楼层分档加价表（可增删行：起始楼层 InputNumber ≥0、结束楼层 InputNumber（可空=以上）、加价金额 InputNumber 元 0-999 precision=2；默认示例 5-6 楼 2.00 / 7-9 楼 5.00 / 10 楼及以上 8.00）
- 关键交互：
  1. 进入页面 → 回显当前规则（未配置时回显默认 免费 4 楼 + 默认分档）
  2. 修改（调整免费楼层/增删档位/改加价）→ 二次确认 → 保存 → 新订单按新规则计算
  3. 用户端确认订单页按所选地址楼层 + 规则展示运费/免配送费（R-MON-02）
- 状态与标签：免费楼层及以下免运费；楼层为空（平房/无楼层信息）免运费；自提免运费；未配置回显默认并提示
- 关键数据字段：免费楼层、分档（起始楼层/结束楼层/加价金额分）、审计记录
- 页面文案：「运费金额无效」「档位区间重叠」「确定保存新的配送费规则吗？修改将影响新订单，已生成订单不受影响」「免配送费」
- 设计要点/禁忌：分档须按楼层升序、区间不重叠、各档加价 0-999 元 ≤2 位小数；保存二次确认须说明对已生成订单无影响；由单档改分档（解决 7 楼与 27 楼同价）
- 备注：已实现；缺口 G62；规则口径由订单域 R-MON-02 定义，本域仅提供配置能力；距离计费为开放问题
