# 11 系统设置域 页面规格

> 来源：`PRD/11-system-settings.md`（F-SYS-001~006），仅管理后台端，入口「系统设置」菜单**仅超级管理员可见**。
> 权限码：`SYSTEM_CONFIG_READ/WRITE`（仅超级管理员；管理员菜单不可见、接口返回 FORBIDDEN — R-SYS-03）；方法级 `@PreAuthorize` 强制（R-AUTH-04，G49 已解决 2026-09）。
> 规则：R-SYS-01（参数生效与审计：键+值+类型+分组，变更按声明即时生效或重启生效，热生效优先，全程审计，不追溯已生成业务数据）；R-SYS-02（敏感配置保护：密钥类不进入在线修改通道，仅配置文件/环境变量注入，前端展示掩码）；R-SYS-03（配置访问权限）。
> 金额类参数以分存储（R-MON-01）；配置变更**不追溯**已生成业务数据（订单成交价/运费/时段按下单时快照）。
> 与运营配置域（12-operations-config.md）区分：本域为平台级基础参数与安全策略（仅超管）；运营配置为管理员可维护的日常运营内容。
> 通用状态：无 `SYSTEM_CONFIG_WRITE` 权限时页面只读；保存失败 toast。

## 页面 1：管理后台 · 系统参数管理（建议文件名 system-parameters.html）
- 功能编号：F-SYS-001 [规划中]（正文现状：2026-08 `system_settings` 表/实体/仓库 + 配置服务/GraphQL 接口/后台页面已落地，本页按状态列标**目标形态**）
- 所属端：管理后台
- 页面入口与跳转：系统设置 → 系统参数；路由 `system-config/parameters`；仅超级管理员可见
- 布局结构（从上到下）：
  1. 参数分组导航（Tabs）：安全 / 通知 / 数据维护（订单与履约、库存两组在独立页面配置，见 F-SYS-002 / F-SYS-003，本页不重复展示）
  2. 参数列表（Table）
  3. 编辑弹窗（Modal）
  4. 「修改记录」页签：审计日志列表
- 组件清单（目标形态）：Tabs、Table、Form、Input、InputNumber、Switch、Select、Modal、Popconfirm、Tag
- 关键交互：
  1. 进入页面 → 按组加载参数列表；
  2. 编辑 → 按声明类型校验 → 保存 → 按声明热生效；
  3. 恢复默认 → 二次确认 → 回默认值；
  4. 「修改记录」页签可查审计日志。
- 状态与标签：
  - 空态：组内无参数空态
  - 加载态：列表/保存 loading
  - 错误态：保存失败 toast
  - 禁用态：无 `SYSTEM_CONFIG_WRITE` 权限时只读（仅超管可写）
  - 类型 Tag：数值 / 布尔 / 文本 / 枚举
- 配置项字段清单（通用「键 + 值 + 类型 + 分组」模型）：
  | 字段名 | 控件类型 | 默认值/取值范围 | 分组 |
  | --- | --- | --- | --- |
  | 参数名 | 文本展示 | — | 安全 / 通知 / 数据维护 |
  | 参数键（setting_key） | 文本展示（唯一，字母数字下划线） | 唯一 | 同上 |
  | 类型 | Tag 展示 | 数值 / 布尔 / 文本 / 枚举 | 同上 |
  | 当前值 | 按类型渲染控件（数值 InputNumber、布尔 Switch、文本 Input、枚举 Select） | 按声明 | 同上 |
  | 说明 | 文本展示 | — | 同上 |
  | 修改人 / 修改时间 | 文本展示 | — | 同上 |
  | 修改记录：时间 / 操作人 / 旧值 / 新值 | 表格（「修改记录」页签） | — | — |
- 图表规格：本页无图表。导出按钮：无（参数导入导出为**目标形态**）。
- 页面文案：
  - Tabs：「安全」「通知」「数据维护」「修改记录」
  - 表头：「参数名」「键」「类型」「当前值」「说明」「修改人」「修改时间」；操作「编辑」「恢复默认」
  - 校验：「参数值格式不正确」「参数值超出范围」；恢复默认确认「确定恢复默认值吗?」
- 设计要点/禁忌：
  - 值与控件须按声明类型渲染（数值 / 开关 / 文本 / 枚举），不得一律用文本框。
  - 值按声明类型校验（数值区间 / 布尔 / 枚举 / 长度）；整数型限区间。
  - 密钥类参数（微信/支付/DB 口令等）**不得出现在本页**（R-SYS-02），后端不回显明文、前端展示掩码。
  - 恢复默认必须二次确认；所有修改留审计（操作人/时间/旧值/新值）。
  - 订单与履约、库存两组**不在本页**展示，避免两处编辑口径不一。
- 备注：目标形态——参数中心 + 业务消费 + 审计闭环、批量修改、参数导入导出。缺口 G64；孤儿种子键 `bucket_deposit_amount` 清理（G06）。开放问题：参数分组与业务消费方映射。

## 页面 2：管理后台 · 订单与履约参数配置（建议文件名 order-fulfillment-params.html）
- 功能编号：F-SYS-002 [部分实现]
- 所属端：管理后台
- 页面入口与跳转：系统设置 → 订单与履约参数；路由 `system-config/order`；仅超级管理员可见
  - 下游消费：用户端确认订单页经 client `deliverySlots` 查询按配置渲染时段选项（已实现 2026-09）；订单详情时段文案按配置渲染（失败回退兜底文案）
- 布局结构（从上到下）：
  1. 支付参数分组
  2. 配送时段分组（立即配送 + 上午 / 下午 / 晚上）
  3. 派单与确认分组
  4. 保存按钮（二次确认）+ 修改记录
- 组件清单（目标形态）：Form、InputNumber、TimePicker（时间范围）、Switch、Button、Modal.confirm
- 关键交互：
  1. 进入页面 → 回显当前参数；
  2. 修改 → 确认保存 → 按声明热生效；
  3. 用户端确认订单页配送时段选项按新配置渲染（F-ORD-001）；
  4. 支付超时任务按新参数执行（R-ORD-04 接通后）。
- 状态与标签：
  - 空态：未配置时按默认值展示
  - 加载态：回显/保存 loading
  - 错误态：保存失败 toast
  - 禁用态：无权限只读
  - 时段启停：Switch 开/关
- 配置项字段清单（分组 + 字段名 + 控件 + 默认值/范围）：
  | 分组 | 字段名 | 控件类型 | 默认值 / 取值范围 |
  | --- | --- | --- | --- |
  | 支付参数 | 支付超时 | InputNumber（分钟） | 默认 30；>0；超时自动取消并恢复库存（R-ORD-04，消费链路规划中） |
  | 配送时段 · 立即配送 | 立即配送时限 | InputNumber（分钟） | 默认 30；>0；**恒启用（不可停用）** |
  | 配送时段 · 上午 | 上午时段 | TimePicker 时间范围 | 默认 09:00-12:00；开始 < 结束 |
  | 配送时段 · 上午 | 启用开关 | Switch | 默认启用；可启停 |
  | 配送时段 · 下午 | 下午时段 | TimePicker 时间范围 | 默认 14:00-18:00；开始 < 结束 |
  | 配送时段 · 下午 | 启用开关 | Switch | 默认启用；可启停 |
  | 配送时段 · 晚上 | 晚上时段 | TimePicker 时间范围 | 默认 18:00-21:00；开始 < 结束 |
  | 配送时段 · 晚上 | 启用开关 | Switch | 默认启用；可启停 |
  | 派单与确认 | 派单超时提醒 | InputNumber（分钟） | >0 |
  | 派单与确认 | ~~自动确认收货~~ | — | **已废弃（2026-10）**：随「送达即完成」（R-ORD-11）取消「待确认收货」态与参数 `auto_confirm_receipt_days`（原默认 7），不再消费、不再展示 |
- 配送时段精细说明（种子默认值）：`30分钟 / 09:00-12:00 / 14:00-18:00 / 18:00-21:00`（GROUP = ORDER_AND_FULFILLMENT）。
  - **立即配送恒启用**：立即配送选项不可停用（无 Switch 或 Switch 置灰锁定），仅可调「立即配送时限」分钟数。
  - 上午 / 下午 / 晚上三类时段各自独立：时间段（TimePicker）+ 启用开关（Switch）；停用后用户端该时段不再可选。
  - 时段字段统一校验：时间窗合法（开始 < 结束），否则提示「时间窗不合法」。
- 图表规格：本页无图表。导出按钮：无。
- 页面文案：
  - 分组标题：「支付参数」「配送时段」「派单与确认」
  - 字段文案：「支付超时（分钟）」「立即配送时限（分钟）」「上午」「下午」「晚上」「派单超时提醒（分钟）」
  - 校验：「参数无效」「时间窗不合法」；超时/时限 > 0
  - 保存确认：「确定保存吗?将影响新订单的履约流程，已生成订单不受影响」
- 设计要点/禁忌：
  - 立即配送**恒启用**，不可停用；上午/下午/晚上可各自启停。
  - 时段修改只影响新订单，已生成订单按下单时快照，不追溯；保存确认文案须明示。
  - 时间窗开始必须早于结束；超时/时限必须 > 0。
  - 「自动确认收货」参数已废弃，不得再出现在表单中。
- 备注：目标形态——其余履约参数后台可配、前端与服务端统一消费（支付超时自动取消消费链路未接通）。开放问题：时段是否区分工作日/周末、每时段是否限量派单。缺口 G64（配送时段用户端消费缺口已关闭）。

- 状态与标签：
  - 空态：未配置时按默认阈值展示
  - 加载态：回显/保存 loading
  - 错误态：保存失败 toast

  | --- | --- | --- | --- |
  | 低库存阈值 | 低库存阈值 | InputNumber（件） | 默认 10；0-99999 整数；库存 ≤ 该值进入预警 |
  | 预警色阶档位 | 红色档位下限（低，<X 红） | InputNumber | 默认 <10 红 |
  | 预警色阶档位 | 橙色档位下限（中，<Y 橙） | InputNumber | 默认 <50 橙；档位值须递增 |
  | 预警色阶档位 | 绿色档位（其余，≥Y 绿） | 文本展示（派生） | 默认 ≥50 绿 |
- 图表规格：本页无图表。导出按钮：无。
- 页面文案：
  - 字段文案：「低库存阈值」「预警色阶档位（低 <X 红 / 中 <Y 橙 / 其余绿）」

  - 阈值为 0-99999 整数；色阶档位必须递增（红 < 橙 < 绿）。

  - 预警仅作用于在售/库存维度，不影响下架商品。
  - 阈值配置后即时生效（热生效）。
- 备注：目标形态——阈值后台可配，商品域/统计域消费。现状阈值与色阶硬编码于后台商品列表展示逻辑（无后台入口）。开放问题：色阶是否允许自定义；预警是否联动通知配置（F-SYS-005）。缺口 G64；G39（阈值配置入口缺失）。

  - 错误态：保存失败 toast
  - 禁用态：无权限只读
  - 重启生效提示：Token 有效期字段旁提示「重启生效」
- 配置项字段清单（分组 + 字段名 + 控件 + 默认值/范围）：
  | 分组 | 字段名 | 控件类型 | 默认值 / 取值范围 |

  | 密码策略 | 是否要求字母数字混合 | Switch | 默认（按需）；开/关 |
  | 登录安全 | 登录失败锁定次数 | InputNumber（次） | 默认 5；1-99 |
  | 登录安全 | 锁定时长 | InputNumber（分钟） | >0 |
  | Token | Token 有效期 | InputNumber（小时） | 重启生效提示 |
- 图表规格：本页无图表。导出按钮：无。
- 页面文案：
  - 分组标题：「密码策略」「登录安全」「Token 有效期」
  - 字段文案：「密码最小长度」「是否要求字母数字混合」「登录失败锁定次数」「锁定时长（分钟）」「Token 有效期（小时）」
  - 校验：「参数无效」（最小长度 6-32、锁定次数 1-99、锁定时长 > 0）
  - 生效提示：「登录校验即时生效」「Token 有效期重启生效」
- 设计要点/禁忌：
  - 最小长度限 6-32，锁定次数限 1-99，锁定时长 > 0。
  - 区分即时生效（登录校验类）与重启生效（Token 类），字段旁须明示生效时机。
  - 密钥/证书类不在此页在线修改（R-SYS-02）。
- 备注：目标形态——超级管理员在线可配。现状登录校验简化（无强度/锁定策略），Token 有效期配置于 application.yml。开放问题：是否引入双因子/验证码登录（现状按不引入设计）。缺口 G64；G49（权限强制配套）。
