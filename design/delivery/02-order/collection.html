页面说明

所属端：送水工端 App（Expo React Native，暗色）

入口：订单详情「收款方式」区 / 完成配送前置步骤。

跳转：收款成功后返回订单详情继续「完成配送」；收款额计入每日收款日报。

来源说明：PRD 未给本页独立规格，页面结构与文案按「订单收款方式」与「每日收款」相关条目按语境拟定（标注于 chips：PRD 未给 · 按语境拟定）。

布局结构

  1. 导航栏：返回 + 标题「收款」+ 消息入口（未读红点）
  2. 订单信息卡：订单号 + 状态 + 收货地址 + 应收金额
  3. 收款方式（现金 / 水票 / 扫码，三选一互斥）
  4. 现金收款：实收金额输入 + 快捷面额 + 应找零提示
  5. 水票核销：扫码核销框；扫码收款：展示商户收款码
  6. 底部操作栏：实收 / 应找零信息 +「确认收款」
  7. 收款成功态：成功提示 + 收款明细 +「完成配送」

关键交互

  1. 选择收款方式 → 进入对应录入：现金填实收并实时算找零；水票调起扫码核销；扫码展示收款码。
  2. 点「确认收款」→ 记录收款方式与金额 → 回写订单完成配送的收款字段。
  3. 收款成功 → 展示明细，返回订单详情可继续「完成配送」（送达即完成，R-ORD-11）。

状态与规则

必选：非自提且无水票核销时收款方式必选，否则拦截完成配送；自提订单默认已收款豁免。

电子票核销：电子票核销订单未选收款方式自动记「水票」；找零：实收 < 应收时不渲染找零并提示补足。

口径：现金 / 扫码收款计入当日收款汇总，与「今日订单情况」系统预计算自动比对（容差 ±1 元，水票按张数精确比对）；两者与对账三者口径一致（R-ORD-11）。

设计要点 / 禁忌

送水工端完全不出现强调橙：主操作「确认收款 / 完成配送」走品牌蓝（--d-primary），找零提示用品牌蓝高亮，异常用 error 色。

金额统一「¥xx.xx」两位小数（分转元）；收款码 / 核销码为占位块，标注「收款码展示」。

本页细节 PRD 未明确，均按语境拟定；正式实现以统一取价 / 收款口径为准，禁止与日报金额手拼不一致。
