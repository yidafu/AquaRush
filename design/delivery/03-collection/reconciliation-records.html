页面说明

所属端：送水工端 App（Expo React Native，亮色）

入口：「我的」页「对账记录」→ reconciliation-records。

跳转：点击卡片 → 对账详情下钻（当日已送达订单流水，逐单差异明细）。

布局结构

  1. 导航栏：返回 + 标题「对账记录」+ 消息入口（未读红点）
  2. 状态筛选（分段控件：全部 / 待确认 / 有差异）
  3. 对账记录卡片列表（按日期倒序）：日期 + 状态标签；系统预计算 / 实际填报 / 差异；差异申诉入口 + 详情下钻
  4. 加载更多区：「没有更多了」
  5. 差异申诉弹层：对账日期 + 差异金额 + 申诉说明（必填）+ 取消 / 提交申诉

关键交互

  1. 加载对账记录，按日期倒序，初始展示第一页；上拉加载下一页，下拉刷新重置。
  2. 点击卡片 → 下钻查看当日已送达订单流水（逐单差异明细）。
  3. 点「差异申诉」→ 打开申诉弹层 → 填写说明提交 → 状态置「差异申诉中」。
  4. 后台复核后此处状态同步更新。

状态与规则

状态标签：待确认（warning）/ 已确认（success）/ 差异申诉中（error）/ 已审核（brand）—— 与后台一致并一目了然。

差异金额色：|差异| ≤ 1 元绿色、> 1 元红色（±100 分容差）；水票按张数精确比对。

空态：「暂无对账记录」；加载态：「加载中...」；错误态：「加载失败」；禁用态：无更多数据「没有更多了」。

复核信息（时间 / 备注）仅在已确认 / 已审核记录展示；列表倒序不可打乱。

设计要点 / 禁忌

差异金额正负与超容差需红色强调，容差内用绿色；系统预计算与填报值须显式并列。

送水工端完全不出现强调橙：提交按钮走品牌蓝（--brand），申诉用 error 色。

仅本人可见（R-AUTH-02）；申诉说明为必填追溯依据，提交防重复点击。
