页面说明

所属端：管理后台（React + Ant Design 5）

入口：左侧菜单「用户管理 → 用户」

跳转：操作列「详情」→ /users/:id；「编辑」→ UserForm 弹窗；「删除」→ Modal.confirm

权限：用户读写权限（用户管理 菜单）

布局结构

  1. 页头：标题「用户列表」+「新增用户」按钮
  2. 筛选卡：关键词（昵称 / 手机号 / 用户ID）·「用户类型」下拉 · 注册时间 · 客户分组 · 是否有订单
  3. UserTable：用户（头像+昵称）/ 手机号（脱敏）/ 用户类型 / 客户分组 / 订单数 / 总消费 / 注册时间 / 操作
  4. 操作列：详情 · 编辑 · 删除（不含「重置密码」——微信登录用户无账号密码，见 07-user.md §3.3）
  5. 分页：共 N 条 · 页码 · 每页条数

关键交互

  1. 筛选变更（关键词防抖）→ 组合条件重新查询（分页重置到第 1 页）
  2. 「新增用户」→ UserForm 弹窗（昵称 / 手机号 / 用户类型 / 客户分组 / 状态）→ message「用户创建成功」
  3. 「编辑」→ UserForm 回填 → 「用户更新成功」
  4. 「删除」→ 二次确认「确定要删除用户 X 吗？此操作不可恢复。」→ 软删除
  5. 「详情」→ 用户详情页（Tab 布局，默认「收货地址」）

状态与规则

空态：表格空（无用户数据）；加载态：Table loading；错误态：操作失败 message；禁用态：提交 loading 期间禁用。

用户类型下拉：全部 / 普通用户 / 企业客户（PRD 明确要求，作为筛选参数）。

展示规则：手机号脱敏；微信OpenID 截断；新建用户 OpenID 由后端自动生成（manual_ 占位）；客户分组为空显示「未分组」。

设计要点 / 禁忌

列表不使用 Tab：用户为单类型身份（PRD §3.3 结论），角色不通过 Tab 切换，统一用「用户类型」下拉筛选。

管理端不出现强调橙；金额分转元（¥0.00 口径）；删除用语义 error 色 + 二次确认。

客户分组归属「营销管理 §F-MKT-001」，本页仅提供筛选与「设置分组」入口。

操作列口径：按 07-user.md §3.3，用户列表不提供「重置密码」（微信登录用户无账号密码，登录态由微信授权维护）。若后续需要封禁/解封能力，应走「状态」字段而非密码类操作。
